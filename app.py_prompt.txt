아래 요구사항에 맞는 Streamlit(파이썬) 언어 학습(단어 암기) 웹앱을 처음부터 작성해줘.
파일은 app.py 하나로 작성하고, 바로 복사해서 실행할 수 있는 완성된 코드로 줘.

# 1. 기본 환경
- 프레임워크: Streamlit (streamlit.components.v1 포함)
- 언어: Python
- 화면 레이아웃: layout="centered", 모바일 화면에서도 잘 보이도록 반응형 CSS 적용
- 폰트: Pretendard 웹폰트 CDN 적용, 다크 모드/기본 모드 두 가지 테마 지원, 글자 크기 조절(크게/작게/초기화) 기능
- 단어장 원본 데이터는 GitHub 저장소(.txt 파일)에 저장되어 있고, 앱이 GitHub API로 그 파일들을 읽어온다.
  - GitHub 저장소 구조: word_list/대분류폴더/세부폴더(선택적)/단어파일.txt
  - 인증 정보는 st.secrets에 다음 키로 저장되어 있다고 가정: github_token, github_owner, github_repo, github_branch, upload_password, gemini_api_key
  - GitHub API 호출 결과는 @st.cache_data로 캐싱(ttl=1800초=30분)해서 API 요청 횟수를 아낀다.

# 2. 단어 파일 형식과 파싱 규칙
- 한 단어 블록은 "단어 : 뜻" 한 줄 + 그 아래 여러 줄의 힌트(설명)로 구성되거나,
  콜론이 없으면 1번째 줄=단어, 2번째 줄=뜻, 3번째 줄부터=힌트로 처리한다.
- 블록 사이는 빈 줄로 구분한다.
- 파싱 함수는 (단어 리스트, 오류 메시지 리스트)를 함께 반환하는 검증용 버전과, 오류 없이 조용히 파싱만 하는 버전 두 가지가 필요하다.
- 대화문/지문 파일은 한 줄에 문장 하나씩, 빈 줄은 무시하고 그대로 리스트로 파싱한다.

# 3. 사이드바 - 학습 자료 선택
- 대분류(폴더) 선택 → 세부 카테고리(하위 폴더, 예: N2/N3) 다중 선택 → 그 안의 txt 파일들을 체크박스로 다중 선택하는 3단계 구조.
- 파일이 많을 때를 위한 "파일 검색창"(입력한 텍스트로 파일명 실시간 필터링)을 제공한다.
- 전체 선택/전체 해제 버튼, 그룹(세부 카테고리)별 선택/해제 버튼을 각각 제공한다.
- 즐겨찾기 단어가 1개 이상 있으면 사이드바에 "즐겨찾기만 사용" 체크박스를 보여주고, 체크하면 파일 선택 UI 대신 즐겨찾기 단어만 학습 대상으로 사용한다.
- 화면 설정(테마, 글자 크기)도 사이드바 상단에 접이식(expander)으로 넣는다.

# 4. 학습 파트
- 선택한 파일들의 단어를 무작위 순서로 섞어서 하나씩 카드 형태로 보여준다(단어/뜻 동시 표시).
- 힌트 보기 버튼(있는 단어만 활성화), 다음 단어 버튼, 즐겨찾기(⭐) 토글 버튼을 화면 상단에 고정(sticky)해서 스크롤해도 항상 보이게 한다.
- 진행률 바와 "현재 인덱스 / 전체 개수" 표시.
- 단축키: 스페이스바=다음 단어, H=힌트 보기, F=즐겨찾기 토글.

# 5. 연습 파트 (망각 곡선 방식)
- "이름만 연습(단어를 보고 뜻 맞히기) / 뜻만 연습(뜻을 보고 단어 맞히기) / 랜덤 연습" 3가지 모드 버튼 제공.
- 큐(대기열) 방식으로 동작: 정답 확인 후 4단계 자기평가(완벽함100/조금앎60/헷갈림40/모름0)를 누르면,
  100점은 큐에서 제거하고, 60/40/0점은 점수가 낮을수록 큐의 더 앞쪽(가까운 위치)으로 다시 삽입해서 더 자주 반복되게 한다.
- 40점, 0점을 받은 단어는 "오답 단어" 목록에 자동으로 누적 저장한다.
- 모든 큐를 다 마치면 완료 화면에서 오답 단어들을 표(단어/뜻)로 보여주고, "오답만 다시 연습하기" 버튼으로 그 단어들만 다시 큐에 넣어 재도전할 수 있게 한다.
- 진행률 바, 완료 개수/남은 개수 표시. 단축키: 스페이스바=정답 확인, H=힌트, Z/X/C/V=4단계 점수, F=즐겨찾기.

# 6. 시험 파트
- 출제 개수를 숫자 입력(+5/-5/최대 버튼 포함)으로 정한 뒤, "이름만 시험/뜻만 시험/랜덤 시험" 중 선택해서 시작.
- 문제를 하나씩 보여주고 정답 확인 → 맞음/틀림 버튼으로 채점. 틀린 단어는 오답 목록에 누적.
- 진행 상황(현재 번호/총 개수, 맞음/틀림 개수)을 상단에 표시.
- 시험이 끝나면: 정답률(%) 계산, 정답률 구간별로 다른 이모지+격려 문구(등급 피드백)를 보여주고,
  오답 목록을 표로 보여주며 "오답만 다시 시험보기" 버튼을 제공한다.
- 단축키: 스페이스바=정답 확인, Z=맞음, X=틀림, F=즐겨찾기.

# 7. 지문(대본) 외우기 파트
- 대화문/지문을 순서대로 한 줄씩 보여주며 이전/다음 버튼으로 이동.
- 진행률 바 표시. 단축키: 스페이스바=다음 문장.

# 8. 단어장 추가(업로드) 파트 - GitHub 연동
- 대분류/세부 폴더를 선택해서 업로드 대상 폴더를 지정하고, 그 폴더에 이미 있는 파일 목록을 미리 볼 수 있다.
- 탭 1 "직접 입력해서 저장": 제목, 단어 목록(직접 타이핑), 업로드 비밀번호를 입력하고 저장 버튼을 누르면
  형식 검증(파싱 오류 있으면 저장 안 하고 오류 목록 표시) 후 GitHub에 새 txt 파일로 업로드(base64 인코딩, PUT API 사용).
  비밀번호는 st.secrets의 upload_password와 hmac.compare_digest로 안전하게 비교한다.
- 탭 2 "txt 파일 업로드": 로컬 txt 파일을 업로드해서 같은 방식으로 검증 후 GitHub에 저장.
- 저장 성공/실패 시 화면 모서리에 뜨는 토스트 알림(st.toast)과 기존 성공/에러 메시지(st.success/st.error)를 함께 보여준다.
- "새로고침" 버튼으로 GitHub 캐시를 수동으로 지울 수 있게 한다.

# 9. Gemini API를 활용한 단어 변환 기능 (단어장 추가 탭 1 안에 위치)
- st.secrets["gemini_api_key"]를 사용해서 Google Generative AI(google-generativeai 패키지)를 호출한다.
- 사용자가 한자/한국어/히라가나/카타카나 단어를 한 줄에 하나씩 입력하는 텍스트 영역과 "Gemini로 변환하기" 버튼을 제공한다.
- 아래 형식의 프롬프트(일본어 전문 사전학자 역할, 단어별로 [단어]/[한국어 뜻(요미가나)]/[한자별 훈음+파자+어원 설명]/[종합 설명] 순서로 출력, 가타카나/외래어는 한자 대신 영어 어원 설명, 출력이 길어서 중간에 끊기면 "완료율: n/전체 (x%) 완료되었습니다" 문구를 맨 끝에 붙이도록 지시)을 이용해 Gemini를 호출한다.
- Gemini 응답을 파싱해서 "단어 : 뜻(요미가나)" + 한자풀이/종합설명을 힌트로 붙인, 기존 파싱 형식과 동일한 텍스트로 자동 변환하는 함수를 만든다("완료율" 문구는 자동으로 제거).
- "이 결과를 아래 입력칸에 채우기" 버튼을 누르면, 변환된 텍스트가 탭1의 단어 저장용 텍스트 영역에 자동으로 채워진다(기존 내용이 있으면 뒤에 이어붙임).
- Gemini 호출은 429(할당량 초과, ResourceExhausted) 에러가 나면 짧게 대기 후 최대 2회 재시도하고, 계속 실패하면 사용자에게 친절한 한국어 에러 메시지를 보여준다. 모델명은 변수로 분리해서 나중에 쉽게 바꿀 수 있게 한다(예: gemini-2.5-flash-lite처럼 무료 할당량이 남아있는 모델을 기본값으로 사용).

# 10. 오늘의 학습 요약, 즐겨찾기 관련 규칙
- 즐겨찾기는 (단어, 뜻) 조합을 키로 하는 딕셔너리로 session_state에 저장하고, 학습/연습/시험 화면 어디서든 별표 버튼으로 추가/제거할 수 있다.
- "오늘 학습한 단어 수/연습 정답률/시험 최고 정답률"처럼 세션 통계를 요약해서 보여주는 기능은 넣지 않는다(사용자가 명시적으로 제거를 요청했으므로 만들지 말 것).

# 11. 여러 사용자 동시 접속 및 세션 안정성
- 20명 정도가 동시에 접속해도, 한 사용자가 학습을 진행 중이면 최소 30분 이상 세션(session_state)이 끊기지 않아야 한다.
- st.session_state(개인별 학습 진행 상태)와 st.cache_data(GitHub API 응답 공용 캐시)를 명확히 분리해서 설계하고, 캐시가 지워져도 사용자 진행 상태에는 영향이 없는 구조로 만든다.
- 브라우저가 주기적으로(90초 간격) 서버에 가벼운 핑(fetch) 요청을 보내 세션이 살아있음을 알리는 JS 스니펫을 components.html로 삽입한다. 사용자가 다른 탭을 보다가 돌아왔을 때도 즉시 한 번 더 핑을 보내도록 visibilitychange 이벤트도 처리한다.
- 화면 우측 상단의 개발자용 메뉴(⋮, "Clear cache" 등)가 일반 사용자에게 보이지 않도록 .streamlit/config.toml에서 client.toolbarMode = "minimal"로 설정한다. showErrorDetails = false, server.fileWatcherType = "none", browser.gatherUsageStats = false도 함께 설정한다.

# 12. 코드 스타일 요구사항
- 모든 함수와 변수명은 이해하기 쉬운 스네이크 케이스로 작성한다.
- 학습/연습/시험/지문 중 하나라도 진행 중이면 "포커스 모드"로 간주해서 상단 헤더/툴바를 숨기고 해당 파트 화면만 크게 보여주며, 화면 하단에 작은 "종료하기" 버튼으로 전체 화면(파트 선택 화면)으로 돌아갈 수 있게 한다.
- 키보드 단축키는 입력창(텍스트박스 등)에 포커스가 있을 때는 동작하지 않도록 예외 처리한다.
- app.py 하나로 실행 가능해야 하며, 실행에 필요한 추가 패키지(streamlit, requests, google-generativeai 등)도 목록으로 알려줘.

위 요구사항을 모두 반영한 완성된 app.py 전체 코드와, 함께 필요한 .streamlit/config.toml 파일, requirements.txt 내용을 각각 복사하기 쉬운 코드 블록으로 나눠서 출력해줘.
