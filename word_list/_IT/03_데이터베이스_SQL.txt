ACID
Atomicity, Consistency, Isolation, Durability / 트랜잭션이 안전하게 수행되기 위해 보장해야 하는 4가지 특성 (암기: 원일격영)
[구성] A=Atomicity(원자성) + C=Consistency(일관성) + I=Isolation(격리성) + D=Durability(영속성·지속성)
[의미] 하나의 논리적 기능을 수행하는 작업 단위인 트랜잭션이 정상적으로 수행되기 위해 반드시 유지해야 하는 특성
[구분] 특성별 의미
· 원자성: 연산이 모두 수행되거나 모두 수행되지 않아야 함 (COMMIT, ROLLBACK)
· 일관성: 트랜잭션 수행 전과 완료 후의 상태가 일관되게 유지
· 격리성: 수행 중인 트랜잭션에 다른 트랜잭션이 접근할 수 없고 각각 독립적이어야 함
· 지속성: 성공적으로 완료된 트랜잭션의 결과는 영구히 보존 (영속성이라고도 함)
[치트키] "원자가 일찍 격리되어 영면했다 = 원일격영"
[예문] 트랜잭션의 ACID 특성 중 원자성은 모두 반영되거나 전혀 반영되지 않아야 함을 의미한다
[헷갈리는 단어] 격리성 - 격리성은 동시 실행 간섭 방지, 일관성은 수행 전후 상태 유지

정규화 과정
이상 현상과 함수 종속으로 인한 문제를 해결하기 위해 릴레이션을 단계적으로 분해하는 과정 (암기: 도부이결다조)
[구성] 1NF → 2NF → 3NF → BCNF → 4NF → 5NF
[의미] 논리적 설계 단계에서 데이터 중복과 이상 현상을 제거하여 구조를 안정화
[구분] 단계별 제거 대상
· 1NF: 모든 도메인이 원자값으로만 구성, 반복 그룹 제거
· 2NF: 부분 함수 종속 제거 (모든 속성이 기본키에 완전 함수 종속)
· 3NF: 이행적 함수 종속 제거
· BCNF: 결정자가 후보키가 아닌 함수 종속 제거 (모든 결정자가 후보키)
· 4NF: 다치 종속 제거
· 5NF: 조인 종속이 후보키를 통해서만 성립되도록 제거
[치트키] "도(도메인 원자값) 부(부분) 이(이행) 결(결정자) 다(다치) 조(조인) = 두부 이걸 다 줘?"
[예문] 정규화에서 이행적 함수 종속을 제거하는 단계는 제3정규형이다
[헷갈리는 단어] 반정규화 - 정규화는 중복 제거, 반정규화는 성능을 위해 중복을 허용

스키마 3계층
데이터베이스를 사용자 관점부터 물리적 저장 관점까지 세 단계로 나누어 정의한 구조 (암기: 외개내)
[구성] 외부 스키마 → 개념 스키마 → 내부 스키마
[의미] 사용자와 물리 저장 구조를 분리해 데이터 독립성을 확보하기 위한 구조
[구분] 계층별 의미
· 외부 스키마: 사용자나 응용 프로그램이 보는 논리적 구조 (서브 스키마라고도 함)
· 개념 스키마: 전체적인 논리적 구조로, 개체 간 관계·제약 조건·접근 권한·보안·무결성 규정을 정의
· 내부 스키마: 데이터베이스의 물리적 구조를 정의하며 전체 데이터베이스에 하나만 존재
[치트키] "외(외부) 개(개념) 내(내부) = 외개내, 바깥에서 안쪽으로"
[예문] 데이터베이스의 물리적 저장 구조를 정의하며 하나만 존재하는 스키마는 내부 스키마이다

키(Key)의 종류
릴레이션에서 튜플을 식별하거나 관계를 맺기 위해 사용하는 속성 집합
[구성] 슈퍼키 ⊃ 후보키 ⊃ 기본키 / 대체키 / 외래키
[의미] 유일성과 최소성을 기준으로 튜플을 식별하고, 릴레이션 간 관계를 표현
[구분] 키별 의미
· 기본키(Primary Key): 각 튜플을 고유하게 식별하는 컬럼
· 대체키: 후보키 중 기본키로 선택되지 않은 키
· 후보키: 기본키와 대체키를 합친 키로 튜플을 구별하는 기준
· 슈퍼키: 유일성은 만족하지만 최소성은 만족하지 못하는 키
· 외래키(Foreign Key): 다른 릴레이션을 참조하는 속성
[치트키] "슈퍼키는 유일성만, 후보키는 유일성 + 최소성, 기본키는 후보키 중 대표, 나머지는 대체키"
[예문] 후보키 중 기본키로 선택되지 않은 키를 대체키라 한다
[헷갈리는 단어] 슈퍼키와 후보키 - 슈퍼키는 최소성 불만족, 후보키는 유일성과 최소성 모두 만족

이상현상(Anomaly)
릴레이션 조작 시 데이터가 불필요하게 중복되어 예기치 않게 발생하는 곤란한 현상 (암기: 삽삭갱)
[구성] 삽입 이상 + 삭제 이상 + 갱신 이상
[의미] 설계가 잘못된 릴레이션에서 데이터 조작 시 발생하는 문제로 정규화로 해결
[구분] 종류별 의미
· 삽입 이상: 원하는 값만 삽입하고 싶은데 필요 없는 필드의 값도 함께 삽입해야 하는 경우
· 삭제 이상: 하나의 튜플 삭제 시 삭제를 원하지 않는 속성값도 같이 지워지는 문제
· 갱신 이상: 중복된 값 중 일부만 업데이트되어 속성값 간 불일치가 발생하는 현상
[치트키] "삽(삽입) 삭(삭제) 갱(갱신) = 삽삭갱, 삽살개가 짖는다"
[예문] 중복된 데이터 중 일부만 수정되어 값이 서로 달라지는 현상은 갱신 이상이다

카디날리티(Cardinality)
릴레이션(표) 내 튜플(행)의 개수
[구성] 카디날리티 = 튜플(행)의 수
[의미] 릴레이션의 세로 길이를 나타내는 값으로, 차수와 함께 릴레이션의 크기를 설명하는 지표
[치트키] "카디날리티의 카 = 행의 수를 카운트, 차수는 열의 수"
[예문] 행이 3개인 릴레이션의 카디날리티는 3이다
[헷갈리는 단어] 차수 - 카디날리티는 튜플(행)의 수, 차수는 속성(열)의 수

차수(Degree)
릴레이션 내 속성(애트리뷰트)의 개수
[구성] 차수 = 속성(열)의 수
[의미] 릴레이션의 가로 길이를 나타내는 값
[치트키] "디그리(차수)는 열(기둥)의 개수, 카디날리티는 행의 개수"
[예문] 속성이 4개인 릴레이션의 차수는 4이다
[헷갈리는 단어] 카디날리티 - 차수는 속성의 수, 카디날리티는 튜플의 수

도메인(Domain)
하나의 속성이 취할 수 있는 같은 타입의 원자값들의 집합
[구성] 속성 + 허용되는 값의 범위
[의미] 속성에 들어갈 수 있는 값의 범위를 정의하여 데이터의 유효성을 보장
[구분] 관련 용어
· 튜플: 관계 데이터 모델에서 한 행을 구성하는 속성들의 집합
· 속성(애트리뷰트): 관계형 데이터베이스에서 사용되는 데이터의 가장 작은 논리적 단위
[치트키] "도메인 = 속성이 가질 수 있는 값의 동네(범위)"
[예문] 성별 속성이 남 또는 여만 가질 수 있도록 정한 값의 집합이 도메인이다

관계 대수(Relational Algebra)
원하는 정보와 그 정보를 유도하기 위한 과정을 함께 기술하는 절차적 언어 (암기: 대절해비)
[구성] 순수 관계 연산자 + 일반 집합 연산자
[의미] 릴레이션에서 결과를 얻기 위한 절차를 연산자로 표현하는 방식
[구분] 연산자 구분
· 순수 관계 연산자: SELECT, PROJECT, JOIN, DIVISION
· 일반 집합 연산자: 합집합, 교집합, 차집합, 카티션 프로덕트
[치트키] "대수는 절차적, 해석은 비절차적 = 대절해비"
[예문] 결과를 얻기 위한 처리 절차까지 기술하는 데이터 언어는 관계 대수이다
[헷갈리는 단어] 관계 해석 - 관계 대수는 어떻게(절차적), 관계 해석은 무엇을(비절차적)

관계 해석(Relational Calculus)
원하는 정보가 무엇인지만 정의하는 비절차적 언어 (암기: 대절해비)
[구성] 술어 논리 기반 + 튜플 해석 / 도메인 해석
[의미] 결과를 얻는 과정은 기술하지 않고 원하는 결과만 선언하는 방식
[치트키] "해석은 해석만 한다 = 무엇을 원하는지만 선언 (비절차적)"
[예문] 원하는 정보가 무엇인지만 정의하는 비절차적 언어는 관계 해석이다
[헷갈리는 단어] 관계 대수 - 관계 해석은 무엇을(비절차적), 관계 대수는 어떻게(절차적)

로킹(Locking)
병행 제어를 위한 대표적인 방법으로, 한 트랜잭션이 사용 중인 자료에 다른 트랜잭션이 접근하지 못하도록 제어하는 기법
[구성] 자료 잠금 → 트랜잭션 수행 → 잠금 해제
[의미] 병행 실행 중 데이터 일관성을 지키기 위한 대표 기법 (격리성과 연결됨)
[구분] 로킹 단위에 따른 관계
· 로킹 단위가 클수록: 병행성 수준 낮음
· 로킹 단위가 작을수록: 병행성 수준 높음
· 병행 제어를 하지 않을 때 문제: 연쇄 복귀, 모순성, 갱신 분실
[치트키] "자물쇠 단위가 크면 한 번에 막아서 병행성이 떨어진다"
[예문] 로킹 단위가 커질수록 병행성 수준은 낮아진다

트리거(Trigger)
특정 테이블에 삽입, 수정, 삭제 등의 이벤트가 발생하면 DBMS에서 자동 실행되도록 구현된 프로그램
[구성] 이벤트(INSERT / UPDATE / DELETE) → 자동 실행
[의미] 데이터 변경 시 자동으로 후속 작업을 수행하여 무결성 유지와 로그 기록에 활용
[치트키] "방아쇠(Trigger)를 당기면 자동 발사 = 이벤트 발생 시 자동 실행"
[예문] 주문 테이블에 INSERT가 발생하면 재고 테이블을 자동으로 갱신하는 프로그램은 트리거이다
[헷갈리는 단어] 프로시저 - 트리거는 이벤트 시 자동 실행, 프로시저는 호출해서 실행

프로시저(Procedure)
절차형 SQL을 활용하여 특정 기능을 수행할 수 있는 트랜잭션 언어
[구성] 절차형 SQL + 저장 모듈
[의미] 연속적인 SQL 실행, 조건, 반복, 분기를 하나의 모듈로 저장해 호출하여 사용
[치트키] "프로시저 = 절차(Procedure)를 저장해 두고 필요할 때 호출"
[예문] 여러 SQL을 묶어 DB에 저장해 두고 호출해서 수행하는 모듈은 프로시저이다
[헷갈리는 단어] 트리거 - 프로시저는 직접 호출, 트리거는 이벤트로 자동 실행

CASCADE
DROP 명령으로 삭제할 때 참조 무결성에 의해 연관된 다른 테이블의 데이터도 연쇄적으로 삭제하는 옵션
[구성] 기본 테이블 삭제 → 관계 맺은 데이터 연쇄 삭제
[의미] 참조 무결성 제약조건이 설정된 데이터를 삭제할 때 관련 데이터를 함께 제거
· DROP TABLE 옵션: CASCADE는 참조하는 객체까지 연쇄 삭제, RESTRICT는 참조 중이면 삭제하지 않음
[치트키] "캐스케이드 = 폭포처럼 아래로 연쇄 삭제"
[예문] 부모 테이블 데이터를 삭제하면서 참조하는 자식 데이터도 함께 삭제하는 옵션은 CASCADE이다

뷰(View)
저장 장치 내에 물리적으로 존재하지 않는 가상 테이블
[구성] SELECT 문으로 정의 + 가상 테이블
[의미] 필요한 데이터만 보여 주어 보안과 편의성을 높이지만 삽입·삭제·갱신 연산에 제약이 따름
[치트키] "뷰 = 창문, 보이기만 하는 가짜 테이블"
[예문] 물리적으로 존재하지 않고 SELECT 결과를 보여주는 가상 테이블은 뷰이다

인덱스(Index)
검색을 빠르게 하기 위한 데이터 구조
[구성] 클러스터드 인덱스 + 논클러스터드 인덱스
[의미] 책의 목차처럼 데이터를 빠르게 찾도록 하는 구조로, 조회는 빨라지나 수정·삽입 시 비용이 증가
[구분] 종류별 특징
· 클러스터드 인덱스: 데이터가 이미 정렬되어 조회가 빠르지만 수정·삽입 시 재정렬로 느려지며 테이블당 1개만 생성
· 논클러스터드 인덱스: 속도는 느리지만 한 테이블에 여러 개 생성 가능, 자주 정렬하는 컬럼에 적합
[치트키] "클러스터드는 사전처럼 정렬된 본체 하나, 논클러스터드는 색인 목록 여러 개"
[예문] 한 테이블에 한 개만 만들 수 있고 데이터가 정렬되어 있는 인덱스는 클러스터드 인덱스이다

ERD(개체 관계도)
개체와 개체 간의 관계 등을 약속된 기호로 표현하는 기법
[구성] 사각형(개체) + 타원(속성) + 마름모(관계) + 선(연결)
[의미] P. Chen 박사가 최초로 제안한 개념적 설계의 표현 기법
[구분] 기호별 의미
· 사각형: 개체를 나타냄 (릴레이션으로 표현)
· 타원: 속성을 나타냄
· 마름모: 개체 집합 간의 관계를 나타냄 (외래키로 표현)
· 선: 속성과 개체 집합, 개체 집합과 관계를 연결
[치트키] "사각형은 개체, 타원은 속성, 마름모는 관계"
[예문] 개체를 사각형, 속성을 타원, 관계를 마름모로 나타내는 다이어그램은 ERD이다

논리적 데이터 모델
데이터를 논리적 구조로 표현하는 데이터 모델의 종류 (암기: 관계네)
[구성] 관계 데이터 모델 + 계층 데이터 모델 + 네트워크 데이터 모델
[의미] 데이터 간 연결 방식에 따라 구분
[구분] 모델별 의미
· 관계 데이터 모델: 1:1, 1:N, N:M을 자유롭게 표현할 수 있는 2차원 표 모델
· 계층 데이터 모델: 1:N 관계만 허용하고 트리 형태로 상하관계가 존재
· 네트워크 데이터 모델: N:M 관계만 허용하고 그래프 형태로 구성
[치트키] "관(관계=표) 계(계층=트리) 네(네트워크=그래프) = 관계네"
[예문] 트리 구조로 상하관계가 있고 1:N만 허용하는 모델은 계층 데이터 모델이다

데이터베이스 설계 순서
데이터베이스를 설계하는 5단계 절차 (암기: 개논물)
[구성] 5단계: 요구사항 분석 → 개념적 설계 → 논리적 설계 → 물리적 설계 → 구현
[의미] 요구사항에서 시작해 점차 구체적인 저장 구조로 설계
[구분] 단계별 의미
· 개념적 설계: ERD 다이어그램을 만드는 단계
· 논리적 설계: 정규화(이상현상 제거), 트랜잭션 인터페이스 설계
· 물리적 설계: 성능을 위해 인덱스, 파티션, 클러스터링, 뷰, 프로시저 설계, 반정규화
[치트키] "개(개념) 논(논리) 물(물리) = 개논물"
[예문] 정규화 작업이 이루어지는 데이터베이스 설계 단계는 논리적 설계이다

데이터베이스(DB)의 정의
특정 조직의 여러 응용 시스템이 공동으로 사용하는 통합된 데이터의 집합 (암기: 공장통운)
[구성] 공유 데이터 + 저장 데이터 + 통합 데이터 + 운영 데이터
[의미] 중복을 최소화하면서 다양한 사용자의 정보 요구를 충족시키는 상호 관련된 데이터의 통합된 집합체
[구분] 데이터별 의미
· 공유 데이터: 여러 응용 프로그램이 공통으로 사용하는 데이터
· 저장 데이터: 컴퓨터가 접근 가능한 저장 매체에 저장된 데이터
· 통합 데이터: 검색 효율성을 위해 중복이 최소화된 데이터의 모임
· 운영 데이터: 조직의 목적을 위해 존재 가치가 확실하고 반드시 필요한 데이터
[치트키] "공(공유) 장(저장) 통(통합) 운(운영) = 공장통운"
[예문] 검색 효율성을 위해 중복이 최소화된 데이터의 모임은 통합 데이터이다

데이터 모델 구성 요소
데이터 모델을 구성하는 세 가지 요소 (암기: 연구제)
[구성] 연산 + 구조 + 제약조건
[의미] 데이터를 어떻게 조작하고, 어떤 구조로 저장하며, 어떤 규칙을 지킬지 정의
[구분] 요소별 의미
· 연산: 데이터베이스에 저장된 실제 데이터를 처리하는 작업에 대한 명세
· 구조: 논리적으로 표현된 개체 타입들 간의 관계로 데이터 구조 및 정적 성질을 표현
· 제약조건: 데이터베이스에 저장될 수 있는 실제 데이터의 논리적 제약
[치트키] "연(연산) 구(구조) 제(제약조건) = 연구제"
[예문] 데이터베이스에 저장될 수 있는 데이터의 논리적 제약은 제약조건이다

데이터 모델의 품질 기준
데이터 모델이 잘 만들어졌는지 평가하는 6가지 기준 (암기: 정준일최완활)
[구성] 정확성 + 준거성 + 일관성 + 최신성 + 완전성 + 활용성
[의미] 데이터 모델의 표현, 규칙 준수, 최신 반영 정도를 평가
[구분] 기준별 의미
· 정확성: 표기법에 따라 정확하게 표현되고 요구사항이 정확히 반영
· 준거성: 제반 준수 요건들이 누락 없이 정확하게 준수
· 일관성: 공통 데이터 요소가 전사 수준에서 한 번만 정의되고 참조·활용되며 일관성을 유지
· 최신성: 현행 시스템의 최신 상태를 반영하고 이슈 사항이 지체 없이 반영
· 완전성: 구성 요소 정의와 요구사항 반영에서 누락을 최소화
· 활용성: 업무 변화 시 설계 변경이 최소화되도록 유연하게 설계
[치트키] "정준일 최신 노래 내면서 완전 활발하게 활동중 = 정준일최완활"
[예문] 업무 변화 시 설계 변경이 최소화되도록 유연하게 설계되었음을 의미하는 기준은 활용성이다

DBA
데이터베이스 시스템과 관련된 모든 자원에 대해 기획과 통제를 수행하는 사람 또는 집단
[구성] 데이터베이스 관리 책임자
[의미] 데이터베이스 시스템의 관리와 운영에 책임을 지는 사람
[치트키] "DBA = Database Administrator, DB 관리인"
[예문] 데이터베이스 시스템의 관리와 운영에 대한 책임을 지는 사람은 DBA이다

DBMS
응용 프로그램과 데이터 사이의 중재자로서 모든 응용 프로그램이 데이터베이스에 접근해 데이터를 공유하도록 관리하는 시스템
[구성] 응용 프로그램 ↔ DBMS ↔ 데이터베이스
[의미] 데이터베이스와 사용자를 연결해 주는 관리 소프트웨어
[치트키] "DBMS = DB와 사용자 사이의 관리소 직원"
[예문] 데이터베이스와 사용자를 연결하여 데이터를 공유하게 하는 소프트웨어는 DBMS이다
[헷갈리는 단어] DB - DB는 데이터 집합, DBMS는 이를 관리하는 시스템

데이터베이스 무결성 제약조건
데이터베이스에 저장되는 데이터가 일관성, 유효성, 정확성을 유지하도록 두는 제약조건 (암기: 개참도)
[구성] 개체 무결성 + 참조 무결성 + 도메인 무결성
[의미] 데이터의 정확성과 일관성을 지키기 위한 규칙
[구분] 종류별 의미
· 개체 무결성: 모든 릴레이션은 기본키를 가져야 하며 기본키는 NULL이 있을 수 없고 중복될 수 없음
· 참조 무결성: 외래키는 참조하는 릴레이션의 기본키 값과 동일해야 함
· 도메인 무결성: 속성 값들은 정의된 도메인에 속한 값만 가질 수 있음
· 참고: 일부 족보는 속성 무결성(도메인), 사용자 정의 무결성, 키 무결성까지 5종류로 분류
[치트키] "개(개체) 참(참조) 도(도메인) = 개참도"
[예문] 외래키 값이 참조하는 릴레이션의 기본키 값과 일치해야 한다는 제약조건은 참조 무결성이다

데이터베이스 회복 기법
장애 발생 시 데이터베이스를 정상 상태로 되돌리는 기법
[구성] 로그 기반(즉시 갱신 + 지연 갱신) + 검사점 회복 + 그림자 페이징
[의미] 트랜잭션의 로그나 복사본을 이용해 복구
[구분] 종류별 의미
· 즉시 갱신: 변경 내용을 즉시 DB에 적용
· 지연 갱신: 트랜잭션이 부분 완료될 때까지 적용을 미룸
· 검사점 회복: 체크포인트를 지정해 그 지점 이후만 복구
· 그림자 페이징: 페이지 단위로 복사본을 만들어 보관
[치트키] "로그 / 체크포인트 / 그림자 = 3가지 복구 도구"
[예문] 체크포인트를 지정해 그 이후의 트랜잭션만 처리하는 회복 기법은 검사점 회복 기법이다

검사점 회복 기법
트랜잭션 실행 중간에 검사 시점(Check Point)을 지정하여 그 시점까지 수행하고 완료된 내용을 데이터베이스에 적용하는 기법
[구성] 체크포인트 지정 → 완료된 내용 반영 → 장애 시 체크포인트 이후만 복구
[의미] 복구 시 전체 로그를 처리하지 않고 체크포인트 이후만 처리해 시간을 줄임
[치트키] "게임의 세이브 포인트에서 다시 시작"
[예문] 체크포인트 이후의 로그만 처리하여 복구 시간을 줄이는 기법은 검사점 회복 기법이다

그림자 페이징 기법
데이터베이스를 동일한 크기의 페이지로 나누고 각 페이지마다 복사하여 그림자 페이지를 보관하는 회복 기법
[구성] 현재 페이지 테이블 + 그림자 페이지 테이블
[의미] 장애 시 그림자 페이지로 되돌려 복구
[치트키] "그림자 = 원본 페이지의 백업 사본"
[예문] 페이지 단위로 복사본을 보관해 두었다가 복구하는 기법은 그림자 페이징이다

즉시 갱신 기법(Eager)
변경 내용을 그때그때 바로 데이터베이스에 적용하는 회복 기법
[구성] 변경 즉시 DB 반영 + 로그 기록
[의미] 장애 시 Redo와 Undo를 모두 수행
[치트키] "즉시 = 바로 반영, Redo와 Undo 둘 다"
[예문] 트랜잭션 수행 중 변경 내용을 즉시 반영하며 Redo와 Undo를 모두 수행하는 기법은 즉시 갱신이다
[헷갈리는 단어] 지연 갱신 - 즉시는 Redo와 Undo, 지연은 Redo만

지연 갱신 기법(Lazy)
트랜잭션이 부분 완료될 때까지 DB에 적용하지 않고 지연시킨 후 로그 내용을 토대로 적용하는 기법
[구성] 부분 완료 전까지 반영 보류 → 완료 후 로그로 반영
[의미] 장애 시 Redo만 수행하면 됨
[치트키] "지연 = 끝날 때까지 미룬다, Redo만"
[예문] 트랜잭션이 부분 완료된 후에 로그를 바탕으로 DB에 반영하는 기법은 지연 갱신이다
[헷갈리는 단어] 즉시 갱신 - 지연은 Redo만, 즉시는 Redo와 Undo

데이터베이스 이중화
재해가 일어났을 때를 대비해 동일한 데이터베이스를 중복시켜 동시에 갱신하며 관리하는 기법
[구성] 원본 DB + 복제 DB + 동시 갱신
[의미] 데이터 보호와 가용성 향상을 위한 기법
[구분] 갱신 방식
· Eager 기법: 트랜잭션 수행 중 변경 즉시 반영
· Lazy 기법: 트랜잭션이 완전히 완료된 후 변경 내용 반영
[치트키] "이중화 = 똑같은 DB를 두 벌 두고 함께 갱신"
[예문] 재해에 대비해 동일한 DB를 복제하여 동시에 갱신하는 기법은 데이터베이스 이중화이다

분산 데이터베이스
여러 곳으로 분산되어 있는 데이터베이스를 하나의 가상 시스템으로 사용할 수 있도록 한 데이터베이스
[구성] 여러 지역의 DB + 네트워크 연결 + 하나의 가상 시스템
[의미] 사용자에게는 하나의 DB처럼 보이도록 함
[치트키] "흩어져 있어도 사용자에게는 하나"
[예문] 물리적으로 분산된 DB를 하나의 시스템처럼 사용하게 하는 DB는 분산 데이터베이스이다

분산 데이터베이스 투명성
분산 환경의 복잡함을 사용자에게 숨기는 5가지 투명성
[구성] 위치 + 분할 + 중복 + 병행 + 장애
[의미] 사용자가 분산 여부를 의식하지 않고 사용할 수 있도록 함
[구분] 투명성별 의미
· 위치 투명성: 위치를 알 필요 없이 논리적 명칭만으로 접근 가능
· 분할 투명성: 하나의 논리적 테이블이 여러 조각으로 분할되어 여러 위치에 저장되어도 의식하지 않음
· 중복 투명성: 동일 데이터가 여러 곳에 중복되어도 하나만 존재하는 것처럼 사용
· 병행 투명성: 병행으로 트랜잭션이 수행되어도 결과가 영향을 받지 않음
· 장애 투명성: 장애에도 불구하고 트랜잭션을 정확하게 처리
[치트키] "위(위치) 분(분할) 중(중복) 병(병행) 장(장애) = 위분중병장"
[예문] 데이터가 어디에 있는지 몰라도 논리적 이름만으로 접근할 수 있는 투명성은 위치 투명성이다

파티셔닝(Partitioning)
데이터베이스를 여러 부분으로 분할하는 것
[구성] 수평 분할 + 수직 분할
[의미] 성능과 관리 효율을 높이기 위해 테이블을 나누는 기법
[구분] 방식별 의미
· 수평 분할: 하나의 테이블의 각 행들을 분할
· 수직 분할: 테이블의 일부를 컬럼 기준으로 분할 (하나의 테이블을 2개 이상으로 분해)
· 파티션의 종류: 범위 분할, 해시 분할, 목록 분할, 조합 분할
[치트키] "수평은 행 단위로 가로로 자르고, 수직은 열 단위로 세로로 자른다"
[예문] 테이블의 행을 기준으로 나누는 파티셔닝은 수평 분할이다

시스템 카탈로그
데이터베이스를 관리하기 위해 DB에서 자동으로 생성한 시스템 테이블 (데이터 사전, Data Dictionary)
[구성] 메타데이터 저장 + 자동 생성 시스템 테이블
[의미] 테이블, 인덱스, 사용자 등 DB 객체 정보를 저장
[치트키] "카탈로그 = DB의 설명서, 데이터 사전"
[예문] 데이터베이스가 자동으로 생성해 객체 정보를 저장하는 시스템 테이블은 시스템 카탈로그이다

옵티마이저
사용자가 질의한 SQL문에 대해 최적의 실행 방법을 결정하는 역할을 수행하는 것
[구성] SQL 질의 → 실행 계획 후보 → 최적 계획 선택
[의미] 비용을 비교해 가장 효율적인 처리 경로를 결정하는 DBMS 구성요소
[치트키] "옵티마이저 = SQL의 내비게이션, 가장 빠른 길 선택"
[예문] SQL문의 최적 실행 방법을 결정하는 DBMS 구성요소는 옵티마이저이다

SQL 언어 3가지
SQL을 기능에 따라 구분한 3가지 언어
[구성] DDL(정의어) + DML(조작어) + DCL(제어어)
[의미] 구조를 정의하고, 데이터를 다루며, 권한과 트랜잭션을 제어
[구분] 언어별 명령어
· DDL: CREATE, ALTER, DROP
· DML: SELECT, INSERT, UPDATE, DELETE
· DCL: GRANT, REVOKE, COMMIT, ROLLBACK
[치트키] "정의는 CAD(CREATE, ALTER, DROP), 조작은 SIUD, 제어는 권한과 확정·취소"
[예문] 테이블에서 데이터를 검색하는 SQL 명령어는 DML의 SELECT이다

SELECT 쿼리 집합 연산자
두 개 이상의 SELECT 결과를 합치거나 비교하는 연산자 (WHERE 조건 뒤에 사용)
[구성] UNION + UNION ALL + INTERSECT + EXCEPT(MINUS)
[의미] 질의 결과를 집합으로 다루는 연산
[구분] 연산자별 의미
· UNION: 합집합, 중복된 행을 하나로 출력 (중복 제거)
· UNION ALL: 모든 값을 그대로 결과에 표시
· INTERSECT: 교집합, 서로 중복된 값만 반영
· EXCEPT(MINUS): 차집합, A 테이블에서 B 테이블과 중복된 값을 뺀 A 값만 반영
[치트키] "UNION은 합쳐서 중복 제거, UNION ALL은 그대로 전부"
[예문] 두 SELECT 결과의 중복을 제거하며 합치는 연산자는 UNION이다
[헷갈리는 단어] UNION ALL - UNION은 중복 제거, UNION ALL은 중복 포함

JOIN의 종류
두 테이블을 연결하여 결과를 구하는 방식 (FROM 절의 Table 뒤에 사용)
[구성] 내부 조인(INNER JOIN) + 외부 조인(OUTER JOIN)
[의미] 컬럼 값을 기준으로 테이블을 결합
[구분] 종류별 의미
· 내부 조인: 컬럼 값이 같은 것들끼리 합침
· 외부 조인(LEFT OUTER JOIN): 컬럼이 같은 것을 왼쪽 기준으로 합치고, 같지 않아도 왼쪽 값은 모두 출력
· 예시: FROM 테이블1 INNER JOIN 테이블2 ON 테이블1.컬럼 = 테이블2.컬럼
[치트키] "내부는 일치하는 것만, 왼쪽 외부는 왼쪽을 모두 살린다"
[예문] 왼쪽 테이블의 모든 행을 출력하고 일치하지 않는 오른쪽 값은 NULL로 두는 조인은 LEFT OUTER JOIN이다

SQL 활용 유형
SQL을 응용 프로그램에서 사용하는 방식
[구성] 내장 SQL + 동적 SQL + 절차형 SQL
[의미] 사용 환경과 목적에 따라 SQL을 확장
[구분] 유형별 의미
· 내장 SQL: C, C++, Visual Basic 등 호스트 프로그램 언어에 삽입되어 응용 프로그램과 함께 실행, 호스트 변수 선언문 필요
· 동적 SQL: 컴파일 시 SQL 문장이 확정되지 않을 때 조건에 따라 SQL 구문을 변경
· 절차형 SQL: SQL 문의 연속 실행과 조건에 따른 반복·분기 제어, 저장 모듈 생성 및 활용
[치트키] "내장은 프로그램 안에, 동적은 실행 중 변경, 절차형은 로직까지"
[예문] 컴파일 시점에 SQL 문장이 확정되지 않는 경우에 사용하는 방식은 동적 SQL이다

이행적 함수 종속
릴레이션 A, B, C에서 A가 B를 결정하고 B가 C를 결정하여 결과적으로 A가 C를 결정하는 경우
[구성] A → B + B → C ⇒ A → C
[의미] 3NF에서 제거해야 하는 종속
[치트키] "A→B→C 징검다리, 건너뛰어 A→C"
[예문] A→B이고 B→C이므로 A→C가 성립하는 종속은 이행적 함수 종속이다

튜닝(Tuning)
기존에 존재하는 데이터베이스의 성능 향상을 위해 데이터베이스 시스템이 최적화되도록 재조정하는 기법
[구성] 성능 분석 + 인덱스·SQL 조정
[의미] 이미 운영 중인 DB의 응답 속도와 자원 효율을 높이는 활동
[치트키] "튜닝 = 악기 조율하듯 DB를 최적화"
[예문] 운영 중인 DB의 성능을 개선하기 위해 재조정하는 기법은 튜닝이다

개체(Entity)
데이터베이스에 표현하려는 것으로 사람이 생각하는 개념이나 현실 세계의 대상체
[구성] 실재하는 대상 + 속성
[의미] 데이터로 관리하고자 하는 정보의 단위
[치트키] "엔티티 = 데이터베이스가 관리할 현실의 것"
[예문] 학생, 과목처럼 DB로 표현하려는 현실 세계의 대상을 개체라 한다

함수적 종속(Functional Dependency)
X의 값이 정해지면 Y의 값이 유일하게 결정되는 관계
[구성] X(결정자) → Y(종속자)
[의미] 정규화의 기준이 되는 속성 간의 관계
[구분] 종류별 의미
· 완전 함수적 종속: Y가 X 전체에 종속
· 부분 함수적 종속: Y가 X의 일부 속성에만 종속
· 이행 함수적 종속: X→Y, Y→Z이면 X→Z
[치트키] "결정자가 정해지면 종속자는 하나로 정해진다"
[예문] 학번이 정해지면 이름이 하나로 결정되므로 학번과 이름은 함수적 종속 관계이다

트랜잭션
데이터베이스에서 하나의 논리적 기능을 수행하기 위한 작업 단위
[구성] 여러 연산의 묶음 + ACID 특성
[의미] 모두 성공하거나 모두 취소되어야 하는 업무 처리 단위
[구분] TCL 명령어
· COMMIT: 확정
· ROLLBACK: 취소
· SAVEPOINT: 저장점
[치트키] "트랜잭션 = 쪼갤 수 없는 한 덩어리 업무"
[예문] 계좌이체처럼 출금과 입금을 하나의 작업으로 묶은 단위는 트랜잭션이다

트랜잭션 상태
트랜잭션이 실행되면서 거치는 상태 변화
[구성] 활동 → 부분 완료 → 완료 / 실패 → 철회
[의미] 정상 종료와 오류 시 취소 경로로 구분
[구분] 상태별 의미
· 활동(Active): 실행 중
· 부분 완료(Partially Committed): 마지막 연산까지 수행했으나 아직 COMMIT되지 않음
· 완료(Committed): 성공적으로 종료되어 확정
· 실패(Failed): 오류로 중단
· 철회(Aborted): ROLLBACK으로 취소되어 시작 전 상태로 복귀
[치트키] "활동 → 부분완료 → (성공)완료 / (실패)철회"
[예문] 마지막 연산은 끝났지만 아직 COMMIT되지 않은 상태는 부분 완료이다

병행제어 기법
여러 트랜잭션이 동시에 실행될 때 데이터 일관성을 유지하기 위한 기법
[구성] 로킹 + 타임스탬프 순서 + 낙관적 검증 + 다중 버전(MVCC)
[의미] 갱신 분실, 모순성, 연쇄 복귀를 방지
[구분] 기법별 의미
· 로킹: 데이터에 잠금을 거는 방식
· 타임스탬프 순서: 트랜잭션 시작 시간 순서로 처리
· 낙관적 검증: 충돌이 드물다고 가정하고 실행 후 검증
· 다중 버전(MVCC): 여러 버전의 데이터를 유지하여 읽기와 쓰기 충돌을 줄임
[치트키] "잠그거나(로킹), 시간순(타임스탬프), 나중에 검증(낙관), 버전 여러 개(MVCC)"
[예문] 데이터의 여러 버전을 유지하여 읽기 충돌을 줄이는 병행제어 기법은 MVCC이다

정규화
데이터베이스의 논리적 설계 단계에서 이상 현상과 함수 종속으로 인한 문제를 해결하기 위해 릴레이션을 분해하는 과정
[구성] 1NF → 2NF → 3NF → BCNF → 4NF → 5NF
[의미] 중복을 줄이고 무결성을 높이는 설계 기법
[치트키] "정규화 = 이상 현상을 막기 위해 쪼개기"
[예문] 릴레이션을 분해하여 이상 현상을 제거하는 과정은 정규화이다
[헷갈리는 단어] 반정규화 - 정규화는 중복 제거, 반정규화는 성능을 위해 중복 허용

스키마(Schema)
데이터베이스 설계 단계를 의미하며 데이터베이스를 구성하는 전체적인 구조와 제약 조건
[구성] 외부 스키마 + 개념 스키마 + 내부 스키마
[의미] 데이터의 구조와 규칙을 정의한 설계도
[치트키] "스키마 = DB의 설계도"
[예문] 데이터베이스의 전체 구조와 제약 조건을 정의한 것은 스키마이다

반정규화
시스템 성능 향상과 개발·운영 편의를 위해 정규화된 데이터 모델을 통합·중복·분리하는, 정규화 원칙에 의도적으로 위배되는 행위
[구성] 테이블 병합 + 테이블 분할 + 중복 테이블 추가 + 컬럼 중복화 + 중복 관계 추가
[의미] 조회 성능을 높이기 위해 조인 횟수를 줄이거나 중복을 허용하는 물리적 설계 단계의 기법
[구분] 주요 기법
· 테이블 병합: 1:1, 1:M 관계 테이블을 통합해 조인 횟수를 줄임
· 테이블 분할: 테이블을 수직 또는 수평으로 분할 (파티셔닝)
· 중복 테이블 추가: 집계 함수로 실시간 통계를 계산하는 경우 별도 통계 테이블·중복 테이블을 추가 (집계 테이블, 진행 테이블 포함)
· 컬럼 중복화: 조인 성능 향상을 위해 중복 컬럼을 허용
· 중복 관계 추가: 여러 경로의 조인 성능 저하를 막기 위해 추가 관계를 맺음
[치트키] "병(병합) 분(분할) 중(중복테이블) 컬(컬럼중복) 관(관계추가) = 병분중컬관"
[예문] 조인 성능 향상을 위해 같은 컬럼을 다른 테이블에 중복해서 두는 반정규화 기법은 컬럼 중복화이다
[헷갈리는 단어] 정규화 - 정규화는 중복 제거와 이상현상 해결, 반정규화는 성능을 위해 중복 허용

외래키 제약조건 SQL 문법
CREATE TABLE에서 다른 테이블을 참조하는 외래키 제약조건을 정의하는 구문
[구성] CONSTRAINT 제약조건명 + FOREIGN KEY (컬럼) + REFERENCES 참조테이블 (참조컬럼)
[의미] 참조 무결성을 보장하기 위해 자식 테이블의 컬럼이 부모 테이블의 기본키(또는 유일키)를 참조하도록 설정
[구분] 2026년 1회 기출 빈칸 매칭
· ( 1 ): CONSTRAINT
· ( 2 ) KEY: FOREIGN
· ( 3 ): (TEAM_ID) 형태의 외래키 컬럼
· ( 4 ): REFERENCES
· ( 5 ): (TEAM_ID2) 형태의 참조 컬럼
· 선택 옵션: ON DELETE CASCADE 등
[치트키] "제약(CONSTRAINT) 이름 짓고 외래(FOREIGN) 키 지정, 참조(REFERENCES)할 곳 명시"
[예문] CONSTRAINT TEAM_TF FOREIGN KEY (TEAM_ID) REFERENCES TEAM (TEAM_ID2) 형태로 외래키를 정의한다
[헷갈리는 단어] PRIMARY KEY - 기본키는 PRIMARY KEY (컬럼), 외래키는 FOREIGN KEY ... REFERENCES

SELECT DISTINCT와 COUNT
검색 결과의 행 수를 구하는 SQL 문에서 DISTINCT와 COUNT의 동작 차이
[구성] SELECT 컬럼 → 중복 포함 행 수 / SELECT DISTINCT 컬럼 → 중복 제거 행 수 / COUNT(DISTINCT 컬럼) → 중복 제거 값의 개수
[의미] 2026년 1회 기출처럼 학과별 학생 수가 주어지면 각 SQL의 반환 행 수를 계산
[구분] 예시 (컴퓨터과 50명, 인터넷과 100명, 사무자동화과 50명 가정)
· SELECT DEPT FROM STUDENT: 전체 행 수 = 200
· SELECT DISTINCT DEPT FROM STUDENT: 학과 종류 수 = 3
· SELECT COUNT(DISTINCT DEPT) FROM STUDENT WHERE DEPT = 컴퓨터과: 집계 결과 1행(값 1)
[치트키] "COUNT 같은 집계 함수는 GROUP BY가 없으면 항상 1행"
[예문] WHERE 조건에 맞는 행이 있어도 COUNT(DISTINCT 컬럼)을 사용하면 결과는 1행이다
[헷갈리는 단어] COUNT(*) - COUNT(*)는 행 전체를 세고, COUNT(컬럼)은 NULL 제외, COUNT(DISTINCT 컬럼)은 중복 제외

서브쿼리(Subquery)
하나의 SQL 문 안에 포함된 또 다른 SELECT 문
[구성] 메인 쿼리 + 서브쿼리 (WHERE, FROM, SELECT 절에서 사용)
[의미] 서브쿼리 결과를 메인 쿼리의 조건이나 값으로 활용
[구분] 사용 예
· WHERE d.budget 초과 (SELECT AVG(budget) FROM dept): 평균보다 예산이 큰 부서만 조회
· 2026년 1회 기출은 이 서브쿼리와 JOIN을 결합해 조건에 맞는 직원 수를 COUNT로 구하는 문제
· 풀이 순서: 서브쿼리로 평균 계산 → 평균보다 큰 부서 선별 → 해당 부서의 직원과 JOIN → COUNT
[치트키] "안쪽 쿼리를 먼저 계산하고 바깥에서 비교"
[예문] 평균 예산보다 큰 부서의 직원 수를 구하려면 서브쿼리로 평균을 먼저 계산한다

절차형 SQL 종류
SQL에 절차적 제어(조건, 반복, 분기)를 추가하여 저장 모듈로 만든 객체
[구성] 프로시저 + 사용자 정의 함수 + 트리거
[의미] 반복되는 로직을 DB 안에 저장해 호출하거나 이벤트로 자동 실행
[구분] 종류별 의미
· 프로시저: 특정 기능을 수행하는 트랜잭션 언어, 호출해서 실행
· 사용자 정의 함수: 값을 계산해 반환
· 트리거: INSERT, UPDATE, DELETE 이벤트 발생 시 자동 실행
[치트키] "프함트 = 프로시저, 함수, 트리거"
[예문] 테이블에 이벤트가 발생하면 자동 실행되는 절차형 SQL은 트리거이다

트랜잭션 격리 수준
동시에 실행되는 트랜잭션 사이의 간섭 허용 정도를 정한 4단계
[구성] Read Uncommitted → Read Committed → Repeatable Read → Serializable Read
[의미] 위로 갈수록 격리가 약하고 아래로 갈수록 강해지지만 동시성은 낮아짐
[구분] 단계별 의미
· Read Uncommitted: 커밋되지 않은 데이터도 읽음 (Dirty Read 가능)
· Read Committed: 커밋된 데이터만 읽음
· Repeatable Read: 같은 데이터를 반복해서 읽어도 같은 결과
· Serializable Read: 트랜잭션을 순차 실행한 것과 같은 결과 (가장 엄격)
[치트키] "미커밋 → 커밋 → 반복읽기 → 직렬화 순으로 점점 엄격"
[예문] 가장 높은 격리 수준으로 직렬 실행과 같은 결과를 보장하는 것은 Serializable Read이다

데이터베이스 장애 유형
데이터베이스 운영 중 발생할 수 있는 장애의 4가지 유형
[구성] 실행 장애 + 트랜잭션 장애 + 시스템 장애 + 미디어 장애
[의미] 장애 범위에 따라 회복 기법이 달라짐
[구분] 유형별 의미
· 트랜잭션 장애: 트랜잭션 내부 오류로 비정상 종료
· 시스템 장애: 하드웨어·OS·DBMS 오류로 시스템 중단
· 미디어 장애: 디스크 손상 등 저장 매체 오류
[치트키] "작은 것부터 트랜잭션 → 시스템 → 미디어"
[예문] 디스크 헤드 손상 같은 저장 매체 문제로 발생하는 장애는 미디어 장애이다

병행제어 미보장 시 문제점
트랜잭션을 동시에 실행하면서 병행제어를 하지 않을 때 발생하는 문제
[구성] 갱신 손실 + 현황 파악 오류 + 모순성 + 연쇄 복귀
[의미] 데이터 일관성과 무결성을 해치므로 로킹 등 병행제어가 필요
[구분] 문제별 의미
· 갱신 손실(분실): 두 트랜잭션이 같은 데이터를 갱신하여 한쪽 결과가 사라짐
· 현황 파악 오류: 갱신 중인 값을 읽어 잘못된 현황을 파악
· 모순성: 같은 데이터에 대한 결과가 서로 일치하지 않음
· 연쇄 복귀: 한 트랜잭션의 롤백이 다른 트랜잭션의 롤백을 연쇄적으로 유발
[치트키] "갱현모연 = 갱신손실 현황오류 모순성 연쇄복귀"
[예문] 한 트랜잭션의 롤백이 다른 트랜잭션의 롤백으로 이어지는 문제는 연쇄 복귀이다

TCL(트랜잭션 제어어) 명령어
트랜잭션의 결과를 확정하거나 취소하는 명령어
[구성] COMMIT + ROLLBACK + SAVEPOINT
[의미] 한 덩어리로 실행한 SQL 작업의 반영 여부를 제어
[구분] 명령어별 의미
· COMMIT: 트랜잭션을 확정하여 DB에 영구 반영
· ROLLBACK: 트랜잭션을 취소하여 이전 상태로 복귀
· SAVEPOINT: 롤백 시점을 지정하는 저장점 (일부 자료에서 체크포인트로 잘못 표기)
[치트키] "확정 커밋, 취소 롤백, 저장점 세이브포인트"
[예문] 롤백할 지점을 지정하는 TCL 명령어는 SAVEPOINT이다

SELECT 문 절의 구성과 실행 순서
질의의 각 절이 하는 일과 논리적 실행 순서
[구성] FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY
[의미] SQL 작성 문제에서 절의 역할을 구분해 정확히 쓰기 위한 기준
[구분] 절별 역할
· FROM: 대상 테이블
· WHERE: 행 조건 (집계 함수 사용 불가)
· GROUP BY: ~별로 그룹화 (문제에 ~별이 나오면 사용)
· HAVING: 그룹에 대한 조건
· ORDER BY: 정렬 (ASC 기본, DESC 내림차순)
[치트키] "프웨그해셀오 = FROM WHERE GROUP HAVING SELECT ORDER"
[예문] 그룹화 후 그룹에 대한 조건을 지정하는 절은 HAVING이다
