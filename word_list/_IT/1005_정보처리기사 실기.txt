애자일(Agile) 방법론
사람이 중심이 되어 유연하고 신속하게 시스템을 개발하는 신속 적응적 경량 개발 방법론
[구성] 스크럼 + XP 등 대표 기법
[의미] 문서·계획 중심의 무거운 개발에서 벗어나 변화에 빠르게 대응하며 고객과 협력하는 개발 방식
[구분] 대표 기법
· 스크럼: 정해진 주기로 반복 개발하는 프로젝트 관리 중심 기법
· XP: 피드백·단순성 등 가치를 중심으로 한 개발 실천 기법
[치트키] "사람(애자일의 핵심)이 중심이라 가볍고 빠르게 적응한다 → 경량·신속·적응"
[예문] 요구사항이 자주 바뀌는 프로젝트에서는 애자일 방법론으로 짧은 주기마다 결과물을 고객에게 확인받는다

스크럼(Scrum) 구성요소
매일 정해진 시간·장소에서 짧게 협업하며 짧은 주기로 반복 개발하는 팀 중심 애자일 기법
[구성] 백로그 + 스프린트 + 스크럼 미팅 + 스크럼 마스터 + 스프린트 회고 + 번다운 차트
[의미] 스프린트 단위로 개발하고 매일 점검하며 품질과 진행 상황을 지속적으로 개선하는 구조
[구분] 구성요소별 역할
· 백로그: 제품과 프로젝트에 대한 요구사항 목록
· 스프린트: 2~4주의 짧은 기간 동안 반복 수행해 개발 품질을 높이는 주기
· 스크럼 미팅: 매일 15분 정도 진행하며 할 일(To-do-list)을 수립
· 스크럼 마스터: 프로젝트의 리더로 문제를 인지하고 해결하는 사람
· 스프린트 회고: 스프린트를 되돌아보며 규칙 준수 여부와 개선점을 기록
· 번다운 차트: 남은 백로그 대비 시간을 그래프로 표현한 차트
[치트키] "백로그에서 골라 → 스프린트로 달리고 → 매일 미팅 → 마스터가 이끌고 → 회고하고 → 번다운으로 확인"
[예문] 번다운 차트는 남은 백로그 대비 시간을 그래픽으로 표현하여 스프린트 진행 상황을 한눈에 보여준다
[헷갈리는 단어] XP - 스크럼은 프로젝트 관리 중심, XP는 프로그래밍 실천 중심

XP(eXtreme Programming)
고객 요구에 빠르게 대응하기 위해 짧은 주기로 개발하는 애자일 기법 (암기: 피존용단소)
[구성] 피드백(Feedback) + 존중(Respect) + 용기(Courage) + 단순성(Simplicity) + 의사소통(Communication)
[의미] 개발자와 고객의 긴밀한 협력과 빠른 피드백으로 변화하는 요구사항에 대응하는 개발 방법론
[구분] 5가지 핵심 가치
· 피드백: 빠른 피드백으로 방향을 수정
· 존중: 팀원과 고객을 존중
· 용기: 변경과 개선을 두려워하지 않음
· 단순성: 필요한 것만 단순하게 구현
· 의사소통: 팀원·고객 간 원활한 소통
[치트키] "피(피드백) 존(존중) 용(용기) 단(단순성) 소(의사소통) = 피존용단소, 피존용 단소(짧은 피리)를 분다"
[예문] XP의 5가지 핵심 가치는 피드백, 존중, 용기, 단순성, 의사소통이다

XP 12가지 기본 원리
XP를 실천하는 12가지 개발 원리
[구성] 계획 게임 + 소규모 릴리즈 + 메타포 + 단순 설계 + 테스트 기반 개발(TDD) + 리팩토링 + 짝 프로그래밍 + 공동 소유권 + 지속적 통합(CI) + 주 40시간 + 고객 상주 + 코딩 표준
[의미] 짧은 반복과 지속적인 개선으로 품질과 의사소통을 확보하기 위한 구체적 실천 방법
[구분] 시험 빈출 4가지
· 리팩토링: 기능은 바꾸지 않고 중복 제거·단순화로 시스템을 재구성, 목적은 유지보수성 향상
· 테스트 기반 개발(TDD): 테스트를 먼저 작성하고 이를 통과하도록 실제 코드를 작성
· 지속적인 통합(CI): 매일 여러 번 소프트웨어를 통합하고 빌드
· 메타포: 공통된 이름 체계와 시스템 서술서로 고객과 개발자 간 의사소통을 원활하게 함
[치트키] "리팩토링은 정리정돈, TDD는 시험 먼저, CI는 매일 합치기, 메타포는 비유로 소통"
[예문] 기능은 그대로 두고 중복을 제거해 유지보수성을 높이는 XP 원리는 리팩토링이다
[헷갈리는 단어] CI - 소프트웨어를 통합·빌드하는 원리이고, TDD는 테스트를 먼저 작성하는 원리

DoS
네트워크 구조의 취약점을 이용하거나 대량의 데이터를 보내 정상적인 서비스를 못 하게 하는 공격
[구성] 공격자 → 대량 요청·취약점 악용 → 대상 서버 자원 고갈 → 서비스 중단
[의미] 정보 보안 3요소 중 가용성을 침해하는 대표적인 공격
[구분] 대표 공격
· SYN Flooding
· 죽음의 핑(Ping of Death)
· 랜드 어택(Land Attack)
· 스머프(Smurf)
[치트키] "도스(DoS) = 서비스 도둑맞기, 정상 서비스를 거부당한다 → 가용성 침해"
[예문] DoS 공격은 대량의 데이터를 보내 정상적인 서비스를 제공하지 못하게 만들어 가용성을 침해한다
[헷갈리는 단어] DDoS - DoS는 단일 공격지, DDoS는 좀비 PC 여러 대를 이용한 분산 공격

DDoS
여러 대의 컴퓨터를 감염시켜(좀비 PC) 한 타겟 시스템을 집중 공격하는 방법
[구성] 공격자 → 마스터 → 좀비 PC 다수 → 타겟 시스템
[의미] 분산된 다수의 공격지에서 동시에 요청을 보내 대상 서비스를 마비시키는 DoS의 확장형
[구분] 대표 DDoS 공격 도구
· Trinoo: 많은 소스로부터 통합된 UDP Flood 서비스 거부 공격을 유발하는 도구
· TFN: Trinoo와 유사하며 UDP Flood뿐 아니라 TCP SYN flood, ICMP echo 요청, ICMP 브로드캐스트(스머프) 공격까지 수행
· Stacheldraht: 분산 서비스 거부 에이전트 역할을 하는 Linux·Solaris용 멀웨어 도구, ICMP Flood·SYN flood·UDP Flood·Smurf 등 수행
[치트키] "디(분산)도스 = 좀비 군단이 한 곳을 집중 공격"
[예문] DDoS는 좀비 PC를 이용해 하나의 타겟 시스템에 트래픽을 집중시켜 서비스를 마비시킨다
[헷갈리는 단어] DoS - 공격 주체가 하나이면 DoS, 여러 대의 좀비 PC이면 DDoS

죽음의 핑(Ping of Death)
ICMP 패킷을 정상보다 매우 크게 만들어 전송해 서비스를 마비시키는 공격
[구성] 큰 ICMP 패킷 전송 → 다수의 IP 단편화 발생 → 수신 측 부하·오버플로우 → 서비스 불가
[의미] 정상 크기를 초과한 ICMP 패킷의 단편화를 이용해 수신 측의 정상적인 서비스를 방해하는 DoS 공격
[치트키] "죽을 만큼 큰 핑(Ping) 하나 = 거대 ICMP 패킷"
[예문] 정상 크기보다 큰 ICMP 패킷으로 다수의 IP 단편화를 일으켜 수신 측을 마비시키는 공격은 Ping of Death이다

SYN Flooding
TCP의 취약점을 이용해 다량의 SYN 패킷을 보내 백로그 큐를 가득 채우는 DoS 공격
[구성] 다량의 SYN 전송 → 서버가 SYN/ACK 응답 후 ACK 대기 → 백로그 큐 가득 참 → 정상 연결 불가
[의미] TCP 3-way handshake의 연결 대기 자원을 고갈시켜 서비스를 거부하게 만드는 공격
[치트키] "SYN만 홍수처럼(Flooding) 보내서 대기실(백로그 큐)을 가득 채운다"
[예문] 다량의 SYN 패킷으로 서버의 백로그 큐를 가득 채워 새 연결을 막는 공격은 SYN Flooding이다
[헷갈리는 단어] Land Attack - SYN Flooding은 SYN 다량 전송, Land Attack은 출발지·목적지 주소를 같게 위조

랜드 어택(Land Attack)
출발지 IP와 목적지 IP를 같은 패킷 주소로 보내 시스템 가용성을 침해하는 공격
[구성] 출발지 IP = 목적지 IP로 위조한 패킷 전송 → 수신자가 자기 자신에게 응답 → 시스템 부하
[의미] 수신자가 자기 자신에게 패킷을 보내게 만들어 가용성을 침해하는 DoS 공격
[치트키] "랜드(Land) = 내 땅으로 되돌아오는 패킷, 보낸 곳과 받는 곳이 같다"
[예문] 출발지와 목적지 IP를 동일하게 위조한 패킷으로 시스템을 마비시키는 공격은 Land Attack이다

스머프(Smurf)
출발지 주소를 공격 대상 IP로 위조해 네트워크 전체에 ICMP Echo 패킷을 브로드캐스팅하여 마비시키는 공격
[구성] 출발지를 피해자 IP로 위조 → ICMP Echo를 브로드캐스트 → 다수 호스트가 피해자에게 응답 → 트래픽 폭주
[의미] 증폭 효과를 이용해 대상 서버를 ICMP 응답으로 마비시키는 DoS 공격
[치트키] "스머프 마을 전체에 소리쳐(브로드캐스트) 모두가 피해자에게 대답하게 만든다"
[예문] 피해자 IP로 위조한 ICMP Echo를 브로드캐스트하여 응답 트래픽을 몰아주는 공격은 Smurf이다
[헷갈리는 단어] Ping of Death - Smurf는 브로드캐스트 증폭, Ping of Death은 거대 패킷의 단편화

스니핑(Sniffing)
네트워크 중간에서 남의 패킷 정보를 도청하는 해킹 유형
[구성] 네트워크 패킷 수집 → 분석 → 정보 획득
[의미] 수동적으로 패킷을 엿보아 계정·비밀번호 등을 탈취하는 공격으로 기밀성을 침해
[치트키] "스니핑 = 킁킁 냄새 맡듯 몰래 엿듣기"
[예문] 스니핑은 네트워크 중간에서 패킷을 도청하여 정보를 탈취하는 공격이다
[헷갈리는 단어] 스푸핑 - 스니핑은 도청(수동적), 스푸핑은 위장(능동적)

IP 스푸핑
해커가 자신의 IP를 숨기고 다른 사람의 IP를 부당하게 취득해 합법적 사용자로 위장하여 공격하는 기법
[구성] 공격자 IP 은닉 → 신뢰받는 IP로 위조 → 대상 공격
[의미] 네트워크의 취약점을 이용해 신뢰 관계를 가진 호스트로 위장하는 공격
[치트키] "스푸핑 = 남의 얼굴로 위장하기, IP 스푸핑은 IP를 훔쳐 쓴다"
[예문] 공격자가 신뢰받는 호스트의 IP로 위장하여 접속하는 공격은 IP 스푸핑이다

ARP 스푸핑
공격자가 특정 호스트의 MAC 주소를 자신의 MAC 주소로 위조한 ARP Reply를 만들어 희생자에게 지속적으로 전송하는 공격
[구성] 위조 ARP Reply 지속 전송 → 희생자의 ARP 테이블 변조 → 패킷이 공격자에게 전달
[의미] IP와 MAC 주소 매핑 정보를 속여 통신 내용을 가로채는 공격
[치트키] "ARP = IP를 MAC으로 바꾸는 안내원, 안내원에게 거짓 주소를 계속 알려준다"
[예문] ARP 테이블을 위조된 ARP Reply로 오염시켜 패킷을 가로채는 공격은 ARP 스푸핑이다

DNS 스푸핑
DNS 서버로 보내는 질문을 가로채 변조된 결과를 보내주는 일종의 중간자 공격
[구성] DNS 질의 가로채기 → 변조된 응답 전송 → 가짜 사이트로 유도
[의미] 도메인 질의 결과를 위조하여 사용자를 의도하지 않은 사이트로 접속시키는 공격
[치트키] "DNS(전화번호부)에 가짜 번호를 끼워 넣는다"
[예문] 사용자의 DNS 질의에 변조된 응답을 보내 악성 사이트로 접속시키는 공격은 DNS 스푸핑이다

스위치 재밍(Switch Jamming)
위조된 MAC 주소를 지속적으로 흘려보내 스위치의 MAC 주소 테이블 저장 기능을 혼란시켜 더미 허브처럼 작동하게 하는 스니핑 기법
[구성] 위조 MAC 주소 대량 전송 → MAC 주소 테이블 포화 → 스위치가 허브처럼 동작 → 패킷 스니핑
[의미] 스위치 환경에서도 패킷을 도청할 수 있도록 스위치의 정상 동작을 방해하는 공격
[치트키] "스위치에 가짜 MAC을 가득 채워(재밍) 허브로 만든다"
[예문] MAC 주소 테이블을 가득 채워 스위치를 허브처럼 동작하게 만드는 스니핑 기법은 스위치 재밍이다

XSS(Cross-Site Scripting)
검증되지 않은 외부 입력 데이터가 포함된 웹페이지를 열람할 때 부적절한 스크립트가 실행되는 공격
[구성] 악성 스크립트 삽입 → 사용자가 해당 페이지 열람 → 사용자 PC(브라우저)에서 스크립트 실행
[의미] 웹 애플리케이션의 입력값 검증 미흡을 악용해 사용자 브라우저에서 악성 스크립트를 실행시키는 공격
[구분] CSRF와의 차이
· XSS: 공격 대상이 사용자 PC(클라이언트)
· CSRF: 공격 대상이 서버
[치트키] "XSS = 사용자 PC에서 스크립트가 터진다 (X-스크립트-S)"
[예문] 게시글에 삽입된 악성 스크립트가 열람자의 브라우저에서 실행되는 공격은 XSS이다
[헷갈리는 단어] CSRF - XSS는 사용자 PC에서 스크립트 실행, CSRF는 사용자 권한으로 서버에 위조 요청

CSRF(Cross-Site Request Forgery)
사용자가 자신의 의지와 무관하게 공격자가 의도한 행동을 하게 만들어 서버에서 수정·삭제 등을 수행시키는 공격
[구성] 로그인된 사용자 유도 → 위조된 요청 전송 → 사용자 권한으로 서버에서 실행
[의미] 사용자의 인증 상태를 악용해 서버에 원하지 않는 요청을 보내게 하는 웹 공격
[치트키] "CSRF = 사용자 이름으로 서버에 가짜 요청서(Request Forgery)를 제출"
[예문] 로그인 상태의 사용자가 모르는 사이 게시글 삭제 요청이 서버로 전송되는 공격은 CSRF이다
[헷갈리는 단어] XSS - CSRF는 서버에 위조 요청, XSS는 사용자 PC에서 스크립트 실행

SQL Injection
웹 프로그램에 악의적인 SQL 구문을 삽입·실행시켜 DB를 조작하는 공격
[구성] 입력값에 악성 SQL 삽입 → 서버가 그대로 실행 → DB 정보 노출·변조
[의미] 입력값 검증이 미흡한 웹 애플리케이션의 취약점을 이용한 대표적인 웹 공격
[치트키] "SQL을 주사기(Injection)로 몰래 주입"
[예문] 로그인 입력창에 악의적인 SQL 구문을 넣어 인증을 우회하는 공격은 SQL Injection이다

APT
지속적이고 지능적인 해킹 공격의 통칭
[구성] 침투 → 잠복 → 내부 확산 → 정보 탈취
[의미] 특정 대상을 목표로 장기간에 걸쳐 은밀하게 수행하는 지능형 지속 위협
[치트키] "APT = 끈질기게(Persistent) 똑똑하게(Advanced) 위협(Threat)"
[예문] 특정 기업을 장기간 노려 은밀하게 정보를 빼내는 지능적 해킹 공격은 APT이다

Rainbow Table Attack
단방향 해시 암호로 만들어낼 수 있는 값들을 대량으로 저장한 표(테이블)를 이용하는 공격
[구성] 평문과 해시값 쌍을 미리 계산해 표로 저장 → 탈취한 해시값을 표에서 검색 → 원문 복원
[의미] 해시 함수가 단방향이어도 해시값에서 원문을 찾을 수 있도록 미리 계산해 둔 표를 이용하는 공격
[치트키] "무지개(Rainbow) 표 = 해시값 답안지를 미리 만들어 둔 표"
[예문] 미리 계산해 둔 해시값 테이블로 비밀번호를 찾아내는 공격은 Rainbow Table Attack이다

RAID
디스크 어레이(Disk Array)라고도 하며, 여러 개의 하드디스크에 일부 중복 데이터를 나눠 저장하는 기술
[구성] 여러 디스크 + 분산 저장 + 중복 데이터
[의미] 여러 디스크를 하나처럼 사용해 성능과 안정성을 높이는 저장 기술
[치트키] "RAID = 디스크 여러 개를 묶어 나눠 담고 중복으로 안전하게"
[예문] 여러 하드디스크에 데이터를 나누어 저장하고 일부를 중복시켜 안정성을 높이는 기술은 RAID이다

REST
HTTP URI로 자원을 표시하고 HTTP Method로 해당 자원에 대한 CRUD 연산을 적용하는 방식
[구성] URI(자원 표현) + HTTP Method(행위) + 표현(JSON 등)
[의미] 자원을 URI로 구분하고 HTTP 메서드로 행위를 표현하는 웹 아키텍처 스타일
[구분] CRUD와 HTTP Method 대응
· CREATE: POST (자원 생성)
· READ: GET (자원 정보 조회)
· UPDATE: PUT (자원 정보 업데이트)
· DELETE: DELETE (자원 삭제)
[치트키] "생성은 포스트(POST), 조회는 게시판 조회 GET, 수정은 PUT, 삭제는 DELETE"
[예문] REST 방식에서는 GET으로 자원을 조회하고 DELETE로 자원을 삭제한다

디지털 저작권 관리(DRM) 구성요소
디지털 콘텐츠의 불법 복제와 무단 사용을 막기 위해 저작권을 보호·관리하는 기술의 구성요소
[구성] 콘텐츠 제공자 + 콘텐츠 분배자 + 패키저 + 보안 컨테이너 + DRM 컨트롤러 + 클리어링 하우스
[의미] 암호화된 콘텐츠를 안전하게 유통하고 이용 권한을 통제하기 위한 구성
[구분] 구성요소별 역할
· 콘텐츠 제공자: 콘텐츠를 제공하는 저작권자
· 콘텐츠 분배자: 쇼핑몰 등으로서 암호화된 콘텐츠를 분배·제공
· 패키저: 콘텐츠를 메타데이터와 함께 배포 가능한 단위로 묶음
· 보안 컨테이너: 원본을 안전하게 유통하기 위한 전자적 보안 장치
· DRM 컨트롤러: 배포된 콘텐츠의 이용 권한을 통제
· 클리어링 하우스: 소비자와 유통업자 사이의 거래에서 라이선스 발급·중계를 수행하는 정산소
[치트키] "제공자가 만들고 → 패키저가 포장하고 → 분배자가 팔고 → 컨트롤러가 권한 통제 → 클리어링 하우스가 정산"
[예문] 클리어링 하우스는 DRM에서 라이선스 발급과 거래 정산을 중계하는 역할을 한다

정보 보안의 3대 요소
정보 보안을 위해 보장해야 하는 세 가지 핵심 특성 (암기: 기무가)
[구성] 기밀성(Confidentiality) + 무결성(Integrity) + 가용성(Availability)
[의미] 정보 자산을 보호하기 위한 기본 목표로, 하나라도 침해되면 보안 사고로 이어짐
[구분] 요소별 의미
· 기밀성: 인가되지 않은 사용자에게 정보가 공개·노출되지 않도록 차단
· 무결성: 인가되지 않은 사용자가 데이터를 변경·파괴하지 못하게 보장
· 가용성: 인가된 사용자가 서비스를 지속해서 사용할 수 있도록 보장
[치트키] "기(기밀성) 무(무결성) 가(가용성) = 기무가, 기무가(기모노) 입고 보안 지킨다"
[예문] DoS 공격은 정보 보안의 3대 요소 중 가용성을 침해한다
[헷갈리는 단어] 무결성 - 무결성은 변조 방지, 기밀성은 노출 방지

클라우드 서비스 유형
클라우드로 제공하는 서비스의 범위에 따른 세 가지 유형 (암기: 인플소)
[구성] 인프라형(IaaS) → 플랫폼형(PaaS) → 소프트웨어형(SaaS)
[의미] 서버·플랫폼·소프트웨어 중 어디까지를 서비스로 제공하는지에 따라 구분
[구분] 유형별 설명
· IaaS: 서버 같은 시스템 자원을 클라우드로 제공
· PaaS: 소프트웨어를 개발할 수 있는 플랫폼을 제공
· SaaS: 소프트웨어와 데이터를 중앙에 호스팅하고 사용자는 웹 브라우저 등으로 접속해 이용
[치트키] "인(인프라) 플(플랫폼) 소(소프트웨어) = 인플소, 인플소(인형 풀소) 순서로 위로 올라간다"
[예문] 서버 같은 시스템 자원을 클라우드로 빌려 쓰는 서비스는 IaaS이다

소프트웨어 테스트의 원리
소프트웨어 테스트에서 지켜야 할 7가지 원리 (암기: 결완초집살정오)
[구성] 결함 존재 + 완벽 불가 + 초기 시작 + 결함 집중 + 살충제 패러독스 + 정황 의존 + 오류 부재의 궤변
[의미] 테스트의 한계와 효율적인 수행 방법을 정리한 일반 원리
[구분] 원리별 의미
· 결함 존재 증명: 결함이 존재함을 밝힐 뿐 결함이 없다는 것을 증명할 수 없음
· 완벽 불가: 완벽한 테스팅은 불가능하며 시도 자체가 시간과 자원의 낭비
· 초기 시작: 개발 초기에 테스트를 시작해야 후반 비용 증가를 막을 수 있음
· 결함 집중: 오류의 80%는 전체 모듈의 20%에서 발견 (파레토 법칙과 유사)
· 살충제 패러독스: 동일한 테스트 케이스를 반복하면 새로운 버그를 찾지 못함
· 정황 의존: 소프트웨어 성격에 맞게 테스트
· 오류 부재의 궤변: 요구사항을 충족하지 못하면 결함이 없어도 품질이 높다고 볼 수 없음
[치트키] "결(결함존재) 완(완벽불가) 초(초기) 집(집중) 살(살충제) 정(정황) 오(오류부재) = 결완초집살정오"
[예문] 동일한 테스트 케이스를 반복하면 새로운 버그를 찾지 못하는 현상은 살충제 패러독스이다

요구사항 개발 프로세스
요구사항을 도출하고 확정하기까지의 4단계 절차 (암기: 도분명확)
[구성] 4단계: 도출 → 분석 → 명세 → 확인
[의미] 이해관계자의 요구를 수집하여 문서화하고 올바른지 검증하는 표준 절차
[구분] 단계별 하는 일
· 도출: 이해관계자로부터 요구사항을 수집
· 분석: 요구 충돌·중복을 해결하고 우선순위를 정리
· 명세: 요구사항을 문서화
· 확인: 명세가 올바른지 검토·검증
[치트키] "도(도출) 분(분석) 명(명세) 확(확인) = 도분명확, 도분(두 분)이 명확하게 확인한다"
[예문] 요구사항 개발 프로세스는 도출, 분석, 명세, 확인 순으로 진행된다
[헷갈리는 단어] 분석과 확인 - 분석은 정리, 확인은 검증

WSDL
XML으로 작성되며 웹 서비스와 데이터를 주고받기 위한 설명서
[구성] XML 기반 + 서비스 설명 + 이용 방법 명세
[의미] 웹 서비스의 위치와 호출 방법을 기술한 문서
[치트키] "WSDL = 웹 서비스 설명서(Description)"
[예문] 웹 서비스의 인터페이스를 XML로 기술한 설명서는 WSDL이다
[헷갈리는 단어] UDDI - WSDL은 설명서, UDDI는 그 설명서를 등록·검색하는 저장소

UDDI
웹 서비스 정보인 WSDL을 등록하고 검색하기 위한, 공개적으로 접근·검색 가능한 레지스트리
[구성] 등록 + 검색 + 공개 레지스트리
[의미] 서비스 제공자와 이용자를 연결하는 웹 서비스의 저장소
[치트키] "UDDI = 서비스 전화번호부(Directory)"
[예문] WSDL을 등록하고 검색하는 레지스트리는 UDDI이다
[헷갈리는 단어] WSDL - UDDI는 저장소(검색), WSDL은 설명서

SOAP
XML 기반의 메시지를 컴퓨터 네트워크 상에서 교환하는 프로토콜
[구성] XML 메시지 + 네트워크 전송 프로토콜
[의미] 웹 서비스 간에 구조화된 정보를 주고받기 위한 메시징 규약
[치트키] "SOAP = 비누로 깨끗이 포장한 XML 메시지"
[예문] 웹 서비스에서 XML 메시지를 교환하는 프로토콜은 SOAP이다

DRS(재해복구시스템)의 유형
재해 시 업무를 신속히 복구하기 위한 재해복구센터의 운영 방식 4가지
[구성] Mirror Site → Hot Site → Warm Site → Cold Site
[의미] 복구 속도가 빠를수록 비용이 높고, 느릴수록 비용이 낮아지는 구조
[구분] 유형별 특징 (복구 소요 시간 RTO 기준)
· Mirror Site: 주 센터와 복구센터가 모두 운영 상태, RTO는 즉시
· Hot Site: 주 센터와 동일한 자원을 대기 상태로 원격지에 보유하며 미러링으로 최신 상태 유지, RTO는 4시간 이내
· Warm Site: 중요성이 높은 자원만 부분적으로 보유, 백업 주기는 수 시간~1일, RTO는 수일~수주
· Cold Site: 데이터만 원격지에 보관하고 재해 시 필요 자원을 조달해 복구, RTO는 수주~수개월
[치트키] "미러(즉시) → 핫(4시간) → 웜(수일) → 콜드(수개월), 뜨거울수록 빠르고 차가울수록 늦다"
[예문] 데이터만 원격지에 보관하고 재해 발생 시 자원을 조달해 복구하는 센터는 Cold Site이다

RTO(Recovery Time Objective)
재해 복구 목표 시간
[구성] 재해 발생 → 서비스 중단 → RTO 이내 복구
[의미] 재해로 서비스가 중단되었을 때 복구하는 데 걸리는 최대 허용 시간이며 0이면 실시간 복구를 의미
[치트키] "T(Time) = 시간, 얼마나 걸려서 되살릴 것인가"
[예문] 재해 발생 후 서비스를 복구하는 데 허용되는 최대 시간은 RTO이다
[헷갈리는 단어] RPO - RTO는 복구 시간, RPO는 허용 가능한 데이터 손실 시점

RPO(Recovery Point Objective)
재해 복구 목표 시점
[구성] 재해 발생 시점 ← 마지막 백업 시점 (이 간격이 RPO)
[의미] 재해 발생 시 데이터 손실을 수용할 수 있는 손실 허용 시점이며 데이터 손실 최소화와 관련된 개념
[치트키] "P(Point) = 시점, 어느 시점의 데이터까지 살릴 것인가"
[예문] 재해 시 어느 시점까지의 데이터 손실을 허용할지 정한 지표는 RPO이다
[헷갈리는 단어] RTO - RPO는 데이터 손실 시점, RTO는 복구 소요 시간

결합도(Coupling)
모듈 간 상호 의존 정도로, 낮을수록 좋은 설계 (암기: 내공외제스자)
[구성] 내용 → 공통 → 외부 → 제어 → 스탬프 → 자료 (결합도 높음 → 낮음)
[의미] 모듈 사이의 의존 관계가 약할수록 수정 영향이 적고 재사용이 쉬워 품질이 높음
[구분] 유형별 특징
· 내용: 다른 모듈의 내부 변수·기능을 직접 사용
· 공통: 전역 변수를 참조하고 갱신
· 외부: 외부에서 도입된 데이터 포맷, 통신 프로토콜, 디바이스 인터페이스를 공유
· 제어: 값만 전달하지 않고 제어 요소를 전달
· 스탬프: 배열·객체 등 자료구조를 전달
· 자료: 파라미터를 통해서만 상호작용 (가장 이상적)
[치트키] "내부공사는 외제를 쓰자 = 내공외제스자, 내용이 가장 나쁘고 자료가 가장 좋다"
[예문] 모듈 간에 값만 파라미터로 주고받는 결합도는 자료 결합도로 가장 바람직하다
[헷갈리는 단어] 응집도 - 결합도는 낮을수록 좋고, 응집도는 높을수록 좋음

응집도(Cohesion)
모듈 내부 요소들의 관련성으로, 높을수록 좋은 설계 (암기: 우논시절통순기)
[구성] 우연적 → 논리적 → 시간적 → 절차적 → 통신적 → 순차적 → 기능적 (응집도 낮음 → 높음)
[의미] 하나의 모듈 안의 구성 요소들이 얼마나 단일 목적에 집중하는지를 나타냄
[구분] 유형별 특징
· 우연적: 모듈 내부 구성 요소들이 서로 연관이 없음
· 논리적: 유사하거나 특정한 요소를 한 모듈에서 처리
· 시간적: 특정 시간에 처리되는 기능들을 모음
· 절차적: 모듈 안의 여러 기능을 순차적으로 실행
· 통신적: 동일한 입출력을 사용하는 서로 다른 기능을 수행하는 요소의 모임 (교환적이라고도 함)
· 순차적: 한 활동의 출력이 다른 활동의 입력으로 사용
· 기능적: 모듈 내부 기능이 단일 목적을 위해 사용 (가장 이상적)
[치트키] "우리가 논 시절에 먹은 통통한 순대가 기가 막혔다 = 우논시절통순기"
[예문] 모듈 내부의 모든 요소가 하나의 기능만 수행하는 응집도는 기능적 응집도이다
[헷갈리는 단어] 결합도 - 응집도는 높을수록 좋고, 결합도는 낮을수록 좋음

ACID
Atomicity, Consistency, Isolation, Durability / 트랜잭션이 안전하게 수행되기 위해 보장해야 하는 4가지 특성 (암기: 원일격영)
[구성] A=Atomicity(원자성) + C=Consistency(일관성) + I=Isolation(격리성) + D=Durability(영속성·지속성)
[의미] 하나의 논리적 기능을 수행하는 작업 단위인 트랜잭션이 정상적으로 수행되기 위해 반드시 유지해야 하는 특성
[구분] 특성별 의미
· 원자성: 연산이 모두 수행되거나 모두 수행되지 않아야 함 (COMMIT, ROLLBACK)
· 일관성: 트랜잭션 수행 전과 완료 후의 상태가 일관되게 유지
· 격리성: 수행 중인 트랜잭션에 다른 트랜잭션이 접근할 수 없고 각각 독립적이어야 함
· 지속성: 성공적으로 완료된 트랜잭션의 결과는 영구히 보존 (영속성이라고도 함)
[치트키] "원자가 일찍 격리되어 영면했다 = 원일격영"
[예문] 트랜잭션의 ACID 특성 중 원자성은 모두 반영되거나 전혀 반영되지 않아야 함을 의미한다
[헷갈리는 단어] 격리성 - 격리성은 동시 실행 간섭 방지, 일관성은 수행 전후 상태 유지

정규화 과정
이상 현상과 함수 종속으로 인한 문제를 해결하기 위해 릴레이션을 단계적으로 분해하는 과정 (암기: 도부이결다조)
[구성] 1NF → 2NF → 3NF → BCNF → 4NF → 5NF
[의미] 논리적 설계 단계에서 데이터 중복과 이상 현상을 제거하여 구조를 안정화
[구분] 단계별 제거 대상
· 1NF: 모든 도메인이 원자값으로만 구성, 반복 그룹 제거
· 2NF: 부분 함수 종속 제거 (모든 속성이 기본키에 완전 함수 종속)
· 3NF: 이행적 함수 종속 제거
· BCNF: 결정자가 후보키가 아닌 함수 종속 제거 (모든 결정자가 후보키)
· 4NF: 다치 종속 제거
· 5NF: 조인 종속이 후보키를 통해서만 성립되도록 제거
[치트키] "도(도메인 원자값) 부(부분) 이(이행) 결(결정자) 다(다치) 조(조인) = 두부 이걸 다 줘?"
[예문] 정규화에서 이행적 함수 종속을 제거하는 단계는 제3정규형이다
[헷갈리는 단어] 반정규화 - 정규화는 중복 제거, 반정규화는 성능을 위해 중복을 허용

디자인 패턴의 종류
객체지향 설계에서 반복되는 문제의 검증된 해법을 세 부류로 나눈 GoF 23가지 패턴 (암기: 생구행)
[구성] 생성 패턴(5) + 구조 패턴(7) + 행위 패턴(11)
[의미] 설계 재사용을 위해 객체 생성 방식, 객체 조합 구조, 객체 간 책임과 상호작용을 정리한 패턴 모음
[구분] 분류별 패턴
· 생성(생빌프로팩앱싱): Builder, Prototype, Factory Method, Abstract Factory, Singleton
· 구조(구브데퍼플프록컴어): Bridge, Decorator, Facade, Flyweight, Proxy, Composite, Adapter
· 행위: Chain of Responsibility, Command, Interpreter, Iterator, Mediator, Memento, Observer, State, Strategy, Template Method, Visitor
[치트키] "생(생성) 구(구조) 행(행위) = 생구행, 생성 5 구조 7 행위 11"
[예문] 객체의 상태 변화를 관찰자들에게 통지하는 패턴은 행위 패턴인 Observer이다

SOLID
객체지향 설계의 5가지 원칙
[구성] S=SRP(단일 책임) + O=OCP(개방 폐쇄) + L=LSP(리스코프 치환) + I=ISP(인터페이스 분리) + D=DIP(의존 역전)
[의미] 변경에 유연하고 유지보수가 쉬운 객체지향 설계를 위한 원칙
[구분] 원칙별 의미
· SRP: 한 클래스는 하나의 책임만 가져야 함
· OCP: 기존 코드를 변경하지 않고 기능을 추가할 수 있도록 설계
· LSP: 자식 클래스는 언제나 부모 클래스를 대체할 수 있어야 함
· ISP: 자신이 사용하지 않는 인터페이스는 구현하지 않아야 함
· DIP: 변화가 잦은 것보다 변화가 거의 없는 것에 의존해야 함
[치트키] "솔리드(SOLID) 순서대로 S단일 O개방 L리스코프 I인터페이스 D의존"
[예문] 기존 코드를 수정하지 않고 기능을 확장할 수 있어야 한다는 원칙은 개방 폐쇄 원칙(OCP)이다

스키마 3계층
데이터베이스를 사용자 관점부터 물리적 저장 관점까지 세 단계로 나누어 정의한 구조 (암기: 외개내)
[구성] 외부 스키마 → 개념 스키마 → 내부 스키마
[의미] 사용자와 물리 저장 구조를 분리해 데이터 독립성을 확보하기 위한 구조
[구분] 계층별 의미
· 외부 스키마: 사용자나 응용 프로그램이 보는 논리적 구조 (서브 스키마라고도 함)
· 개념 스키마: 전체적인 논리적 구조로, 개체 간 관계·제약 조건·접근 권한·보안·무결성 규정을 정의
· 내부 스키마: 데이터베이스의 물리적 구조를 정의하며 전체 데이터베이스에 하나만 존재
[치트키] "외(외부) 개(개념) 내(내부) = 외개내, 바깥에서 안쪽으로"
[예문] 데이터베이스의 물리적 저장 구조를 정의하며 하나만 존재하는 스키마는 내부 스키마이다

키(Key)의 종류
릴레이션에서 튜플을 식별하거나 관계를 맺기 위해 사용하는 속성 집합
[구성] 슈퍼키 ⊃ 후보키 ⊃ 기본키 / 대체키 / 외래키
[의미] 유일성과 최소성을 기준으로 튜플을 식별하고, 릴레이션 간 관계를 표현
[구분] 키별 의미
· 기본키(Primary Key): 각 튜플을 고유하게 식별하는 컬럼
· 대체키: 후보키 중 기본키로 선택되지 않은 키
· 후보키: 기본키와 대체키를 합친 키로 튜플을 구별하는 기준
· 슈퍼키: 유일성은 만족하지만 최소성은 만족하지 못하는 키
· 외래키(Foreign Key): 다른 릴레이션을 참조하는 속성
[치트키] "슈퍼키는 유일성만, 후보키는 유일성 + 최소성, 기본키는 후보키 중 대표, 나머지는 대체키"
[예문] 후보키 중 기본키로 선택되지 않은 키를 대체키라 한다
[헷갈리는 단어] 슈퍼키와 후보키 - 슈퍼키는 최소성 불만족, 후보키는 유일성과 최소성 모두 만족

이상현상(Anomaly)
릴레이션 조작 시 데이터가 불필요하게 중복되어 예기치 않게 발생하는 곤란한 현상 (암기: 삽삭갱)
[구성] 삽입 이상 + 삭제 이상 + 갱신 이상
[의미] 설계가 잘못된 릴레이션에서 데이터 조작 시 발생하는 문제로 정규화로 해결
[구분] 종류별 의미
· 삽입 이상: 원하는 값만 삽입하고 싶은데 필요 없는 필드의 값도 함께 삽입해야 하는 경우
· 삭제 이상: 하나의 튜플 삭제 시 삭제를 원하지 않는 속성값도 같이 지워지는 문제
· 갱신 이상: 중복된 값 중 일부만 업데이트되어 속성값 간 불일치가 발생하는 현상
[치트키] "삽(삽입) 삭(삭제) 갱(갱신) = 삽삭갱, 삽살개가 짖는다"
[예문] 중복된 데이터 중 일부만 수정되어 값이 서로 달라지는 현상은 갱신 이상이다

접근 제어 방식
사용자의 자원 접근 권한을 통제하는 방식 3가지 (암기: MDR)
[구성] MAC + DAC + RBAC
[의미] 권한을 누가 어떤 기준으로 부여하는지에 따라 구분하는 접근통제 방식
[구분] 방식별 의미
· MAC(강제적 접근통제): 관리자가 지정·관리하는 대상에 권한을 부여
· DAC(임의적 접근통제): 접근 권한을 가진 사용자가 자신의 판단에 따라 권한을 허용
· RBAC(역할 기반 접근통제): 조직 내 개인의 역할에 따라 권한을 부여
[치트키] "M(관리자가 강제) D(소유자가 임의) R(역할에 따라)"
[예문] 조직 내 개인의 역할에 따라 접근 권한을 부여하는 방식은 RBAC이다

접근 통제 보호 모델
접근 통제를 위한 대표적인 보안 모델 (암기: BB)
[구성] BLP(벨라파듈라) + Biba
[의미] 기밀성을 강조하는 모델과 무결성을 강조하는 모델로 구분
[구분] 모델별 특징
· BLP: 미 국방부 지원 보안 모델로 기밀성을 강조하며 강제적 정책으로 접근을 통제, No Read Up, No Write Down
· Biba: 무결성을 보장하는 최초의 모델, No Read Down, No Write Up
[치트키] "기밀은 BLP(위를 읽지 마, 아래에 쓰지 마), 무결성은 Biba(아래를 읽지 마, 위에 쓰지 마)"
[예문] 무결성을 보장하는 최초의 접근 통제 모델로 No Read Down, No Write Up 속성을 갖는 것은 Biba이다
[헷갈리는 단어] BLP - BLP는 기밀성, Biba는 무결성

HRN(Highest Response Ratio Next)
응답 비율이 가장 큰 프로세스부터 배치하는 비선점형 스케줄링 (우선순위 = (대기시간 + 서비스시간) / 서비스시간)
[구성] 우선순위 = (대기시간 + 서비스시간) / 서비스시간 → 값이 큰 프로세스 먼저 실행
[의미] SJF의 긴 작업 무한 대기(기아 현상)를 해결하기 위한 기법
[구분] 계산 예시
· 대기 5, 서비스 2이면 (5 + 2) / 2 = 3.5
· 서비스 시간이 짧고 대기 시간이 길수록 우선순위가 높음
[치트키] "대기 + 서비스를 서비스로 나눈다 → 오래 기다린 놈이 이긴다"
[예문] 대기시간 5, 서비스시간 2인 작업의 HRN 우선순위는 3.5이다
[헷갈리는 단어] SJF - SJF는 짧은 작업 우선이라 기아 발생, HRN은 대기시간 반영으로 기아 해결

OSI 7계층
데이터 통신 과정을 7개 계층으로 표준화한 참조 모델 (암기: 물데네전세표응)
[구성] 7단계: 물리 → 데이터링크 → 네트워크 → 전송 → 세션 → 표현 → 응용
[의미] 통신 기능을 계층별로 나누어 서로 다른 시스템 간 호환과 표준화를 돕는 모델
[구분] 계층별 전송 단위와 장비
· 7 응용: 데이터, HTTP·FTP
· 6 표현: 데이터, JPEG·MPEG, 암호화·압축
· 5 세션: 데이터, RPC·NETBIOS
· 4 전송: 세그먼트, TCP·UDP, L4 스위치
· 3 네트워크: 패킷, IP·ICMP, 라우터
· 2 데이터링크: 프레임, HDLC·PPP, 브리지·스위치
· 1 물리: 비트, RS-232C, 허브·리피터
[치트키] "물데네전세표응 (1→7), 영어는 아파서티내다피나다 (7→1)"
[예문] 패킷 단위로 경로 선택을 담당하며 라우터를 사용하는 계층은 네트워크 계층이다

교착상태(Deadlock)
둘 이상의 프로세스가 서로의 자원을 기다리며 무한 대기하는 상태
[구성] 상호 배제 + 점유와 대기 + 비선점 + 환형 대기
[의미] 4가지 조건이 모두 성립할 때 발생하며, 하나라도 제거하면 예방할 수 있음
[구분] 해결 방법 4가지
· 예방: 4조건 중 하나를 제거
· 회피: 안전 상태를 유지하며 자원을 할당 (은행원 알고리즘)
· 탐지: 발생 여부를 검사 (자원 할당 그래프)
· 회복: 프로세스 강제 종료 또는 자원 선점으로 해제
[치트키] "상(상호배제) 점(점유대기) 비(비선점) 환(환형대기) = 상점비환, 4개가 모두 있어야 교착"
[예문] 자원을 점유한 채 다른 자원을 기다리는 교착상태 발생 조건은 점유와 대기이다
[헷갈리는 단어] 기아 현상 - 교착상태는 서로 맞물려 무한 대기, 기아는 우선순위가 낮아 자원을 못 받음

카디날리티(Cardinality)
릴레이션(표) 내 튜플(행)의 개수
[구성] 카디날리티 = 튜플(행)의 수
[의미] 릴레이션의 세로 길이를 나타내는 값으로, 차수와 함께 릴레이션의 크기를 설명하는 지표
[치트키] "카디날리티의 카 = 행의 수를 카운트, 차수는 열의 수"
[예문] 행이 3개인 릴레이션의 카디날리티는 3이다
[헷갈리는 단어] 차수 - 카디날리티는 튜플(행)의 수, 차수는 속성(열)의 수

차수(Degree)
릴레이션 내 속성(애트리뷰트)의 개수
[구성] 차수 = 속성(열)의 수
[의미] 릴레이션의 가로 길이를 나타내는 값
[치트키] "디그리(차수)는 열(기둥)의 개수, 카디날리티는 행의 개수"
[예문] 속성이 4개인 릴레이션의 차수는 4이다
[헷갈리는 단어] 카디날리티 - 차수는 속성의 수, 카디날리티는 튜플의 수

도메인(Domain)
하나의 속성이 취할 수 있는 같은 타입의 원자값들의 집합
[구성] 속성 + 허용되는 값의 범위
[의미] 속성에 들어갈 수 있는 값의 범위를 정의하여 데이터의 유효성을 보장
[구분] 관련 용어
· 튜플: 관계 데이터 모델에서 한 행을 구성하는 속성들의 집합
· 속성(애트리뷰트): 관계형 데이터베이스에서 사용되는 데이터의 가장 작은 논리적 단위
[치트키] "도메인 = 속성이 가질 수 있는 값의 동네(범위)"
[예문] 성별 속성이 남 또는 여만 가질 수 있도록 정한 값의 집합이 도메인이다

ISO/IEC 9126 품질 특성
소프트웨어 제품의 품질을 평가하는 6가지 특성 (암기: 기신사효유이)
[구성] 기능성 + 신뢰성 + 사용성 + 효율성 + 유지보수성 + 이식성
[의미] 소프트웨어 품질을 객관적으로 평가하기 위한 국제 표준의 품질 특성
[구분] 특성별 의미
· 기능성: 정확하지 않은 결과가 발생할 확률과 관련해 시스템 동작을 관찰하기 위한 품질
· 신뢰성: 일정한 시간 동안 의도하는 기능을 수행함을 보장하는 품질
· 사용성: 사용자와 컴퓨터 사이의 행위를 정확하고 쉽게 인지할 수 있는 품질
· 효율성: 할당된 시간에 한정된 자원으로 얼마나 빨리 처리하는지에 대한 품질
· 유지보수성: 요구사항을 개선하고 확장하기 얼마나 용이한지에 대한 품질 기준
· 이식성: 다른 플랫폼에서도 얼마나 쉽게 적용 가능한지에 대한 품질 기준
[치트키] "기(기능성) 신(신뢰성) 사(사용성) 효(효율성) 유(유지보수성) 이(이식성) = 기신사효유이"
[예문] 다른 운영체제에서도 쉽게 설치하고 사용할 수 있는지를 나타내는 품질 특성은 이식성이다

스토리지 장치 구성
데이터를 저장하는 저장소를 서버와 연결하는 방식 3가지 (암기: 다나스)
[구성] DAS + NAS + SAN
[의미] 저장장치와 서버의 연결 방식에 따라 규모와 용도가 달라짐
[구분] 방식별 특징
· DAS: PC나 서버에 USB처럼 직접 꽂아 1:1로 연결, 소규모에 적합
· NAS: 서버와 저장장치를 네트워크로 연결, 서버 한 곳에서 파일을 관리해 파일 공유가 용이, 중규모에 적합
· SAN: 서버와 저장장치를 광채널 스위치로 연결한 고속 데이터 네트워크, 대규모에 적합
[치트키] "다(DAS) 나(NAS) 스(SAN) = 다나스, 작은 것에서 큰 것 순서"
[예문] 광채널 스위치로 서버와 저장장치를 연결한 고속 데이터 네트워크는 SAN이다

기아 현상(Starvation)
우선순위가 낮은 작업이 CPU를 할당받지 못해 처리되지 않는 현상
[구성] 우선순위 낮음 → 계속 밀림 → 무한 대기
[의미] 우선순위 기반 스케줄링에서 낮은 우선순위 프로세스가 자원을 받지 못하는 문제
[구분] 해결 방법
· 에이징: 대기 시간에 비례해 우선순위를 높여줌
· HRN: 대기 시간을 우선순위에 반영
[치트키] "기아 = 굶주림, 우선순위에 밀려 영원히 굶는 프로세스"
[예문] 우선순위가 낮은 작업이 CPU를 계속 할당받지 못하는 현상을 기아 현상이라 한다

에이징(Aging)
자원 할당 과정에서 기아 현상을 방지하기 위해 대기시간에 비례하여 우선순위를 부여하는 기법
[구성] 대기시간 증가 → 우선순위 점진적 상승 → 결국 실행
[의미] 오래 기다린 프로세스가 반드시 자원을 얻도록 하는 기아 방지 기법
[치트키] "에이징 = 나이(대기시간)가 들수록 대접(우선순위)이 올라간다"
[예문] 기아 현상을 방지하기 위해 대기시간에 비례하여 우선순위를 높이는 기법은 에이징이다

관계 대수(Relational Algebra)
원하는 정보와 그 정보를 유도하기 위한 과정을 함께 기술하는 절차적 언어 (암기: 대절해비)
[구성] 순수 관계 연산자 + 일반 집합 연산자
[의미] 릴레이션에서 결과를 얻기 위한 절차를 연산자로 표현하는 방식
[구분] 연산자 구분
· 순수 관계 연산자: SELECT, PROJECT, JOIN, DIVISION
· 일반 집합 연산자: 합집합, 교집합, 차집합, 카티션 프로덕트
[치트키] "대수는 절차적, 해석은 비절차적 = 대절해비"
[예문] 결과를 얻기 위한 처리 절차까지 기술하는 데이터 언어는 관계 대수이다
[헷갈리는 단어] 관계 해석 - 관계 대수는 어떻게(절차적), 관계 해석은 무엇을(비절차적)

관계 해석(Relational Calculus)
원하는 정보가 무엇인지만 정의하는 비절차적 언어 (암기: 대절해비)
[구성] 술어 논리 기반 + 튜플 해석 / 도메인 해석
[의미] 결과를 얻는 과정은 기술하지 않고 원하는 결과만 선언하는 방식
[치트키] "해석은 해석만 한다 = 무엇을 원하는지만 선언 (비절차적)"
[예문] 원하는 정보가 무엇인지만 정의하는 비절차적 언어는 관계 해석이다
[헷갈리는 단어] 관계 대수 - 관계 해석은 무엇을(비절차적), 관계 대수는 어떻게(절차적)

하둡(Hadoop)
다수의 범용 컴퓨터를 연결해 하나의 시스템처럼 작동하도록 묶어 분산 처리하는 공개 소스 프레임워크
[구성] 범용 컴퓨터 클러스터 + 분산 저장 + 분산 처리
[의미] 대용량 데이터를 저렴한 장비로 분산 처리하기 위한 오픈소스 빅데이터 프레임워크
[치트키] "하둡 = 여럿이 힘을 모아 하나처럼 처리 (분산)"
[예문] 범용 컴퓨터 여러 대를 묶어 대용량 데이터를 분산 처리하는 오픈소스 프레임워크는 하둡이다

스쿱(Sqoop)
SQL To Hadoop, SQL과 하둡을 같이 쓸 수 있게 하는 도구
[구성] SQL + Hadoop
[의미] 관계형 데이터베이스와 하둡 사이에서 데이터를 옮겨 주는 도구
[치트키] "스쿱 = 관계형 DB 데이터를 하둡으로 퍼 담는 국자"
[예문] 관계형 데이터베이스의 데이터를 하둡으로 가져오는 도구는 스쿱이다

NoSQL
RDBMS와 다르게 설계된 비관계형 데이터베이스
[구성] Not Only SQL + 비관계형 + 유연한 스키마
[의미] 정형 데이터뿐 아니라 비정형 데이터도 다루며 대용량 분산 환경에 적합한 DB
[치트키] "노(No) SQL = 표(관계형)에 얽매이지 않는 DB"
[예문] 관계형이 아닌 방식으로 대용량 데이터를 유연하게 저장하는 DB는 NoSQL이다
[헷갈리는 단어] RDBMS - NoSQL은 비관계형, RDBMS는 관계형

OLAP
다수의 테이블을 효율적으로 검색할 수 있도록 하는 분석형 애플리케이션
[구성] 다차원 분석 + 데이터 웨어하우스 연계
[의미] 사용자가 다양한 관점에서 데이터를 대화식으로 분석하도록 지원
[치트키] "OLAP = 올라가며(Online) 분석(Analytical)"
[예문] 데이터 웨어하우스의 데이터를 다차원으로 분석하는 도구는 OLAP이다

데이터 웨어하우스(DW)
데이터베이스에 축적된 데이터를 공통으로 모아서 관리하는 데이터베이스
[구성] 여러 원천 데이터 + 통합 + 주제별 저장
[의미] 의사결정을 위해 기업 전체 데이터를 통합 저장한 대규모 저장소
[치트키] "웨어하우스 = 데이터 창고"
[예문] 여러 시스템의 데이터를 통합 저장해 분석에 활용하는 저장소는 데이터 웨어하우스이다
[헷갈리는 단어] 데이터 마트 - 웨어하우스는 전체, 마트는 특정 부서·주제의 일부

데이터 마트(Data Mart)
전체 데이터 웨어하우스의 일부 데이터를 가지고 특정 사용자가 관심 있는 데이터를 담은 비교적 작은 규모의 웨어하우스
[구성] 데이터 웨어하우스의 일부 + 특정 부서·주제
[의미] 특정 사용자 요구에 맞게 데이터를 분리해 접근성과 분석 효율을 높인 소규모 저장소
[치트키] "마트 = 창고에서 필요한 것만 꺼내 진열한 동네 마트"
[예문] 마케팅 부서가 사용하기 위해 데이터 웨어하우스에서 일부만 추출한 저장소는 데이터 마트이다

데이터 마이닝(Data Mining)
대규모 데이터 안에서 체계적이고 자동적으로 규칙이나 패턴을 찾아내는 기술
[구성] 대규모 데이터 + 규칙·패턴 탐색
[의미] 숨겨진 유용한 정보를 자동으로 발견하는 분석 기술
[구분] 유사 용어
· 텍스트 마이닝: 대규모 텍스트에서 의미 있는 정보를 추출
· 웹 마이닝: 웹의 대규모 정보 중 유용한 정보를 찾아내는 기법
[치트키] "마이닝 = 데이터 광산에서 금(패턴)을 캔다"
[예문] 대규모 데이터에서 규칙이나 패턴을 자동으로 찾아내는 기술은 데이터 마이닝이다

메타 데이터(Meta Data)
데이터에 대한 데이터, 다른 데이터를 설명해 주는 구조화된 데이터
[구성] 데이터 + 설명 정보
[의미] 데이터의 구조·의미·출처를 설명하여 검색과 관리에 활용
[치트키] "메타 = 한 단계 위, 데이터를 설명하는 데이터"
[예문] 사진 파일의 촬영일과 크기 정보처럼 데이터를 설명하는 데이터는 메타 데이터이다

로킹(Locking)
병행 제어를 위한 대표적인 방법으로, 한 트랜잭션이 사용 중인 자료에 다른 트랜잭션이 접근하지 못하도록 제어하는 기법
[구성] 자료 잠금 → 트랜잭션 수행 → 잠금 해제
[의미] 병행 실행 중 데이터 일관성을 지키기 위한 대표 기법 (격리성과 연결됨)
[구분] 로킹 단위에 따른 관계
· 로킹 단위가 클수록: 병행성 수준 낮음
· 로킹 단위가 작을수록: 병행성 수준 높음
· 병행 제어를 하지 않을 때 문제: 연쇄 복귀, 모순성, 갱신 분실
[치트키] "자물쇠 단위가 크면 한 번에 막아서 병행성이 떨어진다"
[예문] 로킹 단위가 커질수록 병행성 수준은 낮아진다

대칭키 암호 알고리즘
암호화와 복호화에 동일한 키를 사용하는 암호 방식 (블록 암호)
[구성] DES + AES + SEED + ARIA + IDEA
[의미] 같은 키를 공유하므로 속도가 빠르지만 키 전달 문제가 있음
[구분] 알고리즘별 특징
· DES: 64bit 블록, 56bit 키 사용, Feistel 방식
· AES: DES를 대체, 128/192/256bit 키, SPN 방식
· SEED: 순수 국내 기술로 개발한 128/256bit 알고리즘
· ARIA: AES와 같이 128/192/256bit 키 제공
· IDEA: 스위스에서 PES를 개량하여 만든 블록 암호
[치트키] "DES는 56 · AES는 128/192/256 · SEED·ARIA는 국산"
[예문] DES를 대체하며 128/192/256bit 키를 사용하는 대칭키 알고리즘은 AES이다
[헷갈리는 단어] 비대칭키 - 대칭키는 같은 키, 비대칭키는 서로 다른 키

비대칭키 암호 알고리즘
암호화와 복호화에 서로 다른 키를 사용하는 암호 방식
[구성] 공개키 + 개인키
[의미] 키 분배가 쉽지만 속도가 느림
[구분] 대표 알고리즘
· RSA: 소인수분해를 활용한 비대칭 암호화 알고리즘
· DSA: 미국의 전자 서명 표준
[치트키] "RSA = 소인수 분해, DSA = 서명(Signature)"
[예문] 소인수분해의 어려움에 기반한 비대칭 암호 알고리즘은 RSA이다

해시 함수 특성
임의 길이 입력을 고정 길이 출력으로 변환하는 단방향 함수가 갖춰야 할 3가지 저항성
[구성] 역상 저항성 + 제2 역상 저항성 + 충돌 저항성
[의미] 해시값으로 원문을 알아내거나 같은 해시값을 만드는 입력을 찾기 어렵게 하는 성질
[구분] 특성별 의미
· 역상 저항성: 해시값이 주어졌을 때 그 해시값을 만드는 입력값을 알아내기 불가능
· 제2 역상 저항성: 어떤 입력값과 같은 해시값을 가지는 다른 입력값을 찾을 수 없어야 함
· 충돌 저항성: 해시값이 같은 서로 다른 두 입력을 찾을 수 없어야 함
· 대표 알고리즘: SHA는 미국 국가 표준, MD5는 MD4를 대체한 128bit 해시
[치트키] "하나 주고 원문 못 찾기(역상), 원문 주고 짝 못 찾기(제2역상), 둘 다 못 찾기(충돌)"
[예문] 서로 다른 두 입력이 같은 해시값을 가지지 않도록 하는 특성은 충돌 저항성이다

디스패치(Dispatch)
프로세스 상태 전이 중 준비 상태의 여러 프로세스 가운데 실행될 프로세스를 선정해 CPU를 할당하는 동작
[구성] 준비(Ready) → 실행(Running)
[의미] 스케줄러가 선택한 프로세스에 CPU를 넘겨주는 동작
[치트키] "디스패치 = 파견, 준비실의 프로세스를 CPU로 파견"
[예문] 준비 상태의 프로세스에 CPU를 할당하여 실행 상태로 바꾸는 동작은 디스패치이다

선점형 프로세스 스케줄링
실행 중인 프로세스를 강제로 빼앗을 수 있는 스케줄링 방식
[구성] RR + SRT + MLQ + MLFQ
[의미] 시분할·대화형 시스템에서 응답성을 높이기 위해 사용
[구분] 방식별 특징
· RR(라운드 로빈): 같은 크기의 CPU 시간을 할당하고, 시간 내 완료 못하면 준비 큐의 맨 뒤로 이동
· SRT: 남은 시간이 가장 적은 프로세스부터 배치
· MLQ(다단계 큐): 작업을 여러 그룹으로 분할하고 큐마다 독자 스케줄링, 상위 단계 작업이 하위를 선점
· MLFQ(다단계 피드백 큐): 입출력·CPU 위주 특성에 따라 큐마다 CPU 시간 할당량을 다르게 부여 (FCFS + RR 통합)
[치트키] "선점 4총사 = RR · SRT · MLQ · MLFQ"
[예문] 같은 크기의 CPU 시간을 순환하며 할당하는 선점형 방식은 라운드 로빈이다
[헷갈리는 단어] 비선점형 - 선점형은 CPU를 뺏을 수 있고 비선점형은 끝날 때까지 실행

비선점형 프로세스 스케줄링
한 프로세스가 CPU를 잡으면 끝날 때까지 빼앗기지 않는 스케줄링 방식
[구성] FCFS + SJF + HRN + 우선순위 + 기한부
[의미] 구현이 단순하고 오버헤드가 적지만 긴 작업이 앞에 있으면 대기 시간이 길어질 수 있음
[구분] 방식별 특징
· FCFS(FIFO): 먼저 도착한 프로세스를 먼저 실행
· SJF: 가장 작은 서비스 시간을 갖는 프로세스가 종료 시까지 자원 점유
· HRN: 응답 비율이 큰 프로세스부터 배치, 기아 현상 해결
· 우선순위, 기한부 방식 포함
[치트키] "비선점 = 끝날 때까지 안 뺏는다, FCFS는 먼저 온 순, SJF는 짧은 순, HRN은 비율 순"
[예문] 먼저 도착한 프로세스를 먼저 실행하고 종료하는 방식은 FCFS이다

블루투스 공격
블루투스 장비의 취약점을 이용하는 공격 유형 4가지
[구성] 블루버그 + 블루스나프 + 블루재킹 + 블루프린팅
[의미] 블루투스 연결 관리와 검색 기능의 취약점을 악용한 공격
[구분] 공격별 의미
· 블루버그: 블루투스 장비 사이의 취약한 연결 관리를 악용한 공격
· 블루스나프: 블루투스 취약점을 활용해 장비의 파일에 접근하는 공격
· 블루재킹: 블루투스를 이용해 스팸처럼 명함을 익명으로 퍼뜨리는 공격
· 블루프린팅: 블루투스 공격 장치의 검색 활동
[치트키] "버그는 연결 취약점, 스나프는 파일 낚아채기, 재킹은 명함 뿌리기, 프린팅은 탐색"
[예문] 블루투스로 장비 내부의 파일에 접근하는 공격은 블루스나프이다

트리거(Trigger)
특정 테이블에 삽입, 수정, 삭제 등의 이벤트가 발생하면 DBMS에서 자동 실행되도록 구현된 프로그램
[구성] 이벤트(INSERT / UPDATE / DELETE) → 자동 실행
[의미] 데이터 변경 시 자동으로 후속 작업을 수행하여 무결성 유지와 로그 기록에 활용
[치트키] "방아쇠(Trigger)를 당기면 자동 발사 = 이벤트 발생 시 자동 실행"
[예문] 주문 테이블에 INSERT가 발생하면 재고 테이블을 자동으로 갱신하는 프로그램은 트리거이다
[헷갈리는 단어] 프로시저 - 트리거는 이벤트 시 자동 실행, 프로시저는 호출해서 실행

프로시저(Procedure)
절차형 SQL을 활용하여 특정 기능을 수행할 수 있는 트랜잭션 언어
[구성] 절차형 SQL + 저장 모듈
[의미] 연속적인 SQL 실행, 조건, 반복, 분기를 하나의 모듈로 저장해 호출하여 사용
[치트키] "프로시저 = 절차(Procedure)를 저장해 두고 필요할 때 호출"
[예문] 여러 SQL을 묶어 DB에 저장해 두고 호출해서 수행하는 모듈은 프로시저이다
[헷갈리는 단어] 트리거 - 프로시저는 직접 호출, 트리거는 이벤트로 자동 실행

CASCADE
DROP 명령으로 삭제할 때 참조 무결성에 의해 연관된 다른 테이블의 데이터도 연쇄적으로 삭제하는 옵션
[구성] 기본 테이블 삭제 → 관계 맺은 데이터 연쇄 삭제
[의미] 참조 무결성 제약조건이 설정된 데이터를 삭제할 때 관련 데이터를 함께 제거
[치트키] "캐스케이드 = 폭포처럼 아래로 연쇄 삭제"
[예문] 부모 테이블 데이터를 삭제하면서 참조하는 자식 데이터도 함께 삭제하는 옵션은 CASCADE이다

EAI
미들웨어(Hub)를 이용해 비즈니스 로직을 중심으로 기업 내 애플리케이션을 통합 연계 (암기: 포허메하)
[구성] Point-to-point + Hub&Spoke + Message Bus + Hybrid
[의미] 서로 다른 애플리케이션을 하나의 시스템처럼 연동하기 위한 통합 솔루션
[구분] 방식별 특징
· Point-to-point: 가장 기초적인 1:1 통합 방법
· Hub&Spoke: 어플리케이션 사이에 허브 미들웨어를 두어 데이터를 중앙 집중식으로 전송
· Message Bus: 애플리케이션 사이에 버스 미들웨어를 두어 처리 (주로 ESB)
· Hybrid: Hub&Spoke와 Message Bus의 혼합형
[치트키] "포(점대점) 허(허브) 메(메시지버스) 하(하이브리드) = 포허메하"
[예문] 허브 시스템을 통해 데이터를 중앙 집중식으로 전송하는 EAI 방식은 Hub&Spoke이다
[헷갈리는 단어] ESB - EAI는 점대점·허브 중심의 중앙 집중, ESB는 버스형·SOA 중심

ESB
미들웨어(Bus)를 이용해 서비스 중심으로 관련 시스템을 유기적으로 연계하는 방식
[구성] 버스 미들웨어 + 서비스 중심 + SOA + 느슨한 결합
[의미] 서비스 단위로 시스템을 연결해 유연성과 재사용성을 높임
[구분] EAI와 ESB 차이
· ESB: SOA, 느슨한 결합, 버스형
· EAI: 점대점, 허브&스포크, 중앙 집중
[치트키] "ESB = 서비스(S) 버스(B), 버스를 타고 느슨하게 연결"
[예문] 버스 형태의 미들웨어로 서비스를 느슨하게 결합하는 방식은 ESB이다
[헷갈리는 단어] EAI - ESB는 버스형, EAI는 허브형

뷰(View)
저장 장치 내에 물리적으로 존재하지 않는 가상 테이블
[구성] SELECT 문으로 정의 + 가상 테이블
[의미] 필요한 데이터만 보여 주어 보안과 편의성을 높이지만 삽입·삭제·갱신 연산에 제약이 따름
[치트키] "뷰 = 창문, 보이기만 하는 가짜 테이블"
[예문] 물리적으로 존재하지 않고 SELECT 결과를 보여주는 가상 테이블은 뷰이다

인덱스(Index)
검색을 빠르게 하기 위한 데이터 구조
[구성] 클러스터드 인덱스 + 논클러스터드 인덱스
[의미] 책의 목차처럼 데이터를 빠르게 찾도록 하는 구조로, 조회는 빨라지나 수정·삽입 시 비용이 증가
[구분] 종류별 특징
· 클러스터드 인덱스: 데이터가 이미 정렬되어 조회가 빠르지만 수정·삽입 시 재정렬로 느려지며 테이블당 1개만 생성
· 논클러스터드 인덱스: 속도는 느리지만 한 테이블에 여러 개 생성 가능, 자주 정렬하는 컬럼에 적합
[치트키] "클러스터드는 사전처럼 정렬된 본체 하나, 논클러스터드는 색인 목록 여러 개"
[예문] 한 테이블에 한 개만 만들 수 있고 데이터가 정렬되어 있는 인덱스는 클러스터드 인덱스이다

UI 설계 원칙
사용자 인터페이스를 설계할 때 지켜야 할 4가지 원칙 (암기: 직유학유)
[구성] 직관성 + 유효성 + 학습성 + 유연성
[의미] 사용자가 쉽고 정확하게 목표를 달성할 수 있도록 하는 기준
[구분] 원칙별 의미
· 직관성: 누구나 쉽게 이해하고 사용할 수 있어야 함
· 유효성: 정확하게 사용자의 목표가 달성되어야 함
· 학습성: 누구나 쉽게 배우고 사용할 수 있어야 함
· 유연성: 사용자의 요구사항을 최대한 수용하고 오류를 최소화해야 함
[치트키] "직(직관) 유(유효) 학(학습) 유(유연) = 직유학유"
[예문] 누구나 쉽게 이해하고 사용할 수 있어야 한다는 UI 설계 원칙은 직관성이다

와이어 프레임(Wire Frame)
기획 단계 초기에 제작하며 페이지의 개략적인 레이아웃과 UI 요소 등 뼈대를 설계하는 도구
[구성] 레이아웃 + UI 요소 배치
[의미] 화면 구조를 간단히 그려 설계 방향을 합의하는 UI 설계 도구
[치트키] "와이어 프레임 = 철사로 만든 뼈대 (가장 초기·단순)"
[예문] 기획 초기에 페이지의 개략적인 레이아웃을 뼈대 수준으로 설계하는 도구는 와이어 프레임이다

목업(Mockup)
디자인, 사용 방법 설명, 평가 등을 위해 와이어프레임보다 실제 화면과 유사하게 만든 정적 모형
[구성] 정적 형태 + 실제 화면과 유사
[의미] 실제로 구현되지는 않지만 시각 디자인을 확인하는 데 사용
[치트키] "목업 = 목각 모형처럼 보기엔 진짜인데 눌러도 반응 없음"
[예문] 실제 화면과 유사하게 만들었지만 동작하지 않는 정적 모형은 목업이다
[헷갈리는 단어] 프로토타입 - 목업은 정적, 프로토타입은 인터랙션이 있는 동적 모형

스토리보드(Storyboard)
정책, 프로세스, 콘텐츠 구성, 와이어프레임, 기능 정의, DB 연동 등 서비스 구축을 위한 모든 정보가 담긴 설계 산출물
[구성] 정책 + 프로세스 + 콘텐츠 구성 + 와이어프레임 + 기능 정의 + DB 연동
[의미] 개발자·디자이너가 함께 참고하는 화면 설계 문서
[치트키] "스토리보드 = 서비스 구축의 모든 이야기를 담은 설계서"
[예문] 화면별 기능 정의와 정책, 프로세스까지 담은 UI 설계 산출물은 스토리보드이다

프로토타입(Prototype)
와이어프레임이나 스토리보드 등에 인터랙션을 적용하여 실제 구현한 것처럼 테스트가 가능한 동적인 모형
[구성] 와이어프레임 또는 스토리보드 + 인터랙션
[의미] 사용자 반응과 사용성을 미리 검증하기 위한 동적 모형
[치트키] "프로토타입 = 프로(진짜)처럼 눌러볼 수 있는 시제품"
[예문] 실제처럼 클릭하며 사용성을 테스트할 수 있는 동적 모형은 프로토타입이다
[헷갈리는 단어] 목업 - 프로토타입은 동적, 목업은 정적

UI 시나리오 문서 작성 요건
UI 시나리오 문서가 갖춰야 할 6가지 요건 (암기: 완일이가추수)
[구성] 완전성 + 일관성 + 이해성 + 가독성 + 추적 용이성 + 수정 용이성
[의미] 요구사항을 빠짐없이 명확하게 문서화하기 위한 기준
[구분] 요건별 의미
· 완전성: 누락이 없어야 함
· 일관성: 요구사항에 일관성이 있어야 함
· 이해성: 누구나 이해하기 쉬워야 함
· 가독성: 누구나 읽기 쉬워야 함
· 추적 용이성: 변경 시점을 추적할 수 있어야 함
· 수정 용이성: 요구사항이 쉽게 수정 가능해야 함
[치트키] "완(완전) 일(일관) 이(이해) 가(가독) 추(추적) 수(수정) = 완일이가 추수"
[예문] 변경이 일어난 시점을 추적할 수 있어야 한다는 요건은 추적 용이성이다

애플리케이션 성능 측정 지표
애플리케이션의 성능을 평가하는 4가지 지표 (암기: 처응경자)
[구성] 처리량 + 응답시간 + 경과시간 + 자원 사용률
[의미] 처리 능력과 속도, 자원 소비를 종합적으로 측정
[구분] 지표별 의미
· 처리량(Throughput): 주어진 시간에 처리할 수 있는 트랜잭션 수
· 응답시간(Response Time): 입력이 끝난 후 응답 출력이 시작될 때까지의 시간
· 경과시간(Turnaround Time): 트랜잭션 처리 후 결과 출력이 완료될 때까지 걸리는 시간
· 자원 사용률(Resource Usage): 트랜잭션 처리 동안 CPU, 메모리, 네트워크 사용량
[치트키] "처(처리량) 응(응답시간) 경(경과시간) 자(자원사용률) = 처응경자"
[예문] 입력이 끝난 후 응답 출력이 개시될 때까지의 시간은 응답시간이다

캡슐화(Encapsulation)
데이터와 데이터를 처리하는 행동을 하나로 묶어 정보를 은폐하는 객체지향의 특징
[구성] 데이터 + 메서드 + 접근 제한
[의미] 객체 내부 구현이 바뀌어도 다른 객체에 영향을 주지 않아 독립성과 재사용성을 높임
[구분] 특징
· 객체 제공자와 이용자를 나누어 데이터 직접 접근을 제한, 정보 은폐와 보안 장점
· 클래스 결합도가 낮아져 재사용이 용이
· OSI 계층에서는 각 계층이 상위 계층 정보를 데이터로 취급하고 제어정보를 헤더로 추가하는 과정도 캡슐화라고 함
[치트키] "캡슐 속에 데이터와 행동을 넣고 뚜껑을 닫는다"
[예문] 데이터와 연산을 하나로 묶고 외부 접근을 제한하는 객체지향 특징은 캡슐화이다

UML 구조 다이어그램
UML에서 시스템의 정적인 구조를 표현하는 다이어그램
[구성] 클래스 + 객체 + 패키지 + 컴포넌트 + 배치
[의미] 시스템을 구성하는 요소와 그 관계를 정적으로 나타냄
[구분] 종류별 의미
· 클래스 다이어그램: 클래스의 속성, 함수, 변수, 타입들로 구성
· 객체 다이어그램: 클래스의 인스턴스, 값이 매겨진 독립된 객체 정보를 표현
· 패키지 다이어그램: UML의 모델 요소를 그룹화
· 컴포넌트 다이어그램: 컴포넌트끼리의 구조 관계를 표현
· 배치 다이어그램: 소프트웨어와 하드웨어를 포함한 시스템의 물리적 구조를 표현
[치트키] "구조 = 클·객·패·컴·배, 정적인 뼈대"
[예문] 시스템의 물리적 구조를 하드웨어와 소프트웨어까지 포함해 나타내는 다이어그램은 배치 다이어그램이다

UML 행위 다이어그램
UML에서 시스템의 동적인 행위를 표현하는 다이어그램
[구성] 유스케이스 + 활동 + 상태 + 순서 + 커뮤니케이션
[의미] 시간 흐름에 따른 상호작용과 동작을 나타냄
[구분] 종류별 의미
· 유스케이스: 사용자 관점에서 바라본 시스템
· 활동: 활동들이 순차·병행 방식으로 수행되는 상황
· 상태: 하나의 객체가 다른 객체와의 상호작용에 따라 어떻게 변화하는지
· 순서: 여러 대상 간의 상호작용을 시간 순서에 따라 표현
· 커뮤니케이션: 객체들이 주고받는 메시지와 객체 간 관계까지 표현
[치트키] "행위 = 유·활·상·순·커, 시간 순서는 순서(시퀀스)"
[예문] 여러 대상 간의 상호작용을 시간 순서에 따라 표현하는 다이어그램은 순서 다이어그램이다

클래스 다이어그램 접근제어자
클래스 다이어그램에서 멤버의 접근 범위를 나타내는 기호
[구성] 플러스 + 샵 + 틸드 + 마이너스
[의미] 기호에 따라 접근 가능한 범위가 달라짐
[구분] 기호별 의미
· +(public): 클래스 외부 접근 가능
· #(protected): 동일 패키지, 파생 클래스에서 접근
· ~(default): 동일 패키지, 클래스에서 접근
· -(private): 클래스 내부에서만 접근
[치트키] "플러스는 모두에게 열림, 마이너스는 나만 접근"
[예문] 클래스 내부에서만 접근 가능한 접근제어자 기호는 마이너스(-)이다

UML의 관계
UML에서 사물 간의 관계를 나타내는 6가지 관계
[구성] 연관 + 의존 + 집합(집약·합성) + 일반화 + 실체화
[의미] 클래스와 객체 사이의 연결 방식을 나타내는 표기
[구분] 관계별 의미
· 연관: 2개 이상의 사물이 서로 관련되어 있는 관계, 실선
· 의존: 필요에 의해 짧은 시간 동안만 영향을 주는 관계
· 집약: 전체 객체가 사라져도 부분 객체는 사라지지 않음
· 합성: 전체 객체가 사라지면 부분 객체도 같이 사라짐
· 일반화: 하위 사물에서 상위 사물 쪽으로 속이 빈 화살표
· 실체화: 사물에서 기능 쪽으로 속이 빈 점선 화살표
[치트키] "집약은 팀과 선수(팀이 없어져도 선수 존재), 합성은 책상과 다리(책상이 없어지면 다리도 사라짐)"
[예문] 전체 객체가 사라지면 부분 객체도 함께 사라지는 관계는 합성 관계이다
[헷갈리는 단어] 집약 - 집약은 부분이 독립 존재, 합성은 부분이 전체에 종속

포트 번호
상위 계층의 응용 프로그램으로 데이터를 전달하기 위한 통로
[구성] FTP 20, 21 + TELNET 23 + SMTP 25 + DNS 53 + HTTP 80 + HTTPS 443
[의미] 같은 IP 안에서 서비스를 구분하는 번호
[구분] 주요 포트
· FTP 데이터: 20번
· FTP 제어: 21번
· TELNET: 23번
· SMTP: 25번
· DNS: 53번
· HTTP: 80번
· HTTPS: 443번
· SSH: 22번
[치트키] "FTP 20·21, 텔넷 23, 메일 25, DNS 53, 웹 80, 보안웹 443"
[예문] 웹 서버의 기본 HTTP 포트 번호는 80이다

프로토콜 기본요소
서로 다른 시스템 간 데이터 교환을 원활하게 하기 위한 통신 규약의 기본 요소 (암기: 구의타)
[구성] 구문 + 의미 + 타이밍
[의미] 프로토콜이 규정해야 하는 세 가지 핵심 요소
[구분] 요소별 의미
· 구문: 데이터 형식, 코딩, 신호 레벨 등의 규정
· 의미: 제어 정보로 조정과 에러 처리를 위한 규정
· 타이밍: 속도 조절과 순서 관리 규정
[치트키] "구(구문) 의(의미) 타(타이밍) = 구의타"
[예문] 속도 조절과 순서 관리를 규정하는 프로토콜 요소는 타이밍이다

라우팅 프로토콜
네트워크에서 경로 정보를 교환하여 최적의 경로를 결정하는 프로토콜
[구성] IGP(RIP + OSPF) + EGP(BGP)
[의미] 같은 조직 내부(IGP)와 서로 다른 조직 간(EGP)으로 나뉨
[구분] 프로토콜별 특징
· IGP: 동일 그룹 내부에서 라우팅 정보를 교환
· EGP: 다른 그룹과 라우팅 정보를 교환
· RIP: 최초의 라우팅 프로토콜, 거리 벡터 알고리즘, 최대 15홉
· OSPF: 링크 상태 알고리즘, 변경 정보를 RIP보다 빠르게 업데이트
· BGP: 규모가 큰 네트워크의 상호 연결, 서로 다른 AS를 연결하는 경계 게이트웨이 프로토콜
[치트키] "RIP은 15홉 한계, OSPF는 링크 상태로 빠르게, BGP는 AS 사이를 이어준다"
[예문] 최대 15홉까지만 이동하며 거리 벡터 알고리즘을 사용하는 라우팅 프로토콜은 RIP이다

ARP
IP 네트워크에서 IP 주소를 MAC 주소로 변환하는 프로토콜
[구성] IP 주소 → MAC 주소
[의미] 같은 네트워크 안에서 IP 주소만 알 때 상대의 물리 주소(MAC)를 알아내기 위해 사용
[치트키] "ARP = IP를 주면 MAC을 찾아 주는 안내원 (A→R 방향 정방향)"
[예문] IP 주소로부터 MAC 주소를 알아내는 프로토콜은 ARP이다
[헷갈리는 단어] RARP - ARP는 IP에서 MAC, RARP는 MAC에서 IP

RARP
네트워크 MAC 주소를 IP 주소로 변환하는 프로토콜
[구성] MAC 주소 → IP 주소
[의미] 자신의 MAC 주소는 알지만 IP 주소를 모르는 장치가 IP를 얻기 위해 사용
[치트키] "R(Reverse) = 거꾸로, MAC을 주면 IP를 알려 준다"
[예문] MAC 주소로부터 IP 주소를 알아내는 프로토콜은 RARP이다
[헷갈리는 단어] ARP - RARP는 MAC에서 IP, ARP는 IP에서 MAC

ICMP
IP 패킷 전송 중 에러가 발생하면 에러 발생 메시지를 보내 주는 프로토콜 (인터넷 제어 메시지 프로토콜)
[구성] IP 오류 보고 + 제어 메시지
[의미] 네트워크 상태 진단과 오류 통보에 사용되는 프로토콜 (ping에 사용)
[치트키] "ICMP = 인터넷 제어 메시지, 에러가 나면 알려 준다"
[예문] IP 패킷 전송 중 발생한 오류를 알려 주는 프로토콜은 ICMP이다
[헷갈리는 단어] IGMP - ICMP는 오류·제어 메시지, IGMP는 멀티캐스트 그룹 관리

IGMP
컴퓨터가 멀티캐스트 그룹 구성원을 인접한 라우터에게 알리는 프로토콜 (인터넷 그룹 관리 프로토콜)
[구성] 호스트 → 인접 라우터 / 멀티캐스트 그룹 가입·탈퇴 알림
[의미] 멀티캐스트 통신에서 그룹 구성원을 관리
[치트키] "IGMP의 G = Group, 그룹 가입 신고서"
[예문] 호스트가 멀티캐스트 그룹 가입을 라우터에 알릴 때 사용하는 프로토콜은 IGMP이다
[헷갈리는 단어] ICMP - IGMP는 그룹 관리, ICMP는 오류·제어 메시지

이더넷(Ethernet)
LAN을 위해 개발된 근거리 유선 네트워크 통신 기술로 IEEE 802.3으로 표준화
[구성] 유선 LAN + IEEE 802.3 + CSMA/CD
[의미] 근거리 유선 네트워크에서 가장 널리 쓰이는 통신 방식
[치트키] "이더넷 = 802.3 = 유선 LAN"
[예문] IEEE 802.3으로 정의된 근거리 유선 네트워크 기술은 이더넷이다

CSMA/CD
버스에 연결된 여러 통신 주체가 동시에 통신하며 발생하는 충돌을 막기 위해 충돌을 탐지하는 프로토콜 (유선)
[구성] 반송파 감지 + 다중 접근 + 충돌 탐지(Collision Detection)
[의미] 유선 LAN(이더넷)에서 충돌 발생 시 이를 탐지하고 재전송하는 방식
[치트키] "CD = Detection(탐지), 유선은 부딪힌 걸 알아낸다"
[예문] 이더넷에서 충돌을 탐지하는 접근 제어 방식은 CSMA/CD이다
[헷갈리는 단어] CSMA/CA - CD는 충돌 탐지(유선), CA는 충돌 회피(무선)

CSMA/CA
네트워크가 빌 때까지 기다렸다가 정해진 시간 후 데이터를 전송해 충돌을 회피하는 프로토콜 (무선)
[구성] 반송파 감지 + 다중 접근 + 충돌 회피(Collision Avoidance)
[의미] 무선 LAN에서 충돌 탐지가 어려워 미리 충돌을 피하도록 하는 방식
[치트키] "CA = Avoidance(회피), 무선은 부딪히기 전에 피한다"
[예문] 무선 LAN(IEEE 802.11)에서 충돌을 회피하는 방식은 CSMA/CA이다
[헷갈리는 단어] CSMA/CD - CA는 회피(무선), CD는 탐지(유선)

IPv4
32bit 주소 체계를 갖는 네트워크 계층의 프로토콜
[구성] 32bit + 8bit씩 4부분
[의미] 현재 널리 쓰이지만 주소 고갈 문제가 있음
[치트키] "IPv4 = 32bit (4×8)"
[예문] 32bit 주소 체계를 갖는 IP 버전은 IPv4이다
[헷갈리는 단어] IPv6 - IPv4는 32bit, IPv6는 128bit

IPv6
128bit 주소 체계를 갖는 차세대 인터넷 프로토콜
[구성] 128bit + 16bit씩 8부분
[의미] 주소 고갈 문제를 해결하고 헤더 단순화, 보안 강화(IPSec), QoS 지원
[치트키] "IPv6 = 128bit (16×8)"
[예문] 128bit 주소 체계를 갖는 인터넷 프로토콜은 IPv6이다
[헷갈리는 단어] IPv4 - IPv6는 128bit, IPv4는 32bit

IPv4/IPv6 전환 기술
IPv4에서 IPv6로 넘어가는 과도기에 두 버전을 함께 운용하기 위한 3가지 기술
[구성] 듀얼 스택 + 터널링 + 주소 변환
[의미] 두 프로토콜이 공존하는 환경에서 통신을 가능하게 하는 방법
[구분] 기술별 의미
· 듀얼 스택: IPv4와 IPv6를 동시에 지원
· 터널링: IPv4 패킷으로 캡슐화하여 전송, 두 IPv6 네트워크 간에 터널을 이용
· 주소 변환: IPv4와 IPv6 간에 주소를 변환해 두 버전을 연동
[치트키] "둘 다 쓰면 듀얼, 포장해서 지나가면 터널, 번역하면 주소 변환"
[예문] IPv4와 IPv6를 동시에 지원하는 전환 기술은 듀얼 스택이다

IPv4/IPv6 전송 방식
데이터를 전송하는 대상의 범위에 따른 4가지 방식
[구성] 유니캐스트 + 멀티캐스트 + 브로드캐스트 + 애니캐스트
[의미] 전송 대상이 1:1, 1:다, 1:전체, 가장 가까운 노드인지로 구분
[구분] 방식별 의미
· 유니캐스트: 고유 주소로 식별된 하나의 목적지와 1:1 통신 (IPv4, IPv6 사용)
· 멀티캐스트: 한 번의 송신으로 여러 컴퓨터에 동시 전송, 1:다 (IPv4, IPv6 사용)
· 브로드캐스트: 네트워크에 연결된 모든 호스트에 전송, 1:전체 (IPv4만 사용)
· 애니캐스트: 브로드캐스트 단점을 보완해 가장 가까운 노드와 통신 (IPv6만 사용)
[치트키] "브로드캐스트는 IPv4만, 애니캐스트는 IPv6만, 유니·멀티는 둘 다"
[예문] IPv6에서 브로드캐스트를 대체하여 가장 가까운 노드와 통신하는 방식은 애니캐스트이다

소켓(Socket)
컴퓨터 네트워크를 경유하는 프로세스 간 통신의 종착점
[구성] 응용 계층 프로그램 → 소켓 → 전송 계층 통신망
[의미] 응용 프로그램이 데이터를 송수신하기 위해 소켓을 거쳐 전송 계층으로 데이터를 전달
[치트키] "소켓 = 콘센트, 응용 프로그램이 통신망에 꽂는 구멍"
[예문] 응용 프로그램이 네트워크로 데이터를 주고받는 통신의 종착점은 소켓이다

NAT(Network Address Translation)
한정된 공인 IP를 여러 개의 내부 사설 IP로 변환하기 위해 사용하는 기술
[구성] 사설 IP ↔ 공인 IP 변환
[의미] 공인 IP 부족 문제를 완화하고 내부 네트워크를 보호
[치트키] "NAT = 사설 IP를 공인 IP 옷으로 갈아입힌다"
[예문] 공인 IP 하나로 여러 사설 IP 장비가 인터넷을 쓰게 하는 기술은 NAT이다

IPC(Inter-Process Communication)
실행 중인 프로세스 간 통신을 가능하게 하는 기술
[구성] 파이프 + 메시지 큐 + 공유 메모리 + 세마포어
[의미] 프로세스 사이에서 데이터를 주고받고 동기화하기 위한 방법
[치트키] "IPC 4총사 = 파이프, 큐, 공유 메모리, 세마포어"
[예문] 파이프, 메시지 큐, 공유 메모리 등이 속하는 프로세스 간 통신 기술은 IPC이다

Ad-Hoc 네트워크
특정 기지국에 의존하지 않고 무선 이동 단말로만 구성된 분산형 무선 통신 네트워크
[구성] 무선 단말 + 분산형 + 기지국 없음
[의미] 긴급 구조, 긴급 회의 등 인프라가 없는 환경에서 임시로 구성하는 네트워크
[치트키] "애드혹 = 그때그때(Ad hoc) 즉석에서 만드는 무선망"
[예문] 기지국 없이 단말끼리 구성하는 무선 네트워크는 Ad-Hoc 네트워크이다

TCP
신뢰성이 보장되는 연결 지향형 전송 계층 프로토콜
[구성] 연결 지향 + 흐름 제어 + 에러 제어 + 혼잡 제어 + 패킷 다중화
[의미] IP와 함께 TCP/IP로 사용되며 데이터의 정확한 전달을 보장
[치트키] "TCP = 믿을 수 있고(신뢰) 연결부터 하고 보낸다"
[예문] 흐름 제어와 혼잡 제어를 제공하는 연결 지향형 프로토콜은 TCP이다
[헷갈리는 단어] UDP - TCP는 연결형·신뢰성, UDP는 비연결형·고속

UDP
신뢰성은 없지만 데이터그램 단위로 고속 전송이 가능한 비연결 지향형 전송 계층 프로토콜
[구성] 비연결 지향 + 데이터그램 + 고속
[의미] 스트리밍·DNS처럼 속도가 중요한 서비스에 사용
[치트키] "UDP = 연결 없이 휙 던지는 빠른 우편"
[예문] 연결 설정 없이 데이터그램을 빠르게 전송하는 프로토콜은 UDP이다
[헷갈리는 단어] TCP - UDP는 비연결형·고속, TCP는 연결형·신뢰성

네트워크 연결 장비
OSI 계층에 따라 구분되는 네트워크 연결 장비
[구성] 1계층: 허브, 리피터 → 2계층: 브리지, 스위치 → 3계층: 라우터
[의미] 계층별로 처리하는 단위(비트, 프레임, 패킷)와 기능이 다름
[구분] 장비별 의미
· 허브: 1계층, 여러 컴퓨터를 연결하고 수신 정보를 여러 대로 송신
· 리피터: 1계층, 디지털 신호를 증폭
· 브리지: 2계층, 두 개의 LAN을 서로 연결
· 라우터: 3계층, LAN과 LAN 또는 LAN과 WAN을 연결하고 최적 경로를 판단
[치트키] "1층은 허브·리피터, 2층은 브리지·스위치, 3층은 라우터"
[예문] 최적의 경로를 판단하여 LAN과 WAN을 연결하는 3계층 장비는 라우터이다

SSH
원격 호스트에 접속하기 위해 사용되는 보안 프로토콜로 22번 포트를 사용
[구성] 원격 접속 + 암호화 통신 + 22번 포트
[의미] 텔넷의 평문 전송 단점을 보완한 안전한 원격 접속 방식
[치트키] "SSH = 22번 포트의 안전한 원격 접속"
[예문] 22번 포트를 사용하는 보안 원격 접속 프로토콜은 SSH이다

VPN
공중 네트워크에 암호화 기술을 이용해 자신의 전용 회선을 사용하는 것처럼 해 주는 보안 솔루션
[구성] 공중망 + 터널링 + 암호화
[의미] 저렴하게 안전한 사설망 통신을 구현
[치트키] "VPN = 가상(Virtual) 사설(Private) 망, 공중망 속의 전용 터널"
[예문] 인터넷에서 암호화된 가상의 전용 회선을 제공하는 보안 솔루션은 VPN이다

LAN 802.xx 시리즈 규약
IEEE 802 위원회에서 정한 LAN 표준 규약
[구성] 802.3 + 802.4 + 802.5 + 802.11 + 802.15
[의미] 번호에 따라 접속 방식과 매체가 다름
[구분] 번호별 의미
· 802.3: CSMA/CD (유선)
· 802.4: 토큰 버스
· 802.5: 토큰 링
· 802.11: CSMA/CA (무선)
· 802.15: 블루투스
[치트키] "3 유선 CD, 4 토큰 버스, 5 토큰 링, 11 무선 CA, 15 블루투스"
[예문] 무선 LAN의 표준 규약은 IEEE 802.11이다

테스트 레벨
소프트웨어 테스트를 단계적으로 수행하는 V 모형의 4단계 (암기: 단통시인)
[구성] 단위 → 통합 → 시스템 → 인수
[의미] 작은 단위에서 시작해 전체로 확장하며 검증하는 구조
[구분] 단계별 의미
· 단위 테스트: 요구사항에 대한 단위 모듈, 서브루틴 테스트
· 통합 테스트: 단위 테스트를 통과한 모듈 사이의 인터페이스와 상호작용 검증
· 시스템 테스트: 전체 시스템에서 기능이 정상 동작하는지 검증
· 인수 테스트: 요구사항 만족 여부를 확인
[치트키] "단(단위) 통(통합) 시(시스템) 인(인수) = 단통시인"
[예문] 모듈 간 인터페이스를 검증하는 테스트 레벨은 통합 테스트이다

테스트 오라클
실제 결과와 비교할 기대 결과를 제공하는 기법 (암기: 참샘휴일)
[구성] 참 오라클 + 샘플링 오라클 + 휴리스틱 오라클 + 일관성 오라클
[의미] 테스트 결과의 정답 여부를 판단하는 기준 제공
[구분] 종류별 의미
· 참 오라클: 모든 입력값에 대해 기대하는 결과를 생성
· 샘플링 오라클: 일부 특정 입력값에 대해 기대 결과를 생성
· 휴리스틱(추정) 오라클: 특정 입력값에 대해 올바른 결과를 제공하고 나머지는 휴리스틱으로 처리
· 일관성 오라클: 수행 전과 수행 후의 결과값이 동일한지 확인
[치트키] "참(참) 샘(샘플링) 휴(휴리스틱) 일(일관성) = 참샘휴일"
[예문] 수행 전후의 결과값이 동일한지 확인하는 오라클은 일관성 오라클이다

기초 경로 검사(Basis Path Testing)
McCabe가 제안한 대표적인 화이트박스 테스트 기법
[구성] 제어 흐름 그래프 → 순환 복잡도 계산 → 독립 경로 도출
[의미] 모든 독립적인 경로를 한 번씩 실행하도록 테스트 케이스를 설계
[구분] 순환 복잡도 계산식
· V(G) = E - N + 2 (E: 간선 수, N: 노드 수)
· 폐구간(영역)의 개수에 1을 더해도 구할 수 있음
[치트키] "엣지에서 노드 빼고 2를 더한다 = E - N + 2"
[예문] 간선이 9개, 노드가 7개인 그래프의 순환 복잡도는 9 - 7 + 2 = 4이다

블랙박스 테스트 유형
내부 구조를 보지 않고 입출력 명세를 기준으로 수행하는 기능 테스트
[구성] 동등 분할 + 원인-효과 그래프 + 비교 검사 + 오류 예측 + 경계값 분석
[의미] 요구사항 명세를 기반으로 입력과 출력을 검증
[구분] 기법별 의미
· 동등 분할: 입력 자료를 동등한 그룹으로 나누어 대표값으로 테스트
· 원인-효과 그래프: 입력 데이터 간 관계와 출력에 영향을 미치는 상황을 분석해 효용성이 높은 케이스 선정
· 비교 검사: 동일한 테스트를 하여 동일한 결과가 출력되는지 확인
· 오류 예측: 과거 경험이나 테스터의 감각으로 테스트
· 경계값 분석: 입력 조건의 경계값을 테스트 케이스로 선정
· 페어 와이즈: 테스트 데이터의 최소한의 조합으로 적은 테스트 세트를 구성
[치트키] "동원인 비오면 경계한다 = 동등분할, 원인효과, 비교, 오류예측, 경계값"
[예문] 입력 조건의 최솟값과 최댓값 부근을 집중 테스트하는 기법은 경계값 분석이다

경계값 분석(Boundary Value Analysis)
입력 조건의 경계값을 테스트 케이스로 선정하는 블랙박스 테스트 기법
[구성] 최솟값 ±1 + 최댓값 ±1 + 경계값 자체
[의미] 오류가 경계 부근에서 자주 발생한다는 점에 착안
[치트키] "경계선 바로 앞뒤(±1)를 찔러 본다"
[예문] 입력 범위가 1~100일 때 0, 1, 100, 101을 테스트하는 기법은 경계값 분석이다
[헷갈리는 단어] 동등 분할 - 경계값은 경계 부근, 동등 분할은 그룹 대표값

테스트 드라이버(Driver)
상향식 테스트에서 테스트 대상 하위 모듈을 호출하고 파라미터를 전달하며 결과를 도출하는 도구
[구성] 가짜 상위 모듈 → 하위 모듈 호출
[의미] 아직 개발되지 않은 상위 모듈의 역할을 대신 수행
[치트키] "드라이버 = 운전자, 아래 모듈을 몰고 가는 가짜 상위 모듈"
[예문] 상향식 통합 테스트에서 상위 모듈을 대신하는 도구는 드라이버이다
[헷갈리는 단어] 스텁 - 드라이버는 상향식, 스텁은 하향식

스텁(Stub)
하향식 테스트에서 제어 모듈이 호출하는 타 모듈의 기능을 단순히 수행하는 도구
[구성] 가짜 하위 모듈 → 상위 모듈에서 호출
[의미] 아직 개발되지 않은 하위 모듈을 대신해 특정 값을 반환하거나 메시지를 출력
[치트키] "스텁 = 그루터기, 위에서 부르면 대충 대답하는 가짜 하위 모듈"
[예문] 하향식 통합 테스트에서 하위 모듈을 대신하는 도구는 스텁이다
[헷갈리는 단어] 드라이버 - 스텁은 하향식, 드라이버는 상향식

테스트 케이스
입력값, 실행조건, 기대 결과로 구성된 테스트 항목의 명세서
[구성] 입력값 + 실행 조건 + 기대 결과
[의미] 테스트를 재현 가능하게 하는 개별 항목 명세
[치트키] "넣고(입력) 조건대로 돌리고(실행조건) 이래야 한다(기대 결과)"
[예문] 입력값, 실행조건, 기대 결과로 구성된 명세서는 테스트 케이스이다
[헷갈리는 단어] 테스트 시나리오 - 케이스는 개별 항목, 시나리오는 케이스들의 집합

테스트 시나리오
테스트 수행을 위한 테스트 케이스들의 집합으로 케이스의 동작 순서를 기술한 문서
[구성] 테스트 케이스 여러 개 + 수행 순서
[의미] 업무 흐름 단위로 테스트 절차를 정리
[치트키] "시나리오 = 케이스들을 이어 붙인 이야기"
[예문] 여러 테스트 케이스의 동작 순서를 기술한 문서는 테스트 시나리오이다
[헷갈리는 단어] 테스트 케이스 - 시나리오는 케이스의 집합

테스트 커버리지
테스트를 얼마나 수행했는지 측정하는 기준
[구성] 명세 기반 + 구조 기반 + 경험 기반 / 기능 + 라인 + 코드 커버리지
[의미] 테스트의 충분성을 수치로 평가
[구분] 종류별 의미
· 명세 기반 테스트: 주어진 명세를 빠짐없이 테스트 케이스로 구현했는지 확인
· 구조 기반 테스트: 내부 논리 흐름에 따라 테스트 케이스를 작성하고 확인
· 경험 기반 테스트: 유사 소프트웨어와 기술 평가에서 테스터의 경험을 기반으로 수행
· 기능 기반 커버리지: 전체 기능을 모수로 수행된 기능 수를 측정
· 라인 커버리지: 전체 소스 코드 라인 수 대비 수행된 라인 수를 측정
· 코드 커버리지: 구문, 조건, 결정 등 코드 구조 자체가 얼마나 테스트되었는지 측정
[치트키] "무엇을 모수로 삼느냐 = 기능(기능), 줄(라인), 구조(코드)"
[예문] 전체 소스 코드의 라인 수 대비 수행된 라인 수를 측정하는 것은 라인 커버리지이다

코드 커버리지 구조
소스 코드의 구조를 기준으로 테스트 충분성을 측정하는 커버리지 종류 (암기: 변조조결구다경)
[구성] 변경 조건/결정 → 조건/결정 → 조건 → 결정 → 구문 → 다중 조건 → 경로
[의미] 어디까지 True와 False를 확인했는지에 따라 구분
[구분] 종류별 의미
· 변경 조건/결정 커버리지: 각 조건식이 결정 결과에 독립적으로 영향을 주도록 True/False를 확인
· 조건/결정 커버리지: 결정 포인트와 개별 조건식 둘 다 True/False를 가져야 함
· 조건 커버리지: 개별 조건식만 각각 True/False를 만족
· 결정 커버리지: 결정 포인트만 각각 True/False를 만족
· 구문 커버리지: 코드 내 구문이 한 번 이상 수행
· 다중 조건 커버리지: 결정 포인트 내 모든 개별 조건식의 가능한 조합을 100% 보장
· 경로 커버리지: 가능한 모든 경로를 수행
[치트키] "변조도 결국 다 걸린다 = 변조조결구다경"
[예문] 모든 조건식의 가능한 조합을 보장하는 커버리지는 다중 조건 커버리지이다

회복 테스트(Recovery)
시스템에 고의로 실패를 유도하고 정상적으로 복귀하는지 확인하는 테스트
[구성] 고의 장애 발생 → 복구 과정 → 정상 복귀 여부 확인
[의미] 장애 상황에서의 복구 능력 검증
[치트키] "회복 = 일부러 쓰러뜨려 놓고 일어나는지 본다"
[예문] 시스템에 고의로 실패를 유도해 정상 복귀 여부를 확인하는 테스트는 회복 테스트이다

스트레스 테스트(Stress)
임계점 이상의 부하를 계속 가해 비정상적인 상황에서의 처리를 확인하는 테스트
[구성] 임계점 초과 부하 → 시스템 한계와 장애 동작 관찰
[의미] 극한 상황에서 시스템이 어떻게 반응하는지 검증
[치트키] "스트레스 = 한계 이상으로 몰아붙인다"
[예문] 임계점 이상의 부하를 가해 비정상적인 상황에서의 동작을 보는 테스트는 스트레스 테스트이다
[헷갈리는 단어] 부하 테스트 - 스트레스는 임계점 이상, 부하는 임계점을 찾는 것

회귀 테스트(Regression)
오류 제거와 수정에 의해 새로 유입된 오류가 없는지 확인하는 일종의 반복 테스트
[구성] 수정 → 기존 테스트 재수행 → 신규 결함 여부 확인
[의미] 변경이 기존 기능에 악영향을 주지 않았음을 확인
[치트키] "회귀 = 고치고 나서 다시 돌아가 확인"
[예문] 코드 수정 후 이전에 통과한 기능이 여전히 동작하는지 재검증하는 테스트는 회귀 테스트이다

부하·내구성·스파이크 테스트
성능 관련 테스트 중 부하의 크기와 지속 시간, 순간 증가를 다루는 3가지 테스트
[구성] 부하(Load) + 내구성(Endurance) + 스파이크(Spike)
[의미] 시스템의 한계와 안정성을 다양한 부하 패턴으로 확인
[구분] 종류별 의미
· 부하: 시스템에 부하를 계속 증가시키며 임계점을 찾음
· 내구성: 오랜 시간 동안 시스템에 높은 부하를 가해 테스트
· 스파이크: 짧은 시간에 사용자가 몰릴 때 시스템의 반응을 측정
[치트키] "부하는 점점 올리고, 내구성은 오래 버티고, 스파이크는 순간 폭주"
[예문] 짧은 시간에 사용자가 몰릴 때의 반응을 측정하는 테스트는 스파이크 테스트이다

정적 분석 도구
코드를 실행하지 않고 소스 코드의 코딩 표준, 스타일, 복잡도, 남은 결함을 발견하는 도구
[구성] 소스 코드 분석 (비실행)
[의미] 코드 작성 단계에서 결함을 조기에 발견
[구분] 대표 도구
· PMD, SonarQube, Cppcheck, Checkstyle 등
[치트키] "정적 = 실행 없이 눈으로 코드만 검사"
[예문] 코드를 실행하지 않고 코딩 표준 위반과 복잡도를 검사하는 도구는 정적 분석 도구이다
[헷갈리는 단어] 동적 분석 도구 - 정적은 실행하지 않음, 동적은 실행하며 분석

동적 분석 도구
코드를 실행시켜 분석하고 디버깅으로 파일을 자세히 살펴보며 코드 흐름과 메모리 상태를 확인하는 도구
[구성] 프로그램 실행 + 실행 중 행위 분석
[의미] 실행 중에만 드러나는 결함과 메모리 문제를 발견
[치트키] "동적 = 돌려 보면서 관찰"
[예문] 프로그램을 실행하면서 코드 흐름과 메모리 상태를 확인하는 도구는 동적 분석 도구이다
[헷갈리는 단어] 정적 분석 도구 - 동적은 실행하며, 정적은 실행하지 않고 분석

허니팟(Honeypot)
침입자를 속여 실제로 공격당하는 것처럼 보여줌으로써 크래커를 추적하고 공격 기법 정보를 수집하는 시스템
[구성] 가짜 시스템 + 공격 유인 + 정보 수집
[의미] 실제 시스템을 보호하면서 공격자의 행위를 분석
[치트키] "허니팟 = 꿀단지, 공격자를 꿀로 유인"
[예문] 공격자를 유인해 공격 기법 정보를 수집하는 가짜 시스템은 허니팟이다

세마포어(Semaphore)
상호배제를 해결하기 위한 기법으로, 멀티프로그래밍 환경에서 공유 자원에 대한 접근을 제한하는 기법
[구성] P 연산 + V 연산
[의미] 여러 프로세스가 공유 자원에 동시에 접근하지 못하게 제어
[치트키] "세마포어 = 신호등, P는 진입 대기, V는 해제"
[예문] P와 V 연산으로 공유 자원 접근을 제한하는 상호배제 기법은 세마포어이다

헝가리안 표기법
변수 및 함수의 인자 이름 앞에 데이터 타입을 명시하는 코딩 규칙
[구성] 데이터 타입 접두어 + 변수 이름
[의미] 변수 이름만 보고 자료형을 알 수 있도록 하는 표기 방식
[치트키] "헝가리안 = 타입을 이름 앞에 붙여 국적(타입)을 표시"
[예문] 변수 이름 앞에 자료형을 붙이는 표기법은 헝가리안 표기법이다

낙타 표기법(Camel Case)
여러 단어를 결합할 때 첫 단어는 소문자로 시작하고 이후 단어의 첫 글자를 대문자로 쓰는 표기법
[구성] 첫 단어 소문자 + 이후 단어 첫 글자 대문자
[의미] 대문자가 낙타의 혹처럼 보이는 데서 유래
[치트키] "낙타 혹 = 중간 단어 첫 글자만 불쑥 대문자"
[예문] userName처럼 단어 중간을 대문자로 연결하는 표기법은 낙타 표기법이다

LOC(Lines of Code) 기법
소프트웨어 규모를 코드 라인 수로 추정하는 상향식 비용 산정 방법
[구성] 낙관치 + 중간치 + 비관치를 1:4:1 가중치로 평균
[의미] 코드 라인 수의 낙관치, 중간치, 비관치를 측정하여 가중 평균으로 예측치를 구함
[구분] 관련 용어
· MM(Man Month): 한 사람이 한 달 동안 할 수 있는 일의 양
[치트키] "낙관 1, 중간 4, 비관 1 = 1:4:1"
[예문] 낙관치, 중간치, 비관치를 1:4:1로 가중하여 코드 라인 수를 추정하는 기법은 LOC 기법이다

COCOMO
프로그램 규모에 따라 조직형, 반분리형, 임베디드형으로 구분해 비용을 산정하는 수학적 방식
[구성] 조직형 + 반분리형 + 임베디드형
[의미] 소프트웨어 개발 규모(KDSI)에 기반해 노력과 기간을 예측
[구분] 유형별 규모
· 조직형: 5만 라인 이하
· 반분리형: 30만 라인 이하
· 임베디드형: 30만 라인 이상
[치트키] "5만 이하 조직, 30만 이하 반분리, 30만 이상 임베디드"
[예문] 소프트웨어를 조직형, 반분리형, 임베디드형으로 나누어 비용을 산정하는 모델은 COCOMO이다

폭포수 모형
계획부터 유지보수까지 단계를 순차적으로 진행하는 소프트웨어 생명주기 모형
[구성] 6단계: 계획 → 요구사항 분석 → 설계 → 구현 → 테스트 → 유지 보수
[의미] 앞 단계가 끝나야 다음 단계로 넘어가는 선형 순차 방식
[치트키] "폭포는 위에서 아래로만 흐른다, 되돌릴 수 없다"
[예문] 계획, 요구사항 분석, 설계, 구현, 테스트, 유지 보수의 순서로 진행하는 모형은 폭포수 모형이다

나선형 모형
계획 수립, 위험 분석, 공학적 개발, 고객 평가를 반복하며 점진적으로 개발하는 모형
[구성] 4단계 반복: 계획 수립 → 위험 분석 → 공학적 개발 → 고객 평가
[의미] 위험 분석이 핵심이며 프로토타입을 반복해 완성도를 높임
[치트키] "나선은 빙글빙글 돌며 위험을 먼저 따진다"
[예문] 반복 과정에서 위험 분석 단계를 포함하는 모형은 나선형 모형이다

형상 관리 절차
소프트웨어 개발 중 발생하는 모든 변경 사항을 관리하는 절차 (암기: 식통감기)
[구성] 4단계: 형상 식별 → 형상 통제 → 형상 감사 → 형상 기록
[의미] 산출물의 변경을 체계적으로 추적하고 통제
[구분] 단계별 의미
· 형상 식별: 관리 대상 항목을 선정하고 식별
· 형상 통제: 변경 요청이 있을 때 변경 여부와 변경 활동을 통제 (버전 관리)
· 형상 감사: 변경이 요구사항에 맞게 반영되었는지 검토
· 형상 기록: 변경 이력과 상태를 보고
· 베이스라인: 변화를 통제하는 시점의 기준
[치트키] "식(식별) 통(통제) 감(감사) 기(기록) = 식통감기"
[예문] 변경 요청이 있을 때 변경 여부와 활동을 통제하는 형상 관리 단계는 형상 통제이다

ODBC
데이터베이스에 접근하기 위한 표준 규격
[구성] 응용 프로그램 + ODBC 드라이버 + DBMS
[의미] DBMS 종류와 관계없이 같은 방식으로 데이터베이스에 접근하도록 하는 표준 인터페이스
[치트키] "ODBC = 어떤 DB든 통하는 공용 접속 규격"
[예문] DBMS 종류에 상관없이 표준 방식으로 DB에 접근하게 하는 규격은 ODBC이다
[헷갈리는 단어] JDBC - ODBC는 DB 접근 표준 규격, JDBC는 자바에서 DB에 접근하는 API

ORM
객체와 관계형 데이터베이스의 데이터를 자동으로 매핑(연결)해 주는 기술
[구성] 객체 + 관계형 DB 테이블 + 자동 매핑
[의미] SQL을 직접 작성하지 않고 객체 조작으로 DB를 다룰 수 있게 함
[치트키] "ORM = 객체(O)와 관계(R)를 이어 주는 매퍼(M)"
[예문] 객체와 관계형 데이터베이스의 데이터를 자동으로 매핑하는 기술은 ORM이다

직접 연계 방식 기술
송신 시스템과 수신 시스템 사이에서 중간 매개 없이 직접 데이터를 연계하는 주요 기술
[구성] DB Link + DB Connect + API/Open API + JDBC + Hyper Link
[의미] 시스템 간 데이터를 직접 연결해 주고받는 방식
[구분] 기술별 의미
· DB Link: 수신 시스템에서 DB 링크를 생성하고 송신 시스템에서 DB 링크를 직접 참조
· DB Connect: WAS에서 DB로 연결하는 DB 커넥션 풀을 생성하고 연계 프로그램이 커넥션 풀 이름으로 연결
· API/Open API: DB에서 데이터를 읽어서 제공하는 애플리케이션 프로그래밍 인터페이스
· JDBC: 수신 시스템 프로그램에서 JDBC 드라이버를 이용해 DB와 연결하는 자바 API
· Hyper Link: 현재 페이지에서 다른 부분이나 페이지로 이동
[치트키] "링크는 직접 링크, 커넥트는 풀, API는 읽어 주기, JDBC는 자바"
[예문] WAS에서 DB 커넥션 풀을 생성하여 DB에 연결하는 연계 방식은 DB Connect이다

ERD(개체 관계도)
개체와 개체 간의 관계 등을 약속된 기호로 표현하는 기법
[구성] 사각형(개체) + 타원(속성) + 마름모(관계) + 선(연결)
[의미] P. Chen 박사가 최초로 제안한 개념적 설계의 표현 기법
[구분] 기호별 의미
· 사각형: 개체를 나타냄 (릴레이션으로 표현)
· 타원: 속성을 나타냄
· 마름모: 개체 집합 간의 관계를 나타냄 (외래키로 표현)
· 선: 속성과 개체 집합, 개체 집합과 관계를 연결
[치트키] "사각형은 개체, 타원은 속성, 마름모는 관계"
[예문] 개체를 사각형, 속성을 타원, 관계를 마름모로 나타내는 다이어그램은 ERD이다

논리적 데이터 모델
데이터를 논리적 구조로 표현하는 데이터 모델의 종류 (암기: 관계네)
[구성] 관계 데이터 모델 + 계층 데이터 모델 + 네트워크 데이터 모델
[의미] 데이터 간 연결 방식에 따라 구분
[구분] 모델별 의미
· 관계 데이터 모델: 1:1, 1:N, N:M을 자유롭게 표현할 수 있는 2차원 표 모델
· 계층 데이터 모델: 1:N 관계만 허용하고 트리 형태로 상하관계가 존재
· 네트워크 데이터 모델: N:M 관계만 허용하고 그래프 형태로 구성
[치트키] "관(관계=표) 계(계층=트리) 네(네트워크=그래프) = 관계네"
[예문] 트리 구조로 상하관계가 있고 1:N만 허용하는 모델은 계층 데이터 모델이다

데이터베이스 설계 순서
데이터베이스를 설계하는 5단계 절차 (암기: 개논물)
[구성] 5단계: 요구사항 분석 → 개념적 설계 → 논리적 설계 → 물리적 설계 → 구현
[의미] 요구사항에서 시작해 점차 구체적인 저장 구조로 설계
[구분] 단계별 의미
· 개념적 설계: ERD 다이어그램을 만드는 단계
· 논리적 설계: 정규화(이상현상 제거), 트랜잭션 인터페이스 설계
· 물리적 설계: 성능을 위해 인덱스, 파티션, 클러스터링, 뷰, 프로시저 설계, 반정규화
[치트키] "개(개념) 논(논리) 물(물리) = 개논물"
[예문] 정규화 작업이 이루어지는 데이터베이스 설계 단계는 논리적 설계이다

데이터베이스(DB)의 정의
특정 조직의 여러 응용 시스템이 공동으로 사용하는 통합된 데이터의 집합 (암기: 공장통운)
[구성] 공유 데이터 + 저장 데이터 + 통합 데이터 + 운영 데이터
[의미] 중복을 최소화하면서 다양한 사용자의 정보 요구를 충족시키는 상호 관련된 데이터의 통합된 집합체
[구분] 데이터별 의미
· 공유 데이터: 여러 응용 프로그램이 공통으로 사용하는 데이터
· 저장 데이터: 컴퓨터가 접근 가능한 저장 매체에 저장된 데이터
· 통합 데이터: 검색 효율성을 위해 중복이 최소화된 데이터의 모임
· 운영 데이터: 조직의 목적을 위해 존재 가치가 확실하고 반드시 필요한 데이터
[치트키] "공(공유) 장(저장) 통(통합) 운(운영) = 공장통운"
[예문] 검색 효율성을 위해 중복이 최소화된 데이터의 모임은 통합 데이터이다

데이터 모델 구성 요소
데이터 모델을 구성하는 세 가지 요소 (암기: 연구제)
[구성] 연산 + 구조 + 제약조건
[의미] 데이터를 어떻게 조작하고, 어떤 구조로 저장하며, 어떤 규칙을 지킬지 정의
[구분] 요소별 의미
· 연산: 데이터베이스에 저장된 실제 데이터를 처리하는 작업에 대한 명세
· 구조: 논리적으로 표현된 개체 타입들 간의 관계로 데이터 구조 및 정적 성질을 표현
· 제약조건: 데이터베이스에 저장될 수 있는 실제 데이터의 논리적 제약
[치트키] "연(연산) 구(구조) 제(제약조건) = 연구제"
[예문] 데이터베이스에 저장될 수 있는 데이터의 논리적 제약은 제약조건이다

데이터 모델의 품질 기준
데이터 모델이 잘 만들어졌는지 평가하는 6가지 기준 (암기: 정준일최완활)
[구성] 정확성 + 준거성 + 일관성 + 최신성 + 완전성 + 활용성
[의미] 데이터 모델의 표현, 규칙 준수, 최신 반영 정도를 평가
[구분] 기준별 의미
· 정확성: 표기법에 따라 정확하게 표현되고 요구사항이 정확히 반영
· 준거성: 제반 준수 요건들이 누락 없이 정확하게 준수
· 일관성: 공통 데이터 요소가 전사 수준에서 한 번만 정의되고 참조·활용되며 일관성을 유지
· 최신성: 현행 시스템의 최신 상태를 반영하고 이슈 사항이 지체 없이 반영
· 완전성: 구성 요소 정의와 요구사항 반영에서 누락을 최소화
· 활용성: 업무 변화 시 설계 변경이 최소화되도록 유연하게 설계
[치트키] "정준일 최신 노래 내면서 완전 활발하게 활동중 = 정준일최완활"
[예문] 업무 변화 시 설계 변경이 최소화되도록 유연하게 설계되었음을 의미하는 기준은 활용성이다

DBA
데이터베이스 시스템과 관련된 모든 자원에 대해 기획과 통제를 수행하는 사람 또는 집단
[구성] 데이터베이스 관리 책임자
[의미] 데이터베이스 시스템의 관리와 운영에 책임을 지는 사람
[치트키] "DBA = Database Administrator, DB 관리인"
[예문] 데이터베이스 시스템의 관리와 운영에 대한 책임을 지는 사람은 DBA이다

DBMS
응용 프로그램과 데이터 사이의 중재자로서 모든 응용 프로그램이 데이터베이스에 접근해 데이터를 공유하도록 관리하는 시스템
[구성] 응용 프로그램 ↔ DBMS ↔ 데이터베이스
[의미] 데이터베이스와 사용자를 연결해 주는 관리 소프트웨어
[치트키] "DBMS = DB와 사용자 사이의 관리소 직원"
[예문] 데이터베이스와 사용자를 연결하여 데이터를 공유하게 하는 소프트웨어는 DBMS이다
[헷갈리는 단어] DB - DB는 데이터 집합, DBMS는 이를 관리하는 시스템

데이터베이스 무결성 제약조건
데이터베이스에 저장되는 데이터가 일관성, 유효성, 정확성을 유지하도록 두는 제약조건 (암기: 개참도)
[구성] 개체 무결성 + 참조 무결성 + 도메인 무결성
[의미] 데이터의 정확성과 일관성을 지키기 위한 규칙
[구분] 종류별 의미
· 개체 무결성: 모든 릴레이션은 기본키를 가져야 하며 기본키는 NULL이 있을 수 없고 중복될 수 없음
· 참조 무결성: 외래키는 참조하는 릴레이션의 기본키 값과 동일해야 함
· 도메인 무결성: 속성 값들은 정의된 도메인에 속한 값만 가질 수 있음
[치트키] "개(개체) 참(참조) 도(도메인) = 개참도"
[예문] 외래키 값이 참조하는 릴레이션의 기본키 값과 일치해야 한다는 제약조건은 참조 무결성이다

데이터베이스 회복 기법
장애 발생 시 데이터베이스를 정상 상태로 되돌리는 기법
[구성] 로그 기반(즉시 갱신 + 지연 갱신) + 검사점 회복 + 그림자 페이징
[의미] 트랜잭션의 로그나 복사본을 이용해 복구
[구분] 종류별 의미
· 즉시 갱신: 변경 내용을 즉시 DB에 적용
· 지연 갱신: 트랜잭션이 부분 완료될 때까지 적용을 미룸
· 검사점 회복: 체크포인트를 지정해 그 지점 이후만 복구
· 그림자 페이징: 페이지 단위로 복사본을 만들어 보관
[치트키] "로그 / 체크포인트 / 그림자 = 3가지 복구 도구"
[예문] 체크포인트를 지정해 그 이후의 트랜잭션만 처리하는 회복 기법은 검사점 회복 기법이다

검사점 회복 기법
트랜잭션 실행 중간에 검사 시점(Check Point)을 지정하여 그 시점까지 수행하고 완료된 내용을 데이터베이스에 적용하는 기법
[구성] 체크포인트 지정 → 완료된 내용 반영 → 장애 시 체크포인트 이후만 복구
[의미] 복구 시 전체 로그를 처리하지 않고 체크포인트 이후만 처리해 시간을 줄임
[치트키] "게임의 세이브 포인트에서 다시 시작"
[예문] 체크포인트 이후의 로그만 처리하여 복구 시간을 줄이는 기법은 검사점 회복 기법이다

그림자 페이징 기법
데이터베이스를 동일한 크기의 페이지로 나누고 각 페이지마다 복사하여 그림자 페이지를 보관하는 회복 기법
[구성] 현재 페이지 테이블 + 그림자 페이지 테이블
[의미] 장애 시 그림자 페이지로 되돌려 복구
[치트키] "그림자 = 원본 페이지의 백업 사본"
[예문] 페이지 단위로 복사본을 보관해 두었다가 복구하는 기법은 그림자 페이징이다

즉시 갱신 기법(Eager)
변경 내용을 그때그때 바로 데이터베이스에 적용하는 회복 기법
[구성] 변경 즉시 DB 반영 + 로그 기록
[의미] 장애 시 Redo와 Undo를 모두 수행
[치트키] "즉시 = 바로 반영, Redo와 Undo 둘 다"
[예문] 트랜잭션 수행 중 변경 내용을 즉시 반영하며 Redo와 Undo를 모두 수행하는 기법은 즉시 갱신이다
[헷갈리는 단어] 지연 갱신 - 즉시는 Redo와 Undo, 지연은 Redo만

지연 갱신 기법(Lazy)
트랜잭션이 부분 완료될 때까지 DB에 적용하지 않고 지연시킨 후 로그 내용을 토대로 적용하는 기법
[구성] 부분 완료 전까지 반영 보류 → 완료 후 로그로 반영
[의미] 장애 시 Redo만 수행하면 됨
[치트키] "지연 = 끝날 때까지 미룬다, Redo만"
[예문] 트랜잭션이 부분 완료된 후에 로그를 바탕으로 DB에 반영하는 기법은 지연 갱신이다
[헷갈리는 단어] 즉시 갱신 - 지연은 Redo만, 즉시는 Redo와 Undo

데이터베이스 이중화
재해가 일어났을 때를 대비해 동일한 데이터베이스를 중복시켜 동시에 갱신하며 관리하는 기법
[구성] 원본 DB + 복제 DB + 동시 갱신
[의미] 데이터 보호와 가용성 향상을 위한 기법
[구분] 갱신 방식
· Eager 기법: 트랜잭션 수행 중 변경 즉시 반영
· Lazy 기법: 트랜잭션이 완전히 완료된 후 변경 내용 반영
[치트키] "이중화 = 똑같은 DB를 두 벌 두고 함께 갱신"
[예문] 재해에 대비해 동일한 DB를 복제하여 동시에 갱신하는 기법은 데이터베이스 이중화이다

분산 데이터베이스
여러 곳으로 분산되어 있는 데이터베이스를 하나의 가상 시스템으로 사용할 수 있도록 한 데이터베이스
[구성] 여러 지역의 DB + 네트워크 연결 + 하나의 가상 시스템
[의미] 사용자에게는 하나의 DB처럼 보이도록 함
[치트키] "흩어져 있어도 사용자에게는 하나"
[예문] 물리적으로 분산된 DB를 하나의 시스템처럼 사용하게 하는 DB는 분산 데이터베이스이다

분산 데이터베이스 투명성
분산 환경의 복잡함을 사용자에게 숨기는 5가지 투명성
[구성] 위치 + 분할 + 중복 + 병행 + 장애
[의미] 사용자가 분산 여부를 의식하지 않고 사용할 수 있도록 함
[구분] 투명성별 의미
· 위치 투명성: 위치를 알 필요 없이 논리적 명칭만으로 접근 가능
· 분할 투명성: 하나의 논리적 테이블이 여러 조각으로 분할되어 여러 위치에 저장되어도 의식하지 않음
· 중복 투명성: 동일 데이터가 여러 곳에 중복되어도 하나만 존재하는 것처럼 사용
· 병행 투명성: 병행으로 트랜잭션이 수행되어도 결과가 영향을 받지 않음
· 장애 투명성: 장애에도 불구하고 트랜잭션을 정확하게 처리
[치트키] "위(위치) 분(분할) 중(중복) 병(병행) 장(장애) = 위분중병장"
[예문] 데이터가 어디에 있는지 몰라도 논리적 이름만으로 접근할 수 있는 투명성은 위치 투명성이다

파티셔닝(Partitioning)
데이터베이스를 여러 부분으로 분할하는 것
[구성] 수평 분할 + 수직 분할
[의미] 성능과 관리 효율을 높이기 위해 테이블을 나누는 기법
[구분] 방식별 의미
· 수평 분할: 하나의 테이블의 각 행들을 분할
· 수직 분할: 테이블의 일부를 컬럼 기준으로 분할 (하나의 테이블을 2개 이상으로 분해)
[치트키] "수평은 행 단위로 가로로 자르고, 수직은 열 단위로 세로로 자른다"
[예문] 테이블의 행을 기준으로 나누는 파티셔닝은 수평 분할이다

시스템 카탈로그
데이터베이스를 관리하기 위해 DB에서 자동으로 생성한 시스템 테이블 (데이터 사전, Data Dictionary)
[구성] 메타데이터 저장 + 자동 생성 시스템 테이블
[의미] 테이블, 인덱스, 사용자 등 DB 객체 정보를 저장
[치트키] "카탈로그 = DB의 설명서, 데이터 사전"
[예문] 데이터베이스가 자동으로 생성해 객체 정보를 저장하는 시스템 테이블은 시스템 카탈로그이다

반정규화
데이터베이스의 성능 향상을 위해 데이터 중복을 허용하는 등 정규화에 위배되는 행위
[구성] 테이블 통합 + 중복 컬럼 추가 + 집계 테이블 추가 + 진행 테이블 추가
[의미] 조회 성능을 높이기 위해 의도적으로 정규화를 되돌리는 것
[구분] 테이블 추가 기법
· 집계 테이블 추가: 집계 데이터를 위한 테이블을 만들고 원본 테이블에 트리거를 설정하여 사용
· 진행 테이블 추가: 이력 관리 등을 목적으로 추가, 기본키를 적절히 설정
[치트키] "정규화는 쪼개기, 반정규화는 성능 위해 다시 합치기"
[예문] 조회 성능 향상을 위해 의도적으로 데이터 중복을 허용하는 것은 반정규화이다
[헷갈리는 단어] 정규화 - 정규화는 중복 제거, 반정규화는 중복 허용

객체지향 언어 특징
객체지향 프로그래밍의 5가지 핵심 특징 (암기: 다정상추캡)
[구성] 다형성 + 정보은닉 + 상속 + 추상화 + 캡슐화
[의미] 재사용성과 유지보수성을 높이는 객체지향 개념
[구분] 특징별 의미
· 다형성: 하나의 메시지에 대해 각 객체가 다양한 방법으로 응답
· 정보은닉: 자신의 데이터를 숨기고 정의한 행동을 통해서만 접근 허용
· 상속: 상위 클래스의 데이터와 행동을 하위 클래스가 물려받음
· 추상화: 어떤 실체로부터 공통 부분을 모아 놓음
· 캡슐화: 데이터와 데이터를 처리하는 행동을 하나로 묶음
[치트키] "다정이가 상추를 캡슐로 숨긴다 = 다정상추캡"
[예문] 상위 클래스의 속성과 메서드를 하위 클래스가 물려받는 특징은 상속이다

럼바우 객체지향 분석 기법
시스템을 세 가지 모델로 나누어 분석하는 객체지향 분석 기법 (암기: 객동기)
[구성] 객체 모델링 → 동적 모델링 → 기능 모델링
[의미] 객체, 상태 변화, 처리 흐름의 관점으로 시스템을 분석
[구분] 모델링별 의미
· 객체 모델링: 객체 다이어그램, 시스템에서 요구하는 객체를 찾고 관계를 정의, 가장 중요하며 선행되어야 함
· 동적 모델링: 상태 다이어그램, 시간 흐름에 따른 객체 사이의 제어 흐름과 동작 순서
· 기능 모델링: 자료 흐름도(DFD), 프로세스 중심의 자료 흐름으로 처리 과정 표현
[치트키] "객(객체) 동(동적) 기(기능) = 객동기"
[예문] 상태 다이어그램을 사용하는 럼바우 모델링은 동적 모델링이다

단위 모듈 작성 원칙
공통 모듈 명세를 작성할 때 지켜야 할 5가지 원칙 (암기: 정명완일추)
[구성] 정확성 + 명확성 + 완전성 + 일관성 + 추적성
[의미] 구현 시 오해가 없도록 요구사항을 정확히 문서화
[구분] 원칙별 의미
· 정확성: 실제 시스템 구현 시 필요한지 알 수 있도록 정확히 작성
· 명확성: 기능에 대해 일관되게 이해되고 한 가지로 해석될 수 있도록 작성
· 완전성: 구현에 필요한 모든 것을 기술
· 일관성: 공통 기능들 간에 상호 충돌이 없도록 작성
· 추적성: 요구사항 출처와 관련 시스템 등의 관계를 식별할 수 있도록 작성
[치트키] "정명완이 세계 일주를 했다 = 정명완일추"
[예문] 요구사항의 출처와 관련 시스템 관계를 식별할 수 있도록 작성하는 원칙은 추적성이다

미들웨어
양쪽을 연결하여 데이터를 주고받을 수 있도록 중간에서 매개 역할을 하는 소프트웨어
[구성] 클라이언트 ↔ 미들웨어 ↔ 서버
[의미] 서로 다른 시스템·플랫폼 간 통신을 쉽게 해 주는 소프트웨어 계층
[치트키] "미들웨어 = 중간에 끼어 연결해 주는 통역사"
[예문] 서로 다른 시스템 사이에서 데이터 교환을 중개하는 소프트웨어는 미들웨어이다

MVC 패턴
사용자 인터페이스, 데이터 및 논리 제어를 구현하는 데 널리 사용되는 소프트웨어 디자인 패턴
[구성] 모델(Model) + 뷰(View) + 컨트롤러(Controller)
[의미] 데이터, 화면, 제어를 분리하여 유지보수성과 재사용성을 높임
[치트키] "M 데이터, V 화면, C 제어 = 모뷰컨"
[예문] 모델, 뷰, 컨트롤러로 역할을 분리하는 패턴은 MVC이다

옵티마이저
사용자가 질의한 SQL문에 대해 최적의 실행 방법을 결정하는 역할을 수행하는 것
[구성] SQL 질의 → 실행 계획 후보 → 최적 계획 선택
[의미] 비용을 비교해 가장 효율적인 처리 경로를 결정하는 DBMS 구성요소
[치트키] "옵티마이저 = SQL의 내비게이션, 가장 빠른 길 선택"
[예문] SQL문의 최적 실행 방법을 결정하는 DBMS 구성요소는 옵티마이저이다

간트 차트
시간선 차트라고도 하며 작업이 언제 시작하고 종료되는지 일정을 막대 도표로 표시한 차트
[구성] 작업 + 기간(막대) + 일정
[의미] 프로젝트 일정 관리에 사용
[치트키] "간트 = 막대로 일정 보기"
[예문] 작업의 시작과 종료 일정을 막대 도표로 표시한 차트는 간트 차트이다
[헷갈리는 단어] PERT - 간트는 일정 막대 도표, PERT는 작업 상하관계 네트워크

PERT
프로젝트에 필요한 전체 작업의 상하관계를 표시한 네트워크
[구성] 작업 노드 + 선후 관계 화살표
[의미] 작업 간 선후 관계와 소요 시간을 분석하여 일정 관리에 활용
[치트키] "퍼트 = 작업을 줄줄이 이은 네트워크"
[예문] 전체 작업의 상하관계를 네트워크로 나타낸 일정 도구는 PERT이다
[헷갈리는 단어] 간트 차트 - PERT는 상하관계 네트워크, 간트는 막대 도표

CAP 이론
일관성, 가용성, 분할 내성 세 가지 속성 중 두 가지만 가질 수 있다는 이론
[구성] Consistency(일관성) + Availability(가용성) + Partition tolerance(분할 내성)
[의미] 분산 시스템에서 세 속성을 동시에 모두 만족할 수 없음을 설명
[치트키] "C·A·P 중 두 개만 고르세요"
[예문] 분산 시스템에서 일관성, 가용성, 분할 내성을 모두 만족할 수 없다는 이론은 CAP 이론이다

APM(Application Performance Management)
전체 애플리케이션의 성능을 관리하기 위해 접속자, 트랜잭션, 장애 진단 등을 모니터링하는 도구
[구성] 접속자 모니터링 + 트랜잭션 모니터링 + 장애 진단
[의미] 애플리케이션 상태를 감시하고 성능 문제를 진단
[치트키] "APM = 애플리케이션 건강검진"
[예문] 애플리케이션 전체를 감시하고 성능을 관리하는 도구는 APM이다

DLP
내부 정보의 외부 유출을 방지하기 위한 솔루션
[구성] 정보 식별 + 유출 감시 + 차단
[의미] 회사의 데이터를 외부로 가져갈 수 없게 통제
[치트키] "DLP = 데이터 유출(Leak) 막이"
[예문] 내부 중요 정보의 외부 유출을 막는 보안 솔루션은 DLP이다

블록체인
관리 대상 데이터를 블록이라는 소규모 데이터로 만들어 P2P 방식으로 체인 형태로 연결한 기술
[구성] 블록 + 체인 연결 + P2P 분산 저장
[의미] 중앙 서버 없이 참여자가 거래 기록을 공동으로 보관하고 검증
[치트키] "블록을 쇠사슬처럼 이어 모두가 장부를 나눠 갖는다"
[예문] 거래 정보를 블록으로 묶어 P2P 방식으로 연결한 분산 기술은 블록체인이다

NFT(Non-fungible token)
블록체인 기술을 이용해 디지털 자산의 소유주임을 증명하는 가상의 토큰
[구성] 블록체인 + 고유 토큰 + 소유권 증명
[의미] 대체 불가능한 고유한 디지털 자산을 구분하게 함
[치트키] "NFT = 복사해도 원본임을 증명하는 디지털 소유 증서"
[예문] 디지털 자산의 소유권을 블록체인으로 증명하는 토큰은 NFT이다

하이퍼바이저
하나의 컴퓨터에서 동시에 다수의 운영체제를 구동시킬 수 있게 하는 소프트웨어 가상화 플랫폼
[구성] 물리 서버 → 하이퍼바이저 → 가상 머신 여러 개
[의미] 하드웨어 자원을 추상화하여 여러 운영체제가 공유
[치트키] "하이퍼바이저 = 한 컴퓨터를 여러 대처럼 나누는 감독관"
[예문] 한 대의 서버에서 여러 운영체제를 동시에 구동시키는 가상화 소프트웨어는 하이퍼바이저이다

SDN(Software Defined Networking)
하드웨어에 의존하는 네트워크 체계에서 안전성, 보안, 속도 등을 소프트웨어로 제어·관리하기 위해 개발된 기술
[구성] 제어부 + 데이터부 분리 + 소프트웨어 제어
[의미] 네트워크를 소프트웨어로 중앙에서 유연하게 관리
[치트키] "SDN = 네트워크를 소프트웨어로 조종"
[예문] 네트워크 장비를 소프트웨어로 제어·관리하는 기술은 SDN이다

소프트웨어 정의 기술
하드웨어에 종속된 자원을 소프트웨어로 분리해 제어하는 기술
[구성] SDN + SDS + SDC + SDDC
[의미] 인프라를 소프트웨어로 유연하게 관리
[구분] 기술별 의미
· SDN: 네트워크를 소프트웨어로 제어
· SDS: 하드웨어에서 스토리지 소프트웨어를 분리하는 스토리지 아키텍처
· SDC: 소프트웨어 정의 컴퓨팅 (IaaS)
· SDDC: 모든 하드웨어를 가상화하여 가상 자원 풀을 구성하고 소프트웨어가 동적으로 할당·관리하는 데이터 센터
[치트키] "네트워크 N, 스토리지 S, 컴퓨팅 C, 데이터센터 DC"
[예문] 모든 하드웨어를 가상화해 자원 풀로 운영하는 데이터 센터는 SDDC이다

NFC
13.56MHz 주파수를 이용한 자기 유도결합 기반의 근접 무선 통신 기술
[구성] 근거리 + 13.56MHz + 자기장 통신
[의미] 스마트폰 결제나 출입 인증 등에 쓰이는 짧은 거리 통신
[치트키] "NFC = 가까이(Near Field) 대면 통신"
[예문] 13.56MHz 주파수를 이용해 가까운 거리에서 통신하는 기술은 NFC이다

RFID
전파 신호를 통해 비접촉식으로 사물에 부착된 얇은 평면 형태의 태그를 식별해 정보를 처리하는 기술
[구성] 태그 + 리더기 + 전파 식별
[의미] 물류, 출입 관리 등에서 사물을 자동으로 식별
[치트키] "RFID = 전파로 태그 읽기"
[예문] 전파를 이용해 비접촉으로 태그를 식별하는 기술은 RFID이다

DB 암호화 방식
데이터베이스 안의 데이터를 암호화하는 4가지 방식 (암기: 애플티하)
[구성] API 방식 + Plug-in 방식 + TDE 방식 + Hybrid 방식
[의미] 암호화 모듈을 적용하는 위치에 따라 구분
[구분] 방식별 의미
· API 방식: 애플리케이션 레벨에서 암호 모듈을 적용하는 애플리케이션 수정 방식
· Plug-in 방식: 암호화·복호화 모듈이 DB 서버에 설치된 방식
· TDE 방식: DB 서버의 DBMS 커널이 자체적으로 암호화 기능 수행
· Hybrid 방식: API 방식과 Plug-in 방식을 결합
[치트키] "애(API) 플(Plug-in) 티(TDE) 하(Hybrid) = 애플티하"
[예문] DBMS 커널이 자체적으로 암호화 기능을 수행하는 방식은 TDE이다

SSL/TLS
4계층과 7계층 사이에서 클라이언트와 서버 간 웹 데이터 암호화, 상호 인증, 전송 데이터 무결성을 보장하는 보안 프로토콜
[구성] 암호화 + 상호 인증 + 무결성 / 443 포트
[의미] 웹 통신(HTTPS)의 보안을 담당
[구분] 비교
· S-HTTP: 네트워크 트래픽을 암호화하여 전송하는 보안 프로토콜
[치트키] "SSL/TLS = 전송 계층과 응용 계층 사이, 443번 포트"
[예문] 443 포트를 사용하며 웹 데이터 암호화와 상호 인증을 제공하는 프로토콜은 SSL/TLS이다

IPSec
3계층에서 무결성과 인증을 보장하는 인증 헤더(AH)와 기밀성을 보장하는 암호화(ESP)를 이용한 IP 보안 프로토콜
[구성] AH + ESP + IKE / 전송 모드 + 터널 모드
[의미] IP 계층에서 패킷 단위로 보안을 제공
[구분] 구성별 의미
· 전송 모드: IP 패킷의 페이로드를 보호
· 터널 모드: IP 패킷 전체를 보호
· AH: 인증과 무결성을 제공하며 기밀성은 보장하지 않음
· ESP: 송신처 인증과 기밀성까지 모두 제공
· IKE: 키를 주고받는 키 관리 프로토콜
[치트키] "AH는 인증만, ESP는 암호화까지, IKE는 키 교환"
[예문] 기밀성까지 제공하는 IPSec 프로토콜은 ESP이다

SQL 언어 3가지
SQL을 기능에 따라 구분한 3가지 언어
[구성] DDL(정의어) + DML(조작어) + DCL(제어어)
[의미] 구조를 정의하고, 데이터를 다루며, 권한과 트랜잭션을 제어
[구분] 언어별 명령어
· DDL: CREATE, ALTER, DROP
· DML: SELECT, INSERT, UPDATE, DELETE
· DCL: GRANT, REVOKE, COMMIT, ROLLBACK
[치트키] "정의는 CAD(CREATE, ALTER, DROP), 조작은 SIUD, 제어는 권한과 확정·취소"
[예문] 테이블에서 데이터를 검색하는 SQL 명령어는 DML의 SELECT이다

SELECT 쿼리 집합 연산자
두 개 이상의 SELECT 결과를 합치거나 비교하는 연산자 (WHERE 조건 뒤에 사용)
[구성] UNION + UNION ALL + INTERSECT + EXCEPT(MINUS)
[의미] 질의 결과를 집합으로 다루는 연산
[구분] 연산자별 의미
· UNION: 합집합, 중복된 행을 하나로 출력 (중복 제거)
· UNION ALL: 모든 값을 그대로 결과에 표시
· INTERSECT: 교집합, 서로 중복된 값만 반영
· EXCEPT(MINUS): 차집합, A 테이블에서 B 테이블과 중복된 값을 뺀 A 값만 반영
[치트키] "UNION은 합쳐서 중복 제거, UNION ALL은 그대로 전부"
[예문] 두 SELECT 결과의 중복을 제거하며 합치는 연산자는 UNION이다
[헷갈리는 단어] UNION ALL - UNION은 중복 제거, UNION ALL은 중복 포함

JOIN의 종류
두 테이블을 연결하여 결과를 구하는 방식 (FROM 절의 Table 뒤에 사용)
[구성] 내부 조인(INNER JOIN) + 외부 조인(OUTER JOIN)
[의미] 컬럼 값을 기준으로 테이블을 결합
[구분] 종류별 의미
· 내부 조인: 컬럼 값이 같은 것들끼리 합침
· 외부 조인(LEFT OUTER JOIN): 컬럼이 같은 것을 왼쪽 기준으로 합치고, 같지 않아도 왼쪽 값은 모두 출력
· 예시: FROM 테이블1 INNER JOIN 테이블2 ON 테이블1.컬럼 = 테이블2.컬럼
[치트키] "내부는 일치하는 것만, 왼쪽 외부는 왼쪽을 모두 살린다"
[예문] 왼쪽 테이블의 모든 행을 출력하고 일치하지 않는 오른쪽 값은 NULL로 두는 조인은 LEFT OUTER JOIN이다

기능적 요구사항
소프트웨어를 구성하는 기능들이 무엇인지 정의한 요구사항
[구성] 시스템이 제공해야 하는 기능 + 동작
[의미] 사용자가 시스템으로 무엇을 할 수 있어야 하는지를 정의
[구분] 예시
· 사용자는 로그인할 수 있어야 한다
· 주문 내역을 조회한다
[치트키] "기능적 = 무엇을 한다(기능), 비기능적 = 얼마나 잘한다(조건)"
[예문] 사용자가 주문 내역을 조회할 수 있어야 한다는 요구는 기능적 요구사항이다
[헷갈리는 단어] 비기능적 요구사항 - 기능적은 기능 자체, 비기능적은 성능·보안 같은 조건

비기능적 요구사항
제품 보안, 성능, 안정성 등 소프트웨어 기능들에 대한 조건이 무엇인지 정의한 요구사항
[구성] 성능 + 보안 + 신뢰성 + 사용성 + 이식성 + 유지보수성
[의미] 기능이 아닌 품질과 제약을 정의
[구분] 예시
· 응답 시간 1초 이내
· 개인정보 암호화 저장
[치트키] "비기능 = 기능을 둘러싼 품질 조건"
[예문] 응답 시간이 1초 이내여야 한다는 요구는 비기능적 요구사항이다
[헷갈리는 단어] 기능적 요구사항 - 비기능은 조건, 기능적은 기능

연계 요구사항 분석 기법
연계 요구사항을 도출하고 분석하기 위한 5가지 기법
[구성] 인터뷰 + 체크리스트 + 설문지 + 델파이 기법 + 브레인스토밍
[의미] 이해관계자와 전문가의 의견을 수집해 연계 요구사항을 분석
[구분] 기법별 의미
· 인터뷰: 사용자 면담을 통해 연계 요구사항 도출
· 체크리스트: 시스템 운영 환경, 성능, 보안, 데이터 발생 주기 등 기준을 점검하여 분석
· 설문지: 서비스 활용 목적에 따라 연계 데이터 식별과 연계 주기 등을 설문으로 분석
· 델파이 기법: 각 분야 전문가의 경험적 지식으로 분석
· 브레인스토밍: 자발적으로 자연스럽게 제시된 아이디어 목록으로 분석
[치트키] "물어보고(인터뷰) 점검하고(체크) 설문 돌리고 전문가 모으고(델파이) 아이디어 쏟아낸다(브레인)"
[예문] 업무 전문가들의 경험적 지식으로 분석하는 기법은 델파이 기법이다

델파이 기법
전문가의 경험적 지식을 통한 문제 해결 및 미래 예측을 위한 기법
[구성] 전문가 그룹 + 반복 의견 수렴
[의미] 요구사항 분석과 하향식 비용 산정에서 모두 쓰이는 전문가 합의 기법
[치트키] "델파이 = 신탁처럼 전문가에게 물어 합의"
[예문] 여러 전문가의 의견을 모아 비용이나 요구사항을 추정하는 기법은 델파이 기법이다

프로젝트 핵심 관리 대상 3P
프로젝트를 관리할 때 핵심이 되는 세 가지 대상
[구성] 사람(People) + 문제(Problem) + 프로세스(Process)
[의미] 프로젝트 성공을 위해 사람, 해결할 문제, 진행 절차를 균형 있게 관리
[치트키] "3P = 사람, 문제, 프로세스"
[예문] 프로젝트 관리의 3P는 사람, 문제, 프로세스이다

소프트웨어 공학의 3R
기존 소프트웨어를 이해하고 개선하는 세 가지 활동
[구성] 역공학 + 재공학 + 재사용
[의미] 이미 있는 시스템을 분석하고 개선하여 활용하는 활동
[구분] 활동별 의미
· 역공학: 소스 코드를 보고 CASE 도구를 통해 거꾸로 설계를 만들어 냄
· 재공학: 기존 시스템의 기능이나 성능을 업그레이드하는 작업
· 재사용: 이미 개발되어 있는 소프트웨어의 전체 또는 일부분을 다시 사용
[치트키] "역(거꾸로) 재공(다시 고침) 재사(다시 씀)"
[예문] 소스 코드로부터 설계 정보를 거꾸로 추출하는 활동은 역공학이다

온톨로지
개체, 속성, 관계 정보를 컴퓨터가 이해할 수 있게 서술한 지식 베이스
[구성] 개체 + 속성 + 관계
[의미] 지식을 컴퓨터가 처리할 수 있도록 개념과 관계로 표현
[치트키] "온톨로지 = 컴퓨터용 개념 사전"
[예문] 개체와 관계를 컴퓨터가 이해하도록 서술한 지식 베이스는 온톨로지이다
[헷갈리는 단어] 시멘틱 웹 - 온톨로지는 지식 서술, 시멘틱 웹은 이를 활용하는 웹

시멘틱 웹
온톨로지를 활용하여 컴퓨터가 정보 자원의 뜻을 이해하고 논리적 추론까지 할 수 있는 차세대 웹
[구성] 온톨로지 + 논리적 추론
[의미] 키워드가 아니라 의미 기반으로 정보를 검색하고 처리
[구분] 추론 예시
· 나주 배라는 문맥이면 먹는 배라고 컴퓨터가 스스로 인식
[치트키] "시멘틱 = 의미(semantic)를 이해하는 웹"
[예문] 컴퓨터가 정보의 의미를 이해하고 추론하는 차세대 웹은 시멘틱 웹이다

구조적 분석 도구
구조적 분석에서 요구사항을 모델링하는 도구
[구성] DFD + Data Dictionary + mini-spec + ERD + STD
[의미] 자료 흐름과 데이터 구조, 상태 변화를 도식으로 표현
[구분] 도구별 의미
· DFD(자료 흐름도): 자료의 흐름과 처리 과정을 표현
· Data Dictionary(자료 사전): 자료 항목을 정의
· mini-spec(소단위 명세서): 처리 과정을 상세히 기술
· ERD(개체 관계도): 개체와 관계를 표현
· STD(상태 전이도): 상태 변화를 표현
[치트키] "구조적은 DFD 중심, 객체지향 분석은 UML"
[예문] 자료의 흐름을 표현하는 구조적 분석 도구는 DFD이다

인터페이스 구현 검증 도구
인터페이스가 정상 동작하는지 검증하는 테스트 도구 (암기: 엑스피 엔셀웨)
[구성] xUnit + STAF + FitNesse + NTAF + Selenium + Watir
[의미] 단위 테스트 프레임워크, 웹 테스트 도구 등으로 인터페이스 동작을 자동 검증
[구분] 도구별 의미
· xUnit: 다양한 언어를 지원하는 단위 테스트 프레임워크
· STAF: 서비스 호출, 컴포넌트 재사용 등 다양한 환경을 지원하는 테스트 프레임워크
· FitNesse: 웹 기반 테스트 케이스 설계·실행·결과를 지원, 테스트 케이스 테이블 작성 시 자동 테스트
· NTAF: STAF와 FitNesse의 장점을 통합한 네이버 개발 테스트 자동화 프레임워크
· Selenium: 다양한 브라우저와 개발 언어를 지원하는 웹 애플리케이션 테스트 프레임워크
· Watir: 루비를 사용하는 애플리케이션 테스트 프레임워크
[치트키] "엑스(xUnit) 스(STAF) 피(FitNesse) 엔(NTAF) 셀(Selenium) 웨(Watir)"
[예문] 다양한 브라우저를 지원하는 웹 애플리케이션 테스트 프레임워크는 Selenium이다

IDS(침입 탐지 시스템)
시스템에 대한 원치 않는 조작을 탐지해 주는 시스템 (Intrusion Detection System)
[구성] 모니터링 + 탐지 + 경고
[의미] 침입을 감지하여 알리지만 차단은 하지 않음
[치트키] "D = Detection, 탐지만 한다"
[예문] 침입을 탐지하고 경고하는 시스템은 IDS이다
[헷갈리는 단어] IPS - IDS는 탐지, IPS는 탐지와 차단

IPS(침입 방지 시스템)
네트워크 침입에 대한 차단 및 방지를 수행하는 시스템 (Intrusion Prevention System)
[구성] 탐지 + 차단
[의미] 침입을 탐지하는 데서 나아가 자동으로 막음
[치트키] "P = Prevention, 막아 버린다"
[예문] 침입을 탐지하고 실시간으로 차단하는 시스템은 IPS이다
[헷갈리는 단어] IDS - IPS는 차단까지, IDS는 탐지만

접근 통제 절차
사용자가 자원에 접근하기까지의 4단계 절차
[구성] 식별 → 인증 → 인가 → 책임 추적성
[의미] 누구인지 확인하고, 권한을 부여하고, 행위를 기록
[구분] 단계별 의미
· 식별(Identification): 나는 사용자입니다
· 인증(Authentication): 당신은 사용자가 맞습니다
· 인가(Authorization): 사용자에게 권한을 주겠습니다
· 책임 추적성(Accountability): 언제 누가 로그인했는지 기록
[치트키] "나야(식별) 맞네(인증) 들어와(인가) 기록해(책임추적)"
[예문] 인증된 사용자에게 권한을 부여하는 단계는 인가이다

소프트웨어 아키텍처 패턴
시스템 전체 구조를 설계할 때 사용하는 패턴
[구성] 피어 투 피어 + 브로커 + 이벤트-버스 + 파이프-필터 + 레이어 + MVC + 클라이언트-서버 등
[의미] 시스템의 컴포넌트와 상호작용 방식을 정의한 청사진
[구분] 패턴별 의미
· 피어 투 피어: 피어라 부르는 각 컴포넌트가 서로 서비스를 주고받음
· 브로커: 분리된 컴포넌트로 이루어진 분산 시스템에서 컴포넌트 간 중재
· 이벤트-버스: 이벤트 소스, 이벤트 리스너, 채널, 이벤트 버스 4가지 컴포넌트를 가짐
· 파이프-필터: 필터가 각 처리를 실행하고 처리된 데이터는 파이프로 전송
[치트키] "이벤트 버스는 소·리·채·버 4개, 파이프는 필터 사이를 잇는 관"
[예문] 데이터 스트림을 필터에서 처리하고 파이프로 전달하는 패턴은 파이프-필터 패턴이다

활동 다이어그램 구성 요소
활동들이 순차·병행으로 수행되는 흐름을 표현할 때 쓰는 요소
[구성] 포크 노드 + 조건 노드 + 구획면
[의미] 병렬 흐름 분기, 조건 분기, 수행 주체 구분
[구분] 요소별 의미
· 포크 노드: 병렬로 수행되는 흐름을 나누는 노드, 굵은 가로선, 들어오는 흐름 1개 / 나가는 흐름 여러 개
· 조건 노드: 조건에 따른 제어 흐름 분리, 마름모, 들어오는 흐름 1개 / 나가는 흐름 여러 개
· 구획면: 활동 수행 주체를 구분하는 면, 가로 또는 세로 실선으로 구분
[치트키] "포크는 굵은 선, 조건은 마름모, 구획면은 칸막이"
[예문] 활동 수행 주체를 구분하는 활동 다이어그램 요소는 구획면이다

도커(Docker)
컨테이너 응용 프로그램의 배포를 자동화하는 오픈소스 엔진
[구성] 컨테이너 + 이미지 + 자동 배치
[의미] 응용 프로그램을 컨테이너 안에 넣어 어디서나 동일하게 실행
[치트키] "컨테이너도 커~ = 도커"
[예문] 소프트웨어 컨테이너 안에 응용 프로그램을 배치하는 일을 자동화하는 오픈소스는 도커이다

문맥 교환(Context Switching)
CPU가 현재 실행 중인 문맥 상태를 PCB에 저장하고 다음 프로세스의 PCB로부터 문맥을 복원하는 것
[구성] 현재 상태 저장(PCB) → 다음 프로세스 PCB 복원
[의미] 프로세스 전환 시 발생하는 오버헤드를 동반
[치트키] "문맥 교환 = 하던 일 저장하고 다른 일 불러오기"
[예문] 프로세스를 전환할 때 PCB에 상태를 저장하고 복원하는 동작은 문맥 교환이다

릴리즈 노트
고객에게 개발 과정에서 정리된 상세 서비스 정보와 제품 수정·변경·개선 내용을 제공하는 문서
[구성] 헤더 + 개요 + 목적 + 이슈 요약 + 재현 방법 등
[의미] 배포 버전의 변경 사항을 사용자에게 알리는 문서
[구분] 작성 항목
· 헤더: 문서 이름, 제품 이름, 버전 번호, 날짜 등의 정보
[치트키] "릴리즈 노트 = 이번 배포의 변경 알림장"
[예문] 릴리즈 노트 작성 항목 중 문서 이름, 제품 이름, 버전 번호, 날짜가 들어가는 항목은 헤더이다

AJAX
웹 페이지 전체를 다시 로딩하지 않고도 일부분만 갱신할 수 있는 비동기 방식 처리 기술
[구성] 비동기 통신 + 부분 갱신
[의미] 사용자 경험을 높이는 웹 기술
[치트키] "AJAX = 새로고침 없이 일부만 쏙 바꾸기"
[예문] 페이지 전체를 새로 고치지 않고 일부만 비동기로 갱신하는 기술은 AJAX이다

JSON
키와 값의 쌍으로 이루어진 데이터 오브젝트를 전달하기 위한 XML을 대체하는 주요 데이터 포맷
[구성] 키 + 값 쌍
[의미] 가볍고 읽기 쉬워 웹 API에서 널리 사용
[치트키] "JSON = 키:값 짝으로 가볍게"
[예문] 키-값 쌍으로 데이터를 표현하며 XML을 대체하는 데이터 포맷은 JSON이다

XML
W3C에서 개발되었으며 호환 문제와 SGML의 복잡함을 해결하기 위해 개발된 다목적 마크업 언어
[구성] 태그 기반 + 사용자 정의 태그
[의미] 시스템 간 데이터 교환을 위한 표준 형식
[치트키] "XML = 태그를 내 마음대로 확장"
[예문] 호환 문제와 SGML의 복잡함을 해결하기 위해 개발된 다목적 마크업 언어는 XML이다

SQL 활용 유형
SQL을 응용 프로그램에서 사용하는 방식
[구성] 내장 SQL + 동적 SQL + 절차형 SQL
[의미] 사용 환경과 목적에 따라 SQL을 확장
[구분] 유형별 의미
· 내장 SQL: C, C++, Visual Basic 등 호스트 프로그램 언어에 삽입되어 응용 프로그램과 함께 실행, 호스트 변수 선언문 필요
· 동적 SQL: 컴파일 시 SQL 문장이 확정되지 않을 때 조건에 따라 SQL 구문을 변경
· 절차형 SQL: SQL 문의 연속 실행과 조건에 따른 반복·분기 제어, 저장 모듈 생성 및 활용
[치트키] "내장은 프로그램 안에, 동적은 실행 중 변경, 절차형은 로직까지"
[예문] 컴파일 시점에 SQL 문장이 확정되지 않는 경우에 사용하는 방식은 동적 SQL이다

이행적 함수 종속
릴레이션 A, B, C에서 A가 B를 결정하고 B가 C를 결정하여 결과적으로 A가 C를 결정하는 경우
[구성] A → B + B → C ⇒ A → C
[의미] 3NF에서 제거해야 하는 종속
[치트키] "A→B→C 징검다리, 건너뛰어 A→C"
[예문] A→B이고 B→C이므로 A→C가 성립하는 종속은 이행적 함수 종속이다

포렌식
범죄 사실의 디지털 증거물에 대해 사법기관에 제출하기 위해 수집, 분석, 보고서를 작성하는 일련의 과정
[구성] 수집 → 분석 → 보고서 작성
[의미] 디지털 증거의 법적 효력을 확보하는 절차
[치트키] "포렌식 = 디지털 현장 감식"
[예문] 디지털 증거를 수집·분석하여 보고서로 작성하는 과정은 포렌식이다

UI 유형
사용자 인터페이스의 3가지 유형
[구성] CLI + GUI + NUI
[의미] 사용자가 시스템을 조작하는 방식에 따른 구분
[구분] 유형별 의미
· CLI: 명령어를 텍스트로 입력하여 조작
· GUI: 그래픽 환경에서 마우스 등을 이용
· NUI: 키보드나 마우스 없이 신체 부위(음성, 제스처 등)를 이용
[치트키] "C 명령어 글자, G 그림, N 몸"
[예문] 신체 부위를 이용하여 조작하는 인터페이스는 NUI이다

유스케이스
사용자 측면에서 요구사항과 사용자가 원하는 목표를 달성하기 위해 수행할 내용을 기술한 것
[구성] 액터 + 유스케이스 + 시스템 경계
[의미] 요구사항을 구조적으로 표현하고 다이어그램으로 묘사
[치트키] "유스케이스 = 사용자가 시스템으로 무엇을 하는가"
[예문] 사용자 관점에서 요구사항을 다이어그램으로 나타내는 기법은 유스케이스이다

머신러닝·딥러닝 라이브러리
인공지능 개발에 널리 사용되는 도구
[구성] 딥러닝 + 사이킷런 + 텐서플로 + 파이토치
[의미] 모델 구축과 학습을 쉽게 해 주는 프레임워크
[구분] 도구별 의미
· 딥러닝: 머신러닝 알고리즘 중 인공신경망을 기반으로 한 방법의 통칭
· 사이킷런: 가장 널리 사용되는 머신러닝 패키지 중 하나
· 텐서플로: 구글이 만든 딥러닝 라이브러리, CPU와 GPU로 인공신경망 모델을 효율적으로 훈련
· 파이토치: 페이스북에서 개발해 2016년에 공개한 파이썬 기반 오픈소스 머신러닝 라이브러리
[치트키] "텐서플로는 구글, 파이토치는 페이스북"
[예문] 구글이 만든 딥러닝 라이브러리는 텐서플로이다

수학적 비용 산정 방법
수학적 공식을 이용해 개발 비용을 산정하는 하향식 방법
[구성] COCOMO + Putnam + FP
[의미] 규모나 기능에 기반한 모델로 비용을 계산
[구분] 모델별 의미
· COCOMO: 프로그램 규모에 따라 조직형, 반분리형, 임베디드형으로 구분
· Putnam: 시간과 노력의 Rayleigh-Norden 곡선을 기초로 단계별 필요 인력 분포를 계산
· FP(Function Point): 기능점수 모형
[치트키] "코코모는 규모 3유형, 푸트남은 레일리 곡선, FP는 기능점수"
[예문] Rayleigh-Norden 곡선을 기초로 인력 분포를 구하는 모델은 Putnam이다

프로토타입 모형
실제 개발될 시스템의 견본을 미리 만들어 최종 결과물을 예측하는 모형
[구성] 요구사항 수집 → 견본 제작 → 사용자 평가 → 개선
[의미] 요구사항이 불명확할 때 사용자와 개발자의 이해 차이를 줄임
[치트키] "프로토타입 = 먼저 맛보기 시제품"
[예문] 견본을 먼저 만들어 사용자 요구를 확인하는 생명주기 모형은 프로토타입 모형이다

스택과 큐
대표적인 선형 자료구조
[구성] 스택(LIFO) + 큐(FIFO) + 데크
[의미] 데이터를 넣고 빼는 순서가 다름
[구분] 구조별 의미
· 스택: 후입선출(LIFO), 함수 호출, 수식 계산, undo에 사용
· 큐: 선입선출(FIFO), 작업 대기열, 버퍼에 사용
· 데크: 양쪽에서 삽입·삭제 가능
[치트키] "스택은 접시 쌓기 마지막이 먼저, 큐는 줄서기 먼저 온 사람이 먼저"
[예문] 마지막에 들어간 데이터가 먼저 나오는 구조는 스택이다

이진 트리 순회
이진 트리의 노드를 방문하는 3가지 순서
[구성] 전위(Root → Left → Right) + 중위(Left → Root → Right) + 후위(Left → Right → Root)
[의미] 루트를 언제 방문하느냐에 따라 구분
[구분] 예시 (수식 트리: 곱셈(A, B)과 C의 덧셈)
· 전위: + * A B C
· 중위: A * B + C
· 후위: A B * C +
[치트키] "루트가 앞이면 전위, 가운데면 중위, 뒤면 후위"
[예문] 왼쪽 → 오른쪽 → 루트 순서로 방문하는 순회는 후위 순회이다

정렬 알고리즘
데이터를 일정한 순서로 나열하는 알고리즘
[구성] 선택 + 버블 + 삽입 + 퀵 + 병합 + 힙
[의미] 알고리즘마다 평균 시간 복잡도와 특성이 다름
[구분] 알고리즘별 특징
· 선택: O(n²), 최솟값을 골라 앞으로 이동
· 버블: O(n²), 인접 교환 반복
· 삽입: O(n²), 정렬된 부분에 삽입
· 퀵: 평균 O(n log n), 피벗 기준 분할, 최악 O(n²)
· 병합: O(n log n), 분할 정복, 안정 정렬
· 힙: O(n log n), 힙 자료구조 이용
[치트키] "선버삽은 n제곱, 퀵병힙은 n log n"
[예문] 피벗을 기준으로 분할하며 최악의 경우 O(n²)인 정렬은 퀵 정렬이다

페이지 교체 알고리즘
가상 메모리에서 새 페이지를 적재하기 위해 교체할 페이지를 선택하는 알고리즘
[구성] FIFO + LRU + LFU + NUR + OPT
[의미] 페이지 부재율을 낮추기 위한 정책
[구분] 알고리즘별 의미
· FIFO: 먼저 들어온 페이지를 교체 (벨레이디 모순 발생 가능)
· LRU: 가장 오래 사용하지 않은 페이지를 교체
· LFU: 사용 빈도가 가장 낮은 페이지를 교체
· NUR: 최근에 사용하지 않은 페이지를 교체 (참조·변형 비트 이용)
· OPT: 앞으로 가장 오래 사용되지 않을 페이지를 교체 (이론상 최적)
[치트키] "LRU 오래, LFU 빈도, FIFO 순서, OPT 미래"
[예문] 가장 오랫동안 사용되지 않은 페이지를 교체하는 알고리즘은 LRU이다

단편화(Fragmentation)
메모리 할당과 해제 과정에서 사용하지 못하는 공간이 생기는 현상
[구성] 내부 단편화 + 외부 단편화
[의미] 메모리 낭비의 원인
[구분] 종류별 의미
· 내부 단편화: 할당된 영역이 필요 크기보다 커서 내부 공간이 낭비 (페이징에서 발생)
· 외부 단편화: 작은 빈 공간들이 흩어져 사용하지 못하는 현상 (세그먼테이션에서 발생)
[치트키] "페이징은 내부, 세그먼테이션은 외부"
[예문] 작은 빈 공간들이 흩어져 사용할 수 없는 현상은 외부 단편화이다

스래싱(Thrashing)
페이지 교체가 과도하게 발생해 프로세스 처리보다 교체에 더 많은 시간을 쓰는 현상
[구성] 과도한 페이지 부재 → CPU 이용률 저하
[의미] 다중 프로그래밍 정도가 지나치게 높을 때 발생
[구분] 관련 개념
· 워킹 셋: 일정 시간 동안 자주 참조하는 페이지 집합
· 구역성: 시간 구역성과 공간 구역성
[치트키] "스래싱 = 일은 안 하고 짐만 옮기다 지침"
[예문] 페이지 교체에 더 많은 시간을 사용하여 성능이 떨어지는 현상은 스래싱이다

디스크 스케줄링
디스크 헤드의 이동을 최소화하기 위해 요청 처리 순서를 결정하는 알고리즘
[구성] FCFS + SSTF + SCAN + C-SCAN + LOOK + C-LOOK
[의미] 탐색 시간을 줄여 성능을 높임
[구분] 알고리즘별 의미
· FCFS: 요청 순서대로 처리
· SSTF: 현재 헤드에서 가장 가까운 트랙 우선
· SCAN: 한 방향 끝까지 갔다가 반대로 이동 (엘리베이터)
· C-SCAN: 한 방향만 처리하고 끝나면 시작으로 복귀
· LOOK / C-LOOK: 요청이 있는 곳까지만 이동
[치트키] "SCAN은 엘리베이터, C-SCAN은 한 방향 순환, LOOK은 필요한 곳까지만"
[예문] 현재 헤드에서 가장 가까운 트랙의 요청을 먼저 처리하는 방식은 SSTF이다

메모리 배치 전략
빈 공간 중 프로그램을 어디에 배치할지 정하는 전략
[구성] First Fit + Best Fit + Worst Fit
[의미] 단편화와 탐색 시간에 영향을 줌
[구분] 전략별 의미
· First Fit: 처음 맞는 영역에 배치
· Best Fit: 단편화가 가장 적게 남는 영역에 배치
· Worst Fit: 단편화가 가장 크게 남는 영역에 배치
[치트키] "처음(First) 딱 맞게(Best) 가장 크게(Worst)"
[예문] 남는 공간이 가장 작은 빈 영역에 배치하는 전략은 Best Fit이다

스풀링(Spooling)
입출력 장치의 처리를 디스크 버퍼로 중계해 CPU와 입출력 장치의 속도 차이를 완화하는 기법
[구성] 프로그램 → 디스크 버퍼 → 출력 장치
[의미] 프린터 등 느린 장치를 효율적으로 사용
[치트키] "스풀링 = 줄 세워 두고 프린터가 천천히 가져간다"
[예문] 프린터 출력 데이터를 디스크에 모아 두었다가 순서대로 출력하는 기법은 스풀링이다

3-way handshake
TCP 연결을 설정하기 위해 3번 메시지를 주고받는 과정
[구성] SYN → SYN/ACK → ACK
[의미] 양쪽이 통신 준비가 되었음을 확인하고 연결을 수립
[구분] 단계별 의미
· SYN: 클라이언트가 연결 요청
· SYN/ACK: 서버가 요청을 수락하고 자신의 연결 요청 전송
· ACK: 클라이언트가 확인 응답
[치트키] "요청(SYN) → 요청과 승낙(SYN/ACK) → 승낙(ACK)"
[예문] TCP 연결 설정 과정은 SYN, SYN/ACK, ACK의 3단계로 이루어진다

방화벽(Firewall)
네트워크 트래픽을 규칙에 따라 필터링하여 허용하거나 차단하는 보안 장치
[구성] 접근 규칙 + 허용·차단
[의미] 내부 네트워크와 외부 네트워크 사이를 보호
[치트키] "방화벽 = 네트워크의 성벽 출입문"
[예문] 정해진 규칙에 따라 트래픽을 필터링하는 보안 솔루션은 방화벽이다
[헷갈리는 단어] WAF - 방화벽은 네트워크 필터링, WAF는 웹 공격 방어

WAF(웹 방화벽)
SQL 삽입, XSS 등 웹 기반 공격을 방어하기 위한 웹 애플리케이션 방화벽
[구성] HTTP 트래픽 검사 + 웹 공격 차단
[의미] 웹 서비스의 취약점을 노린 공격을 막음
[치트키] "WAF = 웹(Web)에 특화된 방화벽"
[예문] SQL Injection과 XSS 같은 웹 공격을 방어하는 방화벽은 WAF이다

NAC
네트워크에 접속하는 단말을 인증하고 보안 정책 준수 여부를 검사하여 접근을 제어하는 솔루션
[구성] 단말 인증 + 정책 검사 + 접근 제어
[의미] 허가되지 않거나 위험한 단말의 네트워크 접근을 막음
[치트키] "NAC = 네트워크 출입 심사대"
[예문] 단말의 보안 상태를 검사해 네트워크 접근을 제어하는 솔루션은 NAC이다

SIEM
보안 경고를 실시간으로 분석하고 빅데이터 기반으로 심층 분석하는 통합 보안 관제 솔루션
[구성] 로그 수집 + 실시간 분석 + 상관 분석
[의미] 여러 보안 장비의 로그를 통합해 위협을 탐지
[치트키] "SIEM = 보안 로그를 한곳에 모아 분석하는 관제센터"
[예문] 여러 보안 장비의 로그를 통합 분석해 위협을 탐지하는 솔루션은 SIEM이다

SSO(Single Sign-On)
한 번의 인증으로 여러 서비스를 이용할 수 있게 하는 인증 기술
[구성] 한 번 로그인 → 여러 서비스 이용
[의미] 사용자 편의와 계정 관리 효율을 높임
[치트키] "SSO = 한 번 열쇠로 모든 문"
[예문] 한 번 로그인으로 여러 시스템을 이용하는 인증 방식은 SSO이다

빅데이터 3V
빅데이터의 대표 특성 3가지
[구성] Volume(규모) + Velocity(속도) + Variety(다양성)
[의미] 기존 방식으로 처리하기 어려운 대규모 데이터의 특징
[구분] 특성별 의미
· Volume: 데이터의 양이 매우 큼
· Velocity: 생성과 처리 속도가 빠름
· Variety: 정형·비정형 등 형태가 다양함
[치트키] "양(Volume) 속도(Velocity) 다양성(Variety) = 3V"
[예문] 빅데이터의 3V는 규모, 속도, 다양성이다

DevOps
개발(Development)과 운영(Operations)을 통합하여 개발 주기를 단축하고 지속적으로 배포하는 방법론
[구성] 개발 + 운영 + 자동화(CI/CD)
[의미] 개발과 운영 간 협업으로 빠르고 안정적인 배포를 지원
[치트키] "DevOps = 개발팀과 운영팀의 벽을 허문다"
[예문] 개발과 운영을 통합하여 빠르게 배포하는 방법론은 DevOps이다

마이크로서비스(MSA)
하나의 큰 애플리케이션을 독립적으로 배포 가능한 작은 서비스 단위로 나누어 구성하는 아키텍처
[구성] 작은 서비스 + 독립 배포 + API 통신
[의미] 서비스별로 독립적으로 개발·확장·배포할 수 있어 유연성이 높음
[치트키] "MSA = 큰 덩어리를 작은 서비스로 쪼개기"
[예문] 서비스를 독립적으로 배포 가능한 작은 단위로 나누는 아키텍처는 마이크로서비스이다

레거시 시스템(Legacy System)
낡은 기술이나 방법론, 소프트웨어 등으로 구성된 오래된 시스템
[구성] 오래된 하드웨어 + 소프트웨어 + 업무 로직
[의미] 여전히 업무에 쓰이지만 유지보수와 연계가 어려워 현대화나 재공학의 대상이 되는 시스템
[치트키] "레거시 = 유산, 물려받아 쓰는 낡은 시스템"
[예문] 오래된 기술로 구축되어 현대화가 필요한 기존 시스템을 레거시 시스템이라 한다

메타버스
3차원 가상 세계에서 실제 생활과 같은 직업, 금융, 학습 등이 연결된 가상 세계
[구성] 3차원 가상 공간 + 사용자 아바타 + 경제 활동
[의미] 현실과 가상이 융합되어 사회·경제 활동이 이루어지는 공간
[치트키] "메타(초월) + 유니버스(세계) = 메타버스"
[예문] 3차원 가상 공간에서 경제·사회 활동이 이루어지는 세계는 메타버스이다

스크레이피(Scrapy)
웹 사이트를 크롤링하여 구조화된 데이터를 수집하는 파이썬 기반의 애플리케이션 프레임워크
[구성] 파이썬 + 크롤러 + 데이터 추출
[의미] 웹에서 필요한 정보를 자동으로 수집
[치트키] "스크레이프 = 긁어모으다, 웹 데이터를 긁어 오는 프레임워크"
[예문] 파이썬으로 웹 크롤링을 수행하는 프레임워크는 Scrapy이다

피코넷(Piconet)
소규모 무선 통신망을 형성하는 무선 네트워크 기술
[구성] 근거리 무선 단말 + 소규모 망 형성
[의미] 개인 영역에서 장치들을 무선으로 연결하는 소규모 네트워크
[치트키] "피코(아주 작은) + 넷 = 아주 작은 무선망"
[예문] 근거리 무선 단말들이 구성하는 소규모 무선 네트워크는 피코넷이다
[헷갈리는 단어] WPAN - 피코넷은 소규모 망 형성, WPAN은 개인 영역 무선 네트워크

UWB(초광대역)
낮은 전력으로 넓은 주파수 대역을 사용하여 대용량 정보를 전송하는 무선 통신 기술
[구성] 초광대역 + 저전력 + 대용량 전송
[의미] 근거리에서 고속 통신과 정밀 위치 측정에 활용
[치트키] "UWB = 아주 넓은(Ultra Wide) 대역"
[예문] 낮은 전력으로 대용량 정보를 전송하는 초광대역 무선 통신 기술은 UWB이다

GIS
지리 정보 시스템, 지도에 관한 속성 정보를 컴퓨터를 이용해 해석하는 시스템
[구성] 지도 + 속성 정보 + 분석
[의미] 위치 기반 정보를 저장·분석·시각화
[치트키] "GIS = 지리(Geographic) 정보 시스템"
[예문] 지도와 속성 정보를 컴퓨터로 해석하는 시스템은 GIS이다

WPAN
무선을 이용하는 개인 영역 네트워크
[구성] 무선 + 개인 영역 + 근거리
[의미] 개인 주변 기기들을 무선으로 연결하는 소규모 네트워크
[치트키] "W 무선 + PAN 개인 영역 = 내 주변 무선망"
[예문] 개인 영역에서 무선으로 기기를 연결하는 네트워크는 WPAN이다

비트로커(BitLocker)
드라이브를 암호화하는 보안 기능으로 기본적으로 AES 128bit 암호화를 사용하며 USB나 외장하드도 암호화 가능
[구성] 드라이브 암호화 + AES 128bit
[의미] 분실·도난 시 저장 데이터의 유출을 막는 디스크 암호화 기능
[치트키] "비트(데이터)를 자물쇠(Locker)로 잠근다"
[예문] 드라이브 전체를 암호화하는 윈도우 보안 기능은 비트로커이다

유닉스(UNIX)
대부분 C 언어로 작성되고 트리 구조의 파일 시스템을 갖는 다중 사용자 멀티태스킹 운영체제
[구성] C 언어 + 트리 구조 파일 시스템 + 다중 사용자 + 멀티태스킹
[의미] 이식성이 좋고 안정적인 운영체제로 서버 환경에서 널리 쓰임
[치트키] "유닉스 = C로 만든 트리 구조의 멀티 OS"
[예문] 대부분 C 언어로 작성되고 트리 구조 파일 시스템을 갖는 운영체제는 유닉스이다
[헷갈리는 단어] 리눅스 - 유닉스는 상용 계열 중심, 리눅스는 오픈 소스

리눅스(Linux)
다중 사용자, 멀티태스킹, 다중 스레드를 지원하고 자유 소프트웨어와 오픈 소스로 개발되는 네트워크 운영체제
[구성] 오픈 소스 + 다중 사용자 + 멀티태스킹 + 다중 스레드
[의미] 무료로 사용·수정이 가능한 유닉스 계열 운영체제
[치트키] "리눅스 = 공개된 유닉스 사촌"
[예문] 오픈 소스로 개발되는 다중 사용자 네트워크 운영체제는 리눅스이다

베이스라인(Baseline)
개발 각 단계의 산출물을 검토·평가·조정하여 변화를 통제하는 시점의 기준
[구성] 정식 승인된 산출물 + 변경 통제 기준
[의미] 형상 관리에서 변경을 통제하는 대표적인 기준점
[치트키] "베이스라인 = 여기서부터는 함부로 못 바꾸는 기준선"
[예문] 형상 관리에서 변경 통제의 기준이 되는 승인된 산출물 시점은 베이스라인이다

쉘(Shell)
유닉스 시스템에서 명령어 해석기로, 사용자의 명령어를 인식하여 필요한 프로그램을 호출하고 수행하는 기능
[구성] 사용자 명령 → 쉘 → 커널
[의미] 사용자와 커널 사이의 인터페이스 역할
[치트키] "쉘 = 조개껍데기, 커널을 감싸는 명령 해석기"
[예문] 사용자의 명령어를 해석하여 실행하는 유닉스의 명령어 해석기는 쉘이다

가상화
컴퓨터 자원의 추상화를 의미하는 용어
[구성] 물리 자원 → 추상화 → 논리 자원
[의미] 하나의 물리 자원을 여러 개처럼, 또는 여러 자원을 하나처럼 사용
[치트키] "가상화 = 물리 자원을 추상화해서 나눠 쓴다"
[예문] 컴퓨터 자원을 추상화하여 효율적으로 사용하는 기술은 가상화이다

튜닝(Tuning)
기존에 존재하는 데이터베이스의 성능 향상을 위해 데이터베이스 시스템이 최적화되도록 재조정하는 기법
[구성] 성능 분석 + 인덱스·SQL 조정
[의미] 이미 운영 중인 DB의 응답 속도와 자원 효율을 높이는 활동
[치트키] "튜닝 = 악기 조율하듯 DB를 최적화"
[예문] 운영 중인 DB의 성능을 개선하기 위해 재조정하는 기법은 튜닝이다

개체(Entity)
데이터베이스에 표현하려는 것으로 사람이 생각하는 개념이나 현실 세계의 대상체
[구성] 실재하는 대상 + 속성
[의미] 데이터로 관리하고자 하는 정보의 단위
[치트키] "엔티티 = 데이터베이스가 관리할 현실의 것"
[예문] 학생, 과목처럼 DB로 표현하려는 현실 세계의 대상을 개체라 한다

함수적 종속(Functional Dependency)
X의 값이 정해지면 Y의 값이 유일하게 결정되는 관계
[구성] X(결정자) → Y(종속자)
[의미] 정규화의 기준이 되는 속성 간의 관계
[구분] 종류별 의미
· 완전 함수적 종속: Y가 X 전체에 종속
· 부분 함수적 종속: Y가 X의 일부 속성에만 종속
· 이행 함수적 종속: X→Y, Y→Z이면 X→Z
[치트키] "결정자가 정해지면 종속자는 하나로 정해진다"
[예문] 학번이 정해지면 이름이 하나로 결정되므로 학번과 이름은 함수적 종속 관계이다

트랜잭션
데이터베이스에서 하나의 논리적 기능을 수행하기 위한 작업 단위
[구성] 여러 연산의 묶음 + ACID 특성
[의미] 모두 성공하거나 모두 취소되어야 하는 업무 처리 단위
[구분] TCL 명령어
· COMMIT: 확정
· ROLLBACK: 취소
· SAVEPOINT: 저장점
[치트키] "트랜잭션 = 쪼갤 수 없는 한 덩어리 업무"
[예문] 계좌이체처럼 출금과 입금을 하나의 작업으로 묶은 단위는 트랜잭션이다

트랜잭션 상태
트랜잭션이 실행되면서 거치는 상태 변화
[구성] 활동 → 부분 완료 → 완료 / 실패 → 철회
[의미] 정상 종료와 오류 시 취소 경로로 구분
[구분] 상태별 의미
· 활동(Active): 실행 중
· 부분 완료(Partially Committed): 마지막 연산까지 수행했으나 아직 COMMIT되지 않음
· 완료(Committed): 성공적으로 종료되어 확정
· 실패(Failed): 오류로 중단
· 철회(Aborted): ROLLBACK으로 취소되어 시작 전 상태로 복귀
[치트키] "활동 → 부분완료 → (성공)완료 / (실패)철회"
[예문] 마지막 연산은 끝났지만 아직 COMMIT되지 않은 상태는 부분 완료이다

매시업(Mashup)
웹에서 제공하는 정보 및 서비스를 융합하여 새로운 소프트웨어나 서비스, 데이터베이스 등을 만드는 기술
[구성] 여러 웹 서비스 + 결합 + 새로운 서비스
[의미] 공개 API를 조합해 새로운 가치를 만듦
[치트키] "매시업 = 여러 서비스를 한 그릇에 섞기"
[예문] 지도 API와 맛집 정보를 결합해 새로운 서비스를 만드는 기술은 매시업이다

요구사항 검토 기법
작성된 요구사항 명세서를 검토하는 방법
[구성] 피어 리뷰 + 워크 스루 + 인스펙션 + 프로토타이핑
[의미] 결함을 조기에 발견하고 요구사항을 확정
[구분] 기법별 의미
· 피어 리뷰: 동료 간 상호 리뷰
· 워크 스루: 요구사항 명세서를 미리 배포해 사전 검토
· 인스펙션: 명세 작성자를 제외한 검토 전문가들이 명세서를 확인
· 프로토타이핑: 견본품으로 최종 결과를 예측
[치트키] "인스펙션은 작성자 빼고 전문가만"
[예문] 명세 작성자를 제외한 전문가들이 명세서를 확인하는 검토 방법은 인스펙션이다

미들웨어 유형
서로 다른 시스템 사이의 통신과 데이터 교환을 중개하는 미들웨어의 종류
[구성] DB + RPC + MOM + TP-Monitor + ORB + WAS
[의미] 중개 방식에 따라 구분
[구분] 유형별 의미
· DB: 데이터베이스 접근을 중개
· RPC: 원격 프로시저 호출
· MOM: 메시지 지향 미들웨어, 메시지 큐 기반
· TP-Monitor: 트랜잭션 처리를 감시하고 관리
· ORB: 객체 요청 브로커, 분산 객체 간 통신
· WAS: 웹 애플리케이션 서버
[치트키] "DB·RPC·MOM·TP·ORB·WAS = 6가지"
[예문] 메시지 큐를 이용해 비동기 메시지를 전달하는 미들웨어는 MOM이다

화이트박스 테스트
프로그램 내부 구조와 논리 경로를 보고 수행하는 구조 기반 테스트
[구성] 기초 경로 테스트 + 제어 흐름 커버리지 + 루프 테스트 + 데이터 흐름 테스트
[의미] 내부 로직을 알고 모든 경로와 조건을 확인
[구분] 커버리지 종류
· 구문 커버리지: 모든 문장을 1회 이상 실행
· 결정 커버리지: 모든 분기의 참과 거짓을 1회 이상
· 조건 커버리지: 각 조건식의 참과 거짓
· 조건-결정 커버리지: 조건과 결정 모두
· 다중 조건 커버리지: 모든 조건 조합
[치트키] "화이트박스 = 속이 훤히 보이는 상자"
[예문] 내부 로직과 경로를 보며 수행하는 테스트는 화이트박스 테스트이다
[헷갈리는 단어] 블랙박스 테스트 - 화이트박스는 내부 구조, 블랙박스는 입출력 명세

검증(Verification)과 확인(Validation)
소프트웨어 품질을 확인하는 두 가지 관점
[구성] 검증: 제품을 올바르게 만들고 있는가 + 확인: 올바른 제품을 만들었는가
[의미] 개발 과정과 결과물을 서로 다른 관점에서 점검
[구분] 관점별 차이
· 검증: 개발자 관점, 과정 중심
· 확인: 사용자 관점, 결과 중심
[치트키] "검증은 만드는 과정, 확인은 만든 결과"
[예문] 사용자 관점에서 올바른 제품을 만들었는지 점검하는 활동은 확인이다

오버로딩과 오버라이딩
객체지향에서 메서드를 다형성으로 활용하는 두 가지 방법
[구성] 오버로딩(Overloading) + 오버라이딩(Overriding)
[의미] 같은 이름의 메서드를 다른 방식으로 정의
[구분] 차이
· 오버로딩: 같은 이름, 다른 매개변수 (한 클래스 내)
· 오버라이딩: 상속받은 메서드를 재정의 (상위와 하위 클래스 사이)
[치트키] "로딩은 매개변수를 달리 싣고, 라이딩은 부모 것을 타고 덮어쓴다"
[예문] 상위 클래스의 메서드를 하위 클래스에서 재정의하는 것은 오버라이딩이다

프로세스 상태 전이
프로세스가 생성되어 종료되기까지 거치는 상태 변화
[구성] 생성 → 준비 → 실행 → 대기 → 종료
[의미] CPU 할당과 입출력 대기에 따라 상태가 바뀜
[구분] 전이 용어
· 디스패치: 준비 상태에서 실행 상태로 전이
· 대기: 입출력 등을 기다리는 상태
[치트키] "준비실 → 실행 → (입출력) 대기 → 다시 준비"
[예문] CPU를 할당받아 준비 상태에서 실행 상태로 바뀌는 것은 디스패치이다

프로세스와 스레드
실행 중인 프로그램의 단위와 그 안의 실행 흐름 단위
[구성] 프로세스 + 스레드 + PCB
[의미] 자원 할당 단위와 스케줄링 단위를 구분
[구분] 개념별 의미
· 프로세스: 실행 중인 프로그램, 자원 할당 단위
· 스레드: 프로세스 내 실행 흐름 단위, 스케줄링 단위, 자원 공유
· PCB: 프로세스 상태와 정보를 저장하는 구조
[치트키] "프로세스는 집, 스레드는 그 안의 거주자"
[예문] 프로세스 내에서 자원을 공유하며 실행되는 흐름 단위는 스레드이다

TCP/IP 4계층
인터넷 통신에 사용되는 4계층 모델
[구성] 응용 → 전송 → 인터넷 → 네트워크 액세스
[의미] OSI 7계층을 4계층으로 단순화
[구분] OSI와의 대응
· 응용 = OSI 5·6·7계층
· 전송 = OSI 4계층
· 인터넷 = OSI 3계층
· 네트워크 액세스 = OSI 1·2계층
[치트키] "응전인네 = 응용 전송 인터넷 네트워크"
[예문] TCP/IP 모델에서 OSI의 3계층에 해당하는 계층은 인터넷 계층이다

서브넷 마스크
IP 주소에서 네트워크부와 호스트부를 구분하는 값
[구성] 네트워크 비트 1 + 호스트 비트 0
[의미] 네트워크 범위를 나누고 호스트 수를 결정
[구분] 예시
· 255.255.255.0 = /24
· 사설 IP 대역: 10.x, 172.16~31.x, 192.168.x (NAT로 공인 IP 변환)
[치트키] "마스크 1의 개수 = 슬래시 뒤 숫자"
[예문] 서브넷 마스크 255.255.255.0은 /24로 표기한다

공개키 암호화 활용
비대칭키 암호에서 어떤 키로 암호화하느냐에 따라 얻는 보안 속성이 달라지는 방식
[구성] 공개키 암호화 → 개인키 복호화 / 개인키 암호화 → 공개키 복호화
[의미] 기밀성과 인증·부인 방지(전자서명)를 구분해 구현
[구분] 활용
· 공개키로 암호화 → 개인키로 복호화: 기밀성
· 개인키로 암호화 → 공개키로 복호화: 인증, 부인 방지(전자서명)
[치트키] "남에게 비밀 보낼 땐 상대 공개키, 내가 서명할 땐 내 개인키"
[예문] 공개키로 암호화하면 보장되는 보안 요소는 기밀성이다

병행제어 기법
여러 트랜잭션이 동시에 실행될 때 데이터 일관성을 유지하기 위한 기법
[구성] 로킹 + 타임스탬프 순서 + 낙관적 검증 + 다중 버전(MVCC)
[의미] 갱신 분실, 모순성, 연쇄 복귀를 방지
[구분] 기법별 의미
· 로킹: 데이터에 잠금을 거는 방식
· 타임스탬프 순서: 트랜잭션 시작 시간 순서로 처리
· 낙관적 검증: 충돌이 드물다고 가정하고 실행 후 검증
· 다중 버전(MVCC): 여러 버전의 데이터를 유지하여 읽기와 쓰기 충돌을 줄임
[치트키] "잠그거나(로킹), 시간순(타임스탬프), 나중에 검증(낙관), 버전 여러 개(MVCC)"
[예문] 데이터의 여러 버전을 유지하여 읽기 충돌을 줄이는 병행제어 기법은 MVCC이다

세션 하이재킹
인증된 세션을 가로채어 사용자인 것처럼 시스템에 접근하는 공격
[구성] 세션 ID 탈취 → 정상 사용자로 위장
[의미] 로그인 이후의 통신 세션을 탈취하는 네트워크 공격
[치트키] "하이재킹 = 이미 로그인된 세션을 납치"
[예문] 인증된 세션을 가로채는 공격은 세션 하이재킹이다

MITM(중간자 공격)
통신 사이에 끼어들어 내용을 가로채거나 변조하는 공격
[구성] 사용자 ↔ 공격자 ↔ 서버
[의미] 양쪽 모두 정상 통신으로 오인하게 만듦
[치트키] "중간에 끼어 몰래 엿보고 바꾼다"
[예문] 두 시스템의 통신 사이에 끼어들어 정보를 가로채는 공격은 중간자 공격이다

피싱·파밍·스미싱
사용자를 속여 정보를 탈취하는 사회공학 공격
[구성] 피싱 + 파밍 + 스미싱 + 스피어 피싱
[의미] 기술이 아닌 사람의 심리를 이용한 공격
[구분] 공격별 의미
· 피싱: 가짜 사이트나 메일로 개인정보를 낚음
· 파밍: DNS 등을 변조해 정상 주소로 접속해도 가짜 사이트로 유도
· 스미싱: 문자 메시지로 악성 링크를 보내 유도
· 스피어 피싱: 특정 대상을 겨냥한 맞춤형 피싱
[치트키] "피싱은 낚시, 파밍은 농장(주소 오염), 스미싱은 문자(SMS)"
[예문] 문자 메시지를 이용해 악성 링크로 유도하는 공격은 스미싱이다

악성코드 종류
사용자의 시스템에 해를 끼치는 악의적인 소프트웨어
[구성] 바이러스 + 웜 + 트로이 목마 + 랜섬웨어 + 백도어 + 루트킷 + APT
[의미] 감염 방식과 목적에 따라 구분
[구분] 종류별 의미
· 웜: 자기 복제 후 네트워크로 전파
· 트로이 목마: 정상 프로그램으로 위장
· 랜섬웨어: 파일을 암호화한 뒤 금전을 요구
· 백도어: 정상 인증 없이 접근할 수 있는 비밀 통로
· 루트킷: 침입 흔적을 숨기고 관리자 권한을 유지
[치트키] "웜은 퍼지고, 트로이는 위장하고, 랜섬은 인질"
[예문] 파일을 암호화한 후 금전을 요구하는 악성코드는 랜섬웨어이다

제로 트러스트
내부와 외부를 구분하지 않고 모든 접근을 신뢰하지 않으며 항상 검증하는 보안 모델
[구성] 지속적 인증 + 최소 권한 + 접근 검증
[의미] 경계 기반 보안의 한계를 보완
[치트키] "제로 트러스트 = 아무도 믿지 말고 매번 확인"
[예문] 모든 접근을 신뢰하지 않고 항상 검증하는 보안 모델은 제로 트러스트이다

MQTT
IoT 환경에서 사용되는 경량 메시지 전송 프로토콜
[구성] 발행(Publish) + 구독(Subscribe) + 브로커
[의미] 낮은 대역폭과 제한된 자원을 가진 기기에 적합
[치트키] "MQTT = IoT용 가벼운 발행-구독 우체국"
[예문] 사물 인터넷에서 경량으로 메시지를 주고받는 프로토콜은 MQTT이다

디지털 트윈
현실 세계의 사물이나 시스템을 가상 세계에 똑같이 구현해 시뮬레이션하는 기술
[구성] 현실 사물 + 센서 데이터 + 가상 모델
[의미] 시뮬레이션으로 문제를 미리 예측하고 최적화
[치트키] "트윈 = 쌍둥이, 가상 세계의 쌍둥이"
[예문] 현실의 공장을 가상 모델로 만들어 시뮬레이션하는 기술은 디지털 트윈이다

그레이웨어
악성코드는 아니지만 사용자에게 불편이나 피해를 줄 수 있는 소프트웨어
[구성] 광고 + 정보 수집 + 성능 저하
[의미] 악성과 정상의 중간(회색) 영역에 있는 소프트웨어
[치트키] "그레이웨어 = 검지도 희지도 않은 회색 소프트웨어"
[예문] 악성코드는 아니지만 광고 노출 등 불편을 주는 소프트웨어는 그레이웨어이다

형상 관리 도구
소프트웨어 변경 이력과 버전을 관리하는 도구
[구성] Git + SVN + CVS
[의미] 협업 개발 시 변경 사항을 추적하고 충돌을 해결
[구분] 도구와 용어
· Git: 분산형 버전 관리
· SVN: 중앙집중형
· CVS: 초기 중앙집중형 도구
· 용어: 커밋, 체크아웃, 체크인, 브랜치, 머지, 충돌
[치트키] "Git은 분산, SVN은 중앙"
[예문] 분산형 버전 관리 도구는 Git이다

접근 제어자(Java)
클래스 멤버의 접근 범위를 제한하는 키워드
[구성] public > protected > default > private
[의미] 정보 은닉을 위해 접근 가능 범위를 단계별로 제한
[구분] 범위별 의미
· public: 어디서나 접근
· protected: 같은 패키지와 자식 클래스
· default: 같은 패키지
· private: 같은 클래스 내부
[치트키] "공개 보호 기본 비공개 순으로 좁아진다"
[예문] 같은 클래스 내부에서만 접근 가능한 접근 제어자는 private이다

예외 처리
프로그램 실행 중 발생하는 오류를 처리하여 비정상 종료를 막는 구문
[구성] try + catch(except) + finally
[의미] 오류 발생 시에도 프로그램이 안정적으로 동작하도록 함
[구분] 언어별 표기
· Java: try, catch, finally
· Python: try, except, else, finally
· finally는 예외 발생 여부와 관계없이 항상 실행
[치트키] "try 해보고, 문제면 catch, 어쨌든 finally"
[예문] 예외 발생 여부와 관계없이 항상 실행되는 블록은 finally이다

정규화
데이터베이스의 논리적 설계 단계에서 이상 현상과 함수 종속으로 인한 문제를 해결하기 위해 릴레이션을 분해하는 과정
[구성] 1NF → 2NF → 3NF → BCNF → 4NF → 5NF
[의미] 중복을 줄이고 무결성을 높이는 설계 기법
[치트키] "정규화 = 이상 현상을 막기 위해 쪼개기"
[예문] 릴레이션을 분해하여 이상 현상을 제거하는 과정은 정규화이다
[헷갈리는 단어] 반정규화 - 정규화는 중복 제거, 반정규화는 성능을 위해 중복 허용

스키마(Schema)
데이터베이스 설계 단계를 의미하며 데이터베이스를 구성하는 전체적인 구조와 제약 조건
[구성] 외부 스키마 + 개념 스키마 + 내부 스키마
[의미] 데이터의 구조와 규칙을 정의한 설계도
[치트키] "스키마 = DB의 설계도"
[예문] 데이터베이스의 전체 구조와 제약 조건을 정의한 것은 스키마이다

VLAN
물리적 구성과 관계없이 논리적으로 네트워크를 분리하는 가상 LAN
[구성] 스위치 설정 + 논리적 분리
[의미] 같은 장비에서도 네트워크를 나눠 보안과 관리 효율을 높임
[치트키] "VLAN = 선은 하나, 네트워크는 여러 개"
[예문] 물리적 연결과 상관없이 논리적으로 네트워크를 분리하는 기술은 VLAN이다

플랫폼
어플리케이션을 구동시키기 위해 필요한 하드웨어와 소프트웨어의 결합
[구성] 하드웨어 + 운영체제 + 소프트웨어
[의미] 응용 프로그램이 동작하는 기반 환경
[치트키] "플랫폼 = 응용이 올라타는 승강장"
[예문] 응용 프로그램이 구동되는 하드웨어와 소프트웨어의 결합을 플랫폼이라 한다

CSS
HTML과 함께 웹을 구성하는 기본 요소로, 색상, 크기, 이미지 위치, 배치 등 웹 문서의 디자인 요소를 담당하는 언어
[구성] 스타일 + 레이아웃 + 디자인
[의미] 구조(HTML)와 표현(CSS)을 분리
[치트키] "HTML은 뼈대, CSS는 옷"
[예문] 웹 문서의 색상과 배치를 담당하는 언어는 CSS이다

AAL
ATM 계층 중 패킷을 작은 조각인 셀로 전송하고 다시 조립하여 원래 데이터로 복원하는 역할을 담당하는 계층
[구성] 분할 + 셀 전송 + 재조립
[의미] 상위 계층 데이터를 ATM 셀 단위로 적응시키는 계층
[치트키] "AAL = ATM 적응(Adaptation) 계층, 쪼갰다 다시 붙이기"
[예문] 패킷을 셀로 분할하고 다시 조립하는 ATM 계층은 AAL이다
