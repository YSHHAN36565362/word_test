데이터 3법
개인정보 관련 3개 법률을 묶어 부르는 명칭 (암기: 개정신)
[구성] 개인정보보호법 + 정보통신망법 + 신용정보법
[의미] 2020년 개정으로 개인정보 활용과 보호의 균형을 맞추기 위해 마련된 3개 법률의 통칭
[구분] 주요 개정 특징 4가지
· 가명정보 개념 도입 → 가명처리 시 동의 없이 활용 가능
· 개인정보보호 거버넌스 체계 효율화
· 개인정보처리자 책임 강화(사용자의 책임 아님, 처리자의 책임)
· 개인정보 판단기준 명확화
[치트키] "개인정보보호법(개) + 정보통신망법(정) + 신용정보법(신) = 개정신, 셋이 합쳐서 데이터3법"
[예문] 데이터 3법 개정으로 가명정보는 통계작성·연구 목적일 경우 동의 없이 활용할 수 있게 되었다

개인정보 비식별 조치 가이드라인
개인정보를 비식별화하는 4단계 절차
[구성] 사전 검토 → 비식별 조치 → 적정성 평가 → 사후 관리
[의미] 개인정보를 안전하게 활용하기 위해 순서대로 거쳐야 하는 4단계 프로세스
[구분] 비식별 조치 기술: 데이터 마스킹, 가명처리, 총계처리(합·평균), 범주화(예: 34세→30~40세)
[치트키] "사전에 검토하고(사전검토) → 비식별로 처리하고(비식별조치) → 잘 됐나 평가하고(적정성평가) → 계속 관리한다(사후관리)"
[예문] 비식별 조치가 끝난 데이터는 적정성 평가를 거쳐야 실제 활용이 가능하다

k-익명성 / l-다양성 / t-근접성
프라이버시 보호 모델 3단계 (점점 강화되는 순서)
[구성] k-익명성(k-anonymity) → l-다양성(l-diversity) → t-근접성(t-closeness)
[의미]
· k-익명성: 동일한 값을 가진 레코드가 최소 k개 이상 존재하도록 하여 일정 수준 이상 비식별
· l-다양성: k-익명성의 한계(민감 정보가 그룹 내에서 동질적일 수 있음)를 보완, 민감 정보의 다양성을 높임
· t-근접성: l-다양성의 한계를 보완, 민감 정보의 분포를 전체 데이터의 분포와 유사하게 만들어(분포 차이를 낮춤) 추론 공격 방지
[구분] 세 모델은 순서대로 앞선 모델의 약점을 보완하며 발전한 것 (k→l→t 순서 기억)
[치트키] "k는 숫자로 묶고(k명 이상), l은 다양하게(diversity), t는 분포를 비슷하게(근접)"
[예문] k-익명성만으로는 그룹 내 민감정보가 모두 같을 수 있어 이를 보완한 것이 l-다양성이다

연결 공격 (Linkage Attack)
공개된 데이터와 다른 데이터를 결합해 개인을 재식별하는 공격 기법
[구성] 연결(Linkage) + 공격(Attack)
[의미] 활용 정보의 일부가 다른 공개되어 있는 정보와 결합하여 개인을 식별해내는 공격. 준식별자(성별, 나이, 우편번호 등)를 조합해 특정 개인을 추론
[구분] 비식별 조치를 했더라도, 여러 공개 데이터셋을 조합하면 개인이 재식별될 위험이 있음 → 이를 방지하기 위해 k-익명성 등의 모델이 필요
[치트키] "따로 보면 안 보이는데, 연결(링크)해서 보면 딱 걸리는 공격"
[예문] 익명화된 진료기록도 선거인명부와 결합하면 개인을 특정할 수 있는데 이것이 연결 공격이다

KDD 분석 방법론
데이터마이닝 중심의 5단계 분석 방법론
[구성] 데이터 선택(Selection) → 전처리(Preprocessing) → 변환(Transformation) → 마이닝(Data Mining) → 결과 평가(Interpretation/Evaluation)
[의미] 지식 발견(Knowledge Discovery in Databases)을 위한 절차. 데이터를 고른 뒤 전처리·변환을 거쳐 마이닝하고 최종 평가하는 순서
[구분] CRISP-DM과 순서가 다르므로 혼동 주의 (KDD는 "선택"부터 시작, CRISP-DM은 "업무 이해"부터 시작)
[치트키] "선택해서(고르고) 전처리하고 변환해서 마이닝(캐내고) 평가한다" (선-전-변-마-평)
[예문] KDD 방법론은 데이터 선택 단계부터 시작해 마이닝을 거쳐 결과를 평가하는 순서로 진행된다

CRISP-DM 분석 방법론
가장 널리 쓰이는 6단계 데이터마이닝 표준 방법론
[구성] 업무 이해 → 데이터 이해 → 데이터 준비 → 모델링 → 평가 → 전개
[의미] Cross Industry Standard Process for Data Mining의 약자. 업무를 먼저 이해하고 데이터를 이해한 뒤 준비하는 순서
[구분] 기출 함정: "모델링 단계"에서는 '모델 평가'를 수행하고, "평가 단계"에서는 '모델 적용성 평가'를 수행함 → "평가 단계에서 모델 평가를 수행한다"는 지문은 틀림! (헷갈리기 쉬운 단골 함정)
[치트키] "업무 알고(업무이해) 데이터 알고(데이터이해) 준비하고(데이터준비) 모델 만들고(모델링) 평가하고(평가) 세상에 내놓는다(전개)"
[예문] CRISP-DM의 모델링 단계에서는 여러 모델을 만들고 성능을 비교하는 모델 평가가 이루어진다

SEMMA 분석 방법론
SAS사가 제안한 통계 중심의 5단계 분석 방법론
[구성] 샘플링(Sample) → 탐색(Explore) → 수정(Modify) → 모델링(Model) → 검증(Assess)
[의미] 통계적 데이터마이닝에 초점을 맞춘 방법론으로, KDD·CRISP-DM과 달리 "통계" 중심이라는 게 특징
[구분] KDD(선택-전처리-변환-마이닝-평가), CRISP-DM(업무-데이터-준비-모델링-평가-전개)과 단계 개수·순서가 다름을 구분해서 암기
[치트키] "샘플 뽑고(샘플링) 탐색하고 수정하고 모델링해서 검증한다" (샘-탐-수-모-검)
[예문] SEMMA는 SAS 소프트웨어 기반의 통계 중심 분석 방법론으로 샘플링부터 시작한다

빅데이터 분석 방법론 5단계 (PPADD)
분석 기획부터 평가·전개까지의 전체 프로세스 (암기: PPADD)
[구성] Planning(분석기획) → Preparing(데이터준비) → Analyzing(데이터분석) → Developing(시스템구현) → Deploying(평가 및 전개)
[의미]
· 분석기획: 비즈니스 이해 및 범위 설정(SOW 작성) / 프로젝트 정의 및 계획 수립(WBS 작성) / 프로젝트 위험계획 수립
· 데이터준비: 필요 데이터 정의 / 데이터 스토어 설계 / 데이터 수집 및 정합성 점검
· 데이터분석: 분석용 데이터 준비 / 텍스트 분석 / 탐색적 분석(EDA) / 모델링 / 모델 평가 및 검증
· 시스템구현: 설계 및 구현 / 시스템 테스트 및 운영
· 평가및전개: 모델 발전계획 수립 / 프로젝트 평가 및 보고
[구분] "분석기획" 단계는 기획 단계이므로, 세부적인 실무 항목(모델링, 텍스트분석 등)이 함께 나오면 그것이 오답
[치트키] "PPADD = Plan(계획)-Prepare(준비)-Analyze(분석)-Develop(개발)-Deploy(배포)"
[예문] 분석 기획 단계에서는 SOW와 WBS를 작성하고, 데이터 분석 단계에서 비로소 모델링을 수행한다

분석 방법론 모델 (폭포수/나선형/프로토타입/애자일)
분석 프로젝트 진행 방식에 따른 4가지 모델
[구성] 폭포수 모델(Top-Down) / 나선형 모델 / 프로토타입 모델 / 애자일
[의미]
· 폭포수: 위에서 아래로 순차 진행(Top-Down), 이전 단계로 되돌아가지 않음
· 나선형: 점진적으로 완성해가며 위험요소 제거에 초점
· 프로토타입: 시제품(프로토타입)을 우선 개발한 후 보완
· 애자일: 일정 주기(스프린트)마다 프로토타입을 끊임없이 수정하여 고객 니즈를 반영
[구분] 폭포수는 "직선적"이고 애자일은 "반복적"이라는 게 가장 큰 차이
[치트키] "폭포수(위→아래로 한번에), 나선형(빙글빙글 돌며 완성), 프로토타입(일단 만들고 고침), 애자일(짧은 주기로 계속 수정)"
[예문] 스타트업 개발팀은 고객 피드백을 빠르게 반영하기 위해 애자일 방법론을 채택했다

ROI 관점 우선순위 매트릭스 (시급성 vs 난이도)
분석 과제의 우선순위를 정하는 2x2 매트릭스 (투자대비수익률 관점)
[구성] 시급성(비즈니스 관점, Value) / 난이도(투자비용 관점, 3V-다양성/속도/규모)
[의미] 4개 사분면으로 나눠 우선순위를 정함. 가로축=시급성(현재↔미래), 세로축=난이도(쉬움↔어려움)
[구분] 우선순위 결정 원칙
· 시급성을 중요시할 때: 3사분면(현재+쉬움) → 4사분면(미래+쉬움) → 2사분면(미래+어려움)
· 난이도를 중요시할 때: 3사분면(현재+쉬움) → 1사분면(현재+어려움) → 2사분면(미래+어려움)
[치트키] "시급하고 쉬운 것부터(3사분면)! 그 다음은 관점에 따라 시급성이냐 난이도냐로 갈림"
[예문] 투자 대비 빠른 성과가 필요한 조직은 시급성이 높고 난이도가 낮은 3사분면 과제부터 착수한다

분석 거버넌스 & 데이터 거버넌스
빅데이터 분석/데이터 관리를 위한 표준 체계 (암기: 원조프)
[구성] 분석 거버넌스: 조직/프로세스/시스템/데이터/분석 교육 및 마인드 육성체계
데이터 거버넌스: 원칙(Principle) + 조직(Organization) + 프로세스(Process) = 원조프
[의미]
· 분석 거버넌스: 조직 전체가 분석 역량을 지속적으로 유지·발전시키기 위한 종합 체계
· 데이터 거버넌스: 전사 차원에서 데이터에 대해 표준화된 관리 체계를 수립하는 것 (원칙-조직-프로세스 3요소)
[구분] "분석" 거버넌스와 "데이터" 거버넌스의 구성요소가 다름에 주의 (분석은 5가지, 데이터는 3가지-원조프)
[치트키] "데이터 거버넌스 = 원칙 세우고(원) 조직 만들고(조) 프로세스 정한다(프) = 원조프"
[예문] 데이터 거버넌스는 원칙, 조직, 프로세스라는 3가지 구성요소를 기반으로 전사적 데이터 관리 체계를 수립한다

데이터 분석 수준 진단 (준비도 & 성숙도)
기업의 데이터 분석 역량을 진단하는 2가지 축 (암기: 도준정확)
[구성] 분석 준비도(가로축) × 분석 성숙도(세로축) → 4가지 유형
[의미]
· 분석 준비도: 분석업무 파악, 분석 인력 및 조직, 기법, 데이터, 문화, 인프라 등 "역량과 기반"이 갖춰졌는지
· 분석 성숙도: CMMI 모델 기반, 비즈니스/조직·역량/IT 부문 관점에서 "얼마나 조직에 정착되었는지" (도입-활용-확산-최적화 단계로 구분)
[구분] 4가지 유형
· 준비형: 준비도 낮음, 성숙도 낮음 → 환경·인프라 정비 중
· 도입형: 준비도 낮음, 성숙도 높음 → 분석을 이제 막 시작
· 정착형: 준비도 높음, 성숙도 낮음 → 분석 업무가 정례화됨
· 확산형: 준비도 높음, 성숙도 높음 → 전사 차원으로 확대 적용
[치트키] "도준정확 = 도입형/준비형/정착형/확산형, 준비도는 기반, 성숙도는 정착 정도"
[예문] 분석 인프라는 갖췄지만 아직 조직 전반에 분석 문화가 정착되지 않은 기업은 준비형에 해당할 수 있다

ETL / 스쿱(SQOOP) / 웹 크롤링
데이터 수집 기술 3가지 (전통적 수집 방식부터 최신까지)
[구성] ETL(Extract-Transform-Load) / 스쿱(SQOOP) / 웹 크롤링(Crawling)
[의미]
· ETL: 추출-변환-적재의 전통적 수집 방식, 예) DB에서 DW로 데이터 옮기기
· 스쿱: RDBMS와 하둡 간의 대용량 데이터 전송 도구
· 웹 크롤링: 웹사이트에서 데이터를 자동으로 수집
[구분] ETL은 "정형 데이터 간 이동", 스쿱은 "정형(RDBMS)↔분산(하둡) 간 이동"에 특화된 도구라는 차이
[치트키] "ETL = 추출(E)해서 변환(T)하고 적재(L), 스쿱 = RDBMS와 하둡을 이어주는 다리"
[예문] 기존 관계형 데이터베이스의 데이터를 하둡 클러스터로 옮길 때는 스쿱을 활용한다

데이터 마트(DM) vs 데이터 레이크
데이터 웨어하우스와 관련된 2가지 저장 개념
[구성] 데이터 마트(Data Mart) / 데이터 레이크(Data Lake)
[의미]
· 데이터 마트: 데이터 웨어하우스의 한 분야, 특정 목적을 위한 작은 규모 DW. 분석이 편하도록 미리 요약한 정보를 모아둔 곳(요약변수가 기본 변수)
· 데이터 레이크: 다양한 유형의 대량 데이터를 원시(RAW) 형태 그대로 저장, 비정형 데이터도 저장 가능, 하둡과 연계
[구분] 데이터 마트는 "가공·요약된" 데이터, 데이터 레이크는 "가공 전 원시" 데이터라는 게 핵심 차이
[치트키] "마트(Mart)는 소분해서 파는 작은 가게(요약된 데이터), 레이크(Lake)는 있는 그대로의 큰 호수(원시 데이터)"
[예문] 마케팅팀 전용으로 요약된 매출 데이터를 모아둔 것은 데이터 마트, 모든 로그를 원본 그대로 저장한 것은 데이터 레이크다

병렬 DBMS
대규모 데이터를 병렬로 처리하는 관계형 데이터베이스 시스템
[구성] 병렬(Parallel) + DBMS(Database Management System)
[의미] 대규모 처리를 위해 데이터를 일정 단위로 나눠 병렬로 처리하는 시스템. 빠른 처리 가능, 시스템 용량 확장이 용이함
[구분] 기출 함정: 병렬 DBMS는 "중복 저장"과는 직접적인 관련이 없음(중복 저장은 HDFS의 복제 개념과 헷갈리지 말 것)
[치트키] "병렬 DBMS = 데이터를 나눠서 여러 대가 동시에 처리, 그래서 빠르고 확장 잘 됨"
[예문] 대용량 정형 데이터를 빠르게 처리하기 위해 병렬 DBMS 구조를 도입했다

빅데이터 조직 인력방안 3구조 표 비교
집중/기능/분산 구조를 수직·수평 업무활동 관점에서 비교
[구성] 수직 업무활동(우선순위 결정) / 수평 업무활동(프로세스별 업무 배분)
[의미]
· 집중구조: 별도 전담부서, 우선순위 지정 가능
· 기능구조: 해당 부서에서 분석, 전사적 분석 어려움
· 분산구조: 각 부서로 배치, 베스트 프랙티스 공유
[구분] "수직 업무활동"은 우선순위를 결정하는 활동, "수평 업무활동"은 프로세스별로 업무를 배분하는 활동 → 조직구조 유형과 짝지어 이해
[치트키] "집중은 힘을 한곳에 모으고(수직적), 분산은 여러 곳에 퍼뜨림(수평적)"
[예문] 우선순위를 빠르게 결정해야 하는 조직은 집중 구조가 유리하다

데이터 단위 & DIKW 피라미드
데이터 용량 단위 체계와 지식 계층 구조
[구성] 데이터 단위: KB < MB < GB < TB < PB < EB < ZB < YB (1MB=2^10KB)
DIKW: Data(데이터) → Information(정보) → Knowledge(지식) → Wisdom(지혜)
[의미]
· 데이터: 객관적 사실 (예: 제품X가 사이트A에서 10,000원)
· 정보: 데이터 간 연관관계 & 의미 도출 (예: 사이트B가 더 싸므로 거기서 구매)
· 지식: 정보를 구조화 & 일반화 (예: 사이트B가 항상 더 싸다고 계획)
· 지혜: 깊은 이해 → 창의적 아이디어 (예: 사이트B의 타 제품도 더 쌀 것으로 예측)
[구분] 데이터→정보 단계에서 "연관관계와 의미"가 처음 부여됨. 이후 지식은 "일반화", 지혜는 "창의적 확장"이 핵심 키워드
[치트키] "DIKW = 사실(D)에서 의미(I)를 찾고, 구조화(K)해서, 지혜(W)로 응용"
[예문] 여러 매장의 판매 데이터를 분석해 "이 매장이 항상 더 싸다"는 지식을 도출하고, 이를 다른 상품에도 적용해 예측하는 것이 지혜 단계다

암묵지 vs 형식지 (SECI 모델)
지식이 변환되는 4단계 프로세스 (암기: 공표연내)
[구성] 공통화(Socialization) → 표준화(Externalization) → 연결화(Combination) → 내연화(Internalization)
[의미]
· 공통화: 대화·상호작용으로 암묵지를 타인에게 알려줌
· 표준화: 문서화·매체화 (암묵지 → 형식지)
· 연결화: 형식지들을 상호 결합 (교재·매뉴얼에 새 지식 추가)
· 내연화: 행동·실천교육으로 형식지를 다시 암묵지로 습득
[구분] 암묵지(나만 아는 지식) ↔ 형식지(문서·매뉴얼로 형상화된 지식)의 순환 과정이 SECI 모델
[치트키] "공표연내 = 공유하고(공통화) 표준으로 만들고(표준화) 연결하고(연결화) 내 것으로 만든다(내연화)"
[예문] 숙련자의 노하우(암묵지)를 매뉴얼로 문서화하는 과정이 표준화(외부화) 단계다

빅데이터가 만들어내는 변화 (전후양상)
빅데이터 시대 이전과 이후의 패러다임 변화 4가지
[구성] 표본 → 전수조사 / 사전처리 → 사후처리 / 질 → 양 / 인과관계 → 상관관계
[의미] 기존에는 표본을 뽑아 분석했지만 빅데이터는 전체(전수)를 분석 가능해졌고, 데이터를 미리 정제(사전처리)하기보다 일단 모으고 나중에 처리(사후처리)하는 방식으로, 데이터의 질보다 양을 중시하고, 왜 그런지(인과관계)보다 무슨 상관이 있는지(상관관계)를 중시하는 방향으로 변화
[구분] 이 4가지는 "기존 통계 방식" vs "빅데이터 방식"을 대조하는 개념이므로 짝을 정확히 암기
[치트키] "표본에서 전수로, 사전에서 사후로, 질에서 양으로, 인과에서 상관으로 - 모두 화살표 방향이 오른쪽"
[예문] 빅데이터 시대에는 왜 그런 현상이 발생했는지보다 무엇과 상관관계가 있는지를 먼저 파악하는 경향이 있다

하둡(Hadoop)
여러 컴�터를 하나로 묶어 대용량 데이터를 처리하는 오픈소스 솔루션
[구성] Hadoop = 분산 파일 시스템(HDFS) + 분산 처리 프레임워크(MapReduce)
[의미] 저렴한 여러 대의 컴퓨터(서버)를 하나로 묶어 대용량 데이터를 저장하고 처리하는 오픈소스 프레임워크
[구분] R, Python은 "분석 언어"이고 하둡은 "분산 처리 인프라"라는 점에서 역할이 다름. JDBC·OLAP도 분석 도구지만 하둡과는 다른 카테고리
[치트키] "하둡 = 코끼리 로고, 컴퓨터 여러 대를 코끼리처럼 힘을 합쳐 큰 데이터를 처리"
[예문] 페타바이트급 로그 데이터를 분산 저장·처리하기 위해 하둡 클러스터를 구축했다
