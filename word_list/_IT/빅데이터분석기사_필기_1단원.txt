빅데이터의 3V + 확장V
빅데이터의 기본 특징을 나타내는 개념(Volume/Velocity/Variety + 확장 V들)
[구성] Volume(양) / Velocity(속도) / Variety(다양성) + Value(가치) / Veracity(신뢰성·정확성) / Validity(정확성) / Volatility(휘발성)
[의미] 빅데이터를 정의하는 핵심 특성들. 기본 3V에 추가 V가 계속 붙는 구조
[구분] 기출에서 자주 헷갈리는 포인트
· Volume = 데이터의 양이 크다 (O)
· Velocity = 데이터가 실시간으로 변한다/속도 (O)
· Variety = 데이터가 다양하다 (O)
· Veracity = 데이터의 "가치"를 반영한다 → 이건 오답! Veracity는 신뢰성/정확성이지 가치가 아님
· Value = 가치 (Veracity와 헷갈리지 말 것)
[치트키] "볼륨-벨로시티-버라이어티는 기본 3총사, 베러시티는 믿음(신뢰), 밸류는 돈(가치)"
[기출 포인트] "Veracity – 데이터의 가치를 반영한다"는 설명은 틀린 지문 (8회 기출 1번)
[예문] 빅데이터 3V는 Volume, Velocity, Variety이며 최근에는 Value와 Veracity가 추가로 강조된다

빅데이터 유형 (정형/반정형/비정형)
데이터를 구조적 관점에서 분류하는 3가지 유형
[구성] 정형(Structured) / 반정형(Semi-structured) / 비정형(Unstructured)
[의미]
· 정형: 스키마 O, 고정필드 O → RDBMS(Oracle, MS-SQL), 스프레드시트
· 반정형: 스키마 O, 메타데이터 O, 고정필드 X → XML, JSON, HTML, RSS, 웹/시스템 로그
· 비정형: 스키마 X, 메타데이터 X, 고정필드 X → 텍스트, 이미지, 동영상, 오디오, SNS
[구분] 기출 함정: "반정형 데이터는 구조나 형태를 유연하게 변경할 수 없다" → 틀림! 반정형은 유연하게 변경 가능한 게 특징
[구분] 거래 내역(Transaction) 데이터는 비정형이 아니라 정형/반정형에 가까움 (8회 기출 11번: "비정형 데이터로 옳지 않은 것" 정답이 거래내역)
[치트키] "정형은 틀에 딱! 반정형은 틀은 있는데 유연해! 비정형은 틀 자체가 없어!"
[예문] 로그 데이터는 XML, JSON 형태로 저장되는 대표적인 반정형 데이터다

집중형 vs 기능형 vs 분산형 조직구조
빅데이터 분석 조직 및 인력방안을 나타내는 3가지 구조 (암기: 집기분)
[구성] 집중 구조 / 기능 구조 / 분산 구조
[의미]
· 집중 구조: 별도 전담부서 설치, 전사적 우선순위 지정 가능, 표준화에 유리
· 기능 구조: 각 현업 부서에서 직접 분석(별도 분석조직 없음), 전사적 분석 어려움
· 분산 구조: 분석 조직의 인력을 각 부서로 배치, 베스트 프랙티스 공유
[구분] 기출 함정: "집중형 구조는 분석 결과를 현업 부서 업무에 가장 빠르게 적용할 수 있다" → 틀림! 이건 분산형/기능형의 장점. 집중형은 오히려 현업 부서 요청이 몰리면 병목현상 발생
[치트키] "집중= 한곳에 모아 전사표준, 기능=각자 부서에서, 분산=조직인력을 부서로 파견"
[기출 포인트] 집중형 특징 아닌 것 찾기 문제에서 "현업 업무 최속 적용"은 오답 선택지로 자주 등장

가명정보 vs 익명정보
개인정보 비식별 조치의 두 가지 결과물
[구성] 가명정보(假名情報) / 익명정보(匿名情報)
[의미]
· 가명정보: 일부 삭제·대체하여 특정 개인을 "알아볼 수 없지만", 추가 정보와 결합하면 재식별 가능한 정보
· 익명정보: 완전히 개인을 알아볼 수 없도록 처리, 결합해도 재식별 불가능(개인정보보호법 적용 X)
[구분] 가명정보는 통계작성, 과학적 연구, 공익적 기록보존 목적이면 "정보주체 동의 없이" 처리 가능 (개인정보처리자 재량)
[구분] 익명 처리는 "정보주체의 동의가 필요하다"는 설명은 틀림 → 익명처리는 개인 식별 자체가 불가능해서 동의 이슈가 발생하지 않음 (8회 기출 3번 오답 포인트)
[치트키] "가명은 가짜 이름표, 다시 붙이면 원상복구 가능! 익명은 이름표 자체가 없어서 복구 불가능!"
[예문] 연구 목적으로 가명처리된 정보는 정보주체의 동의 없이도 활용할 수 있다

총계처리
개인정보 비식별 조치 기술 중 하나, 그룹 단위로 합산·요약하는 방법
[구성] 총계(總計) + 처리(處理) = 데이터를 합계·평균 등으로 집단화
[의미] 개인정보를 특정 그룹 단위로 합산하여 요약함으로써 개인 식별을 불가능하게 만드는 비식별 조치
[구분] "서울 거주 30대 남성의 평균 소득" = 총계처리의 대표 예시
[구분] 기출 함정: "총계처리를 하면 데이터의 재현성이 높아져 항상 동일한 분석 결과가 나온다" → 틀림! 총계처리의 목적은 재현성이 아니라 개인 식별 방지
[치트키] "총계처리 = 다 합쳐서 뭉뚱그리기 → 개인은 안 보이고 평균/합계만 보임"
[기출 포인트] 개인정보 비식별 조치 4대 기술: 데이터 마스킹, 가명처리, 총계처리(합·평균), 범주화(34세→30~40세)

책임 원칙 위배
빅데이터 시대의 역기능 3가지 중 하나
[구성] 사생활 침해 / 책임 원칙 위배 / 데이터 오용
[의미] 빅데이터 분석 결과로 나타난 문제에 대해 "누구에게 책임을 물을지" 불분명한 상황
[구분] '빅브라더'처럼 국가나 기업이 개인을 감시·통제하는 것은 "사생활 침해"에 해당 (책임 원칙 위배 아님, 8회 기출 4번 오답 함정)
[구분] 알고리즘 편향성으로 인한 차별적 결과 = 책임 원칙 위배의 대표 사례 (누구 책임인지 불분명)
[치트키] "책임 원칙 위배 = '이게 누구 잘못이야?'를 못 정하는 문제, 빅브라더 감시는 사생활 침해"
[예문] AI 채용 시스템의 편향된 결과에 대해 기업, 개발자, 데이터 중 누구의 책임인지 불분명한 것이 책임 원칙 위배의 사례다

하향식 접근법 (Top-Down)
빅데이터 분석 과제 발굴 방법론 중 하나
[구성] 문제 탐색 → 문제 정의 → 해결방안 탐색 → 타당성 검토
[의미] 비즈니스 문제(목표)를 먼저 정의하고, 그에 필요한 데이터를 찾아 분석하는 방식. 문제가 명확할 때 사용
[구분] 상향식 접근법(Bottom-Up): 문제 정의 자체가 어려울 때, 데이터를 자유롭게 탐색하며 패턴을 발견하는 방식
[구분] 문제 탐색 단계에서 비즈니스 모델 캔버스를 5가지로 단순화: 업무/제품/고객/규제와감사/지원 인프라
[치트키] "하향식 = 위(목표)에서 아래(데이터)로 내려옴, 문제부터 정하고 시작"
[기출 포인트] "문제 탐색 단계에서는 단순하게 나열한다"는 지문은 틀림(8회 기출 4번) → 문제 정의를 명확히 구체화·세분화하는 것이 하향식의 핵심

빅데이터 분석 절차 (5단계)
분석 기획부터 시스템 구현까지의 전체 프로세스
[구성] 분석 기획 → 데이터 준비 → 데이터 분석 → 시스템 구현 → 평가 및 전개
[의미] 빅데이터 분석 프로젝트가 진행되는 표준적인 순서(PPADD로도 불림: Planning-Preparing-Analyzing-Developing-Deploying)
[구분] 기출 함정: "분석 기획 - 데이터 분석 - 데이터 준비 - 시스템 구현-평가 및 전개" 순서는 틀림 (데이터 준비가 데이터 분석보다 먼저)
[치트키] "기획해서 → 준비하고 → 분석하고 → 만들고(구현) → 평가한다" (기-준-분-구-평)
[기출 포인트] 정답 순서: 분석 기획 → 데이터 준비 → 데이터 분석 → 시스템 구현 → 평가 및 전개 (8회 기출 9번)

분석 대상/방법 매트릭스 (최적화·통찰·솔루션·발견)
분석 과제 유형을 대상(What)과 방법(How)의 인지 여부로 나눈 2x2 매트릭스
[구성]
· 대상 Known + 방법 Known = 최적화(Optimization)
· 대상 Unknown + 방법 Known = 통찰(Insight)
· 대상 Known + 방법 Unknown = 솔루션(Solution)
· 대상 Unknown + 방법 Unknown = 발견(Discovery)
[의미] 조직이 분석 대상과 분석 방법을 각각 알고 있는지 모르는지에 따라 접근 전략이 달라짐
[구분] "분석 방법은 알지만 분석 대상을 모르는" 경우 = 통찰(Insight) (8회 기출 7번, 4월 기출 13번 반복 출제)
[치트키] "둘 다 알면 최적화(익숙한 길), 방법만 알면 통찰(새로운 곳에 익숙한 도구), 대상만 알면 솔루션(익숙한 곳에 새 방법), 둘 다 모르면 발견(완전 새로움)"
[기출 포인트] 같은 매트릭스 개념이 두 시험(8회, 4월 복원)에서 반복 출제됨 → 반드시 암기

데이터 웨어하우스(Data Warehouse)
정형 데이터를 저장하는 통합 저장소, 4대 특징을 가짐
[구성] 주제 지향성(Subject-Oriented) + 통합성(Integrated) + 시계열성(Time-Variant) + 비휘발성(Non-Volatile)
[의미] 여러 시스템의 데이터를 주제별로 통합해서 저장하며, 시간 흐름에 따라 데이터가 누적되고 한번 저장되면 삭제되지 않는(비휘발성) 저장소
[구분] 기출 함정: "휘발성(Volatile)"이 데이터 웨어하우스 특징이라는 지문은 틀림 → 실제로는 "비휘발성"이 특징 (8회 기출 16번)
[구분] 4월 기출에서는 "확장성(Scalability)"이 4대 특징에 해당하지 않는다고 출제됨 → 정답 키워드는 매번 조금씩 다르니 4가지(주제지향/통합/시계열/비휘발성)를 정확히 암기
[치트키] "DW는 한번 들어오면 안 나가! (비휘발성) 시간순으로 쌓이고(시계열) 주제별로 정리(주제지향) 여러 곳에서 모아(통합)"
[예문] 데이터 웨어하우스는 매일 갱신되지만 과거 데이터를 삭제하지 않는 비휘발성 특징을 가진다

전이학습 (Transfer Learning)
사전 학습된 모델을 새로운 문제에 재사용하는 머신러닝 기법
[구성] 전이(轉移, 옮겨감) + 학습(學習)
[의미] 대규모 데이터로 미리 학습된 모델(Pre-trained Model)을 가져와 유사하지만 새로운 문제에 재사용하여 학습 효율과 성능을 높이는 기법. fine-tuning은 이 모델을 특정 타겟에 맞게 재조정하는 것
[구분] 강화학습: 보상(Reward)을 통한 시행착오 학습 / 준지도학습: 일부만 라벨링된 데이터 학습 / 앙상블 학습: 여러 모델 결합 → 전이학습과 다름
[치트키] "이미 배운 거(사전학습 모델)를 다른 문제에 옮겨(전이) 써먹는다"
[기출 포인트] 8회 기출 15번 정답. "기존에 학습된 모델을 재사용"이라는 문구가 나오면 전이학습

WBS (Work Breakdown Structure, 작업분할구조도)
분석 프로젝트의 업무 범위를 세부 작업 단위로 계층적으로 분해한 도구
[구성] Work(작업) + Breakdown(분해) + Structure(구조)
[의미] 전체 프로젝트 업무를 계층적(트리 구조)으로 세분화하여 관리하는 도구. 프로젝트 정의 및 계획 수립 단계에서 활용
[구분] 비즈니스 이해 및 범위 설정 단계 → 구조화된 작업 기술서(SOW) 작성
[구분] 프로젝트 정의 및 계획 수립 단계 → 프로젝트 계획서, 목적, 기대효과, WBS 작성
[치트키] "WBS = 일(Work)을 잘게 쪼개서(Breakdown) 나무 구조로(Structure) 관리"
[기출 포인트] 8회 기출 18번: WBS는 "분석 계획 수립 단계"에서 활용되는 도구

FGI (Focus Group Interview, 표적집단면접)
정성적 데이터 수집 방법 중 하나
[구성] Focus(초점) + Group(집단) + Interview(면접)
[의미] 특정 주제에 대해 전문가나 소수의 응답자를 한자리에 모아 토의를 통해 심층적인 의견을 수집하는 방법
[구분] 대규모 설문지 배포 = 정량적 조사(FGI 아님) / 실험집단·통제집단 비교 = 실험설계(FGI 아님) / 문헌 분석 = 문헌연구(FGI 아님)
[치트키] "FGI = 소수의 사람들을 모아(Group) 집중적으로(Focus) 인터뷰(Interview)"
[예문] 신제품 출시 전 소비자 반응을 알아보기 위해 8명의 참가자를 모아 FGI를 진행했다

WBS · SOW 위험관리 4대 전략 (회피/전이/완화/수용)
프로젝트 위험계획 수립 단계에서 사용하는 4가지 대응 전략
[구성] 회피(Avoid) / 전이(Transfer) / 완화(Mitigate) / 수용(Accept)
[의미]
· 회피: 위험 자체를 없앰 (기간 연장, 범위 축소)
· 전이: 위험을 제3자에게 넘김 (보험, 사후 보증)
· 완화: 위험의 영향을 줄임 (절감 노력)
· 수용: 위험을 받아들임 (긴급 대책 마련, 조치는 X, 백업플랜만 준비)
[구분] "수용"은 아무 조치도 하지 않는 게 아니라 백업플랜/긴급대책은 준비해두는 것 (완전 방치 아님)
[치트키] "회피(피하기)-전이(떠넘기기)-완화(줄이기)-수용(받아들이기)" 순서로 대응 강도가 약해짐
[예문] 프로젝트 기간이 부족할 경우 범위를 축소하는 것은 위험 회피 전략에 해당한다

데이터 품질 특성 (완전성/일관성/정확성/적시성)
데이터 품질을 판단하는 4가지 핵심 기준
[구성] 완전성(Completeness) / 일관성(Consistency) / 정확성(Accuracy) / 적시성(Timeliness)
[의미]
· 완전성: 결측치 없이 필요한 데이터가 모두 존재
· 일관성: 시스템 전반에서 내용·형식이 일치
· 정확성: 현실을 정확히 반영, 오류·왜곡 없음
· 적시성: 필요한 시점에 제공됨
[구분] 기출 함정: "완전성은 사용자의 주관적 판단에 따라 필요한 정보만 선택적으로 구성"은 틀림 → 완전성은 "결측 없이 모두 갖춰짐"을 의미, 주관적 선택과 무관 (4월 기출 10번)
[치트키] "완전(빠짐없이 다) - 일관(항상 똑같이) - 정확(사실 그대로) - 적시(제때)"
[예문] 결측치가 많은 데이터셋은 완전성이 낮다고 평가된다

빅데이터 플랫폼 계층 구조
빅데이터 플랫폼을 구성하는 계층별 분류
[구성] 인프라스트럭처 계층 < 데이터 처리 계층 < 데이터 분석 계층 (하위 → 상위)
[의미] 하드웨어 자원(서버, 네트워크)을 관리하는 인프라 계층이 가장 하위, 그 위에 처리/분석 계층이 쌓이는 구조
[구분] 노드(Node) 배치·관리, YARN 같은 자원관리 모듈 = 인프라스트럭처 계층 (4월 기출 8번)
[구분] "서비스" 관점에서는 분석 결과를 API 형태로 제공하는 것이 서비스에 해당 (인프라가 아님, 4월 기출 12번)
[치트키] "인프라(땅) 위에 플랫폼(건물) 위에 소프트웨어(입주민)"

FTP vs 웹 크롤링 vs Open API
웹 환경에서 데이터를 수집하는 대표적인 3가지 방법
[구성] FTP(File Transfer Protocol) / 크롤링(Crawling) / Open API
[의미]
· FTP: 컴�터 간 "파일"을 교환하는 프로토콜 (실시간 스트리밍이 아님!)
· 크롤링: 봇이 웹페이지 링크를 따라다니며 자동으로 정보 수집
· Open API: 서비스 제공자가 정한 규격대로 데이터를 요청·수신
[구분] 기출 함정: "FTP는 웹 로그 데이터를 실시간으로 스트리밍하여 수집한다" → 틀림! FTP는 파일 "전송" 프로토콜이지 실시간 스트리밍 도구가 아님 (4월 기출 9번)
[치트키] "FTP = 파일을 옮기는 택배, 크롤링 = 로봇이 링크 타고 돌아다님, API = 정해진 창구로 요청"
[예문] 대용량 로그 파일을 서버 간 이동시킬 때는 FTP를 활용한다

데이터 사이언티스트의 역량
데이터 사이언티스트에게 요구되는 핵심 역량 3가지 (AIB / 하드스킬·소프트스킬)
[구성] Analytics(이론적 지식) / IT(프로그래밍 지식) / Business(비즈니스 분석 능력) = AIB
[의미] 데이터 사이언티스트는 통계·수학 이론, 프로그래밍 기술, 비즈니스 이해력을 모두 갖춰야 함. 하드 스킬(이론·기술 숙련도)과 소프트 스킬(통찰력·협력·전달력)로도 구분
[구분] 기출 함정: "데이터 분석 조직의 예산 편성, 인력 채용·평가를 전담하는 관리 능력"은 데이터 사이언티스트의 핵심 역량이 아님 (이건 관리자의 역할, 4월 기출 17번)
[치트키] "AIB = Analytics + IT + Business, 세 박자가 맞아야 진짜 데이터 사이언티스트"
[예문] 분석 결과를 비전문가에게도 이해시키는 커뮤니케이션 능력은 데이터 사이언티스트의 소프트 스킬에 해당한다

강화학습 (Reinforcement Learning)
에이전트가 환경과 상호작용하며 보상을 최대화하는 방향으로 학습하는 머신러닝 기법
[구성] 에이전트(Agent) + 환경(Environment) + 보상(Reward) + 정책(Policy)
[의미] 정답 라벨 없이, 시행착오(Trial and Error)를 통해 최적의 행동을 스스로 학습. 순차적 의사결정 문제에 주로 적용. 대표 알고리즘: Q-러닝, SARSA
[구분] 기출 함정: "정답이 라벨링된 대규모 데이터셋을 통해 명시적인 규칙을 학습한다"는 지도학습의 설명 → 강화학습이 아님! (4월 기출 20번 정답)
[치트키] "강화학습 = 정답을 안 알려주고 잘하면 상(보상), 못하면 벌 주면서 스스로 터득하게 함"
[예문] 알파고는 바둑을 두며 승패라는 보상을 통해 학습하는 강화학습의 대표 사례다
